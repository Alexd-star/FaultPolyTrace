# GeoEast 主控插件说明

该目录用于实现 GeoEast 主界面中的一个入口按钮，目标是在 GeoEast Ribbon 或功能页中启动 `faultpolytrace_launcher.exe`。它不是算法本体，也不是 GeoEast 数据读写主程序；真正的数据闭环由 `bo_runner` 完成。

## 当前文件

- `FaultPolyTraceMainframePlugin.pro`：GeoEast 插件 qmake 工程。
- `attriModuleAction.cpp`：注册 `FaultPolyTrace` 动作。
- `manifest.xml`：声明 GeoEast 功能页和按钮。

## 当前状态

主控插件已经可以在本机 VS2019 + GeoEast 自带 Qt 5.15.2 环境下构建通过，并已输出到 GeoEast 插件目录：

```text
C:\Users\26312\GeoEast\GeoEast-RC\bin\plugins\GeoAttribute\FaultPolyTraceMainframePlugin\FaultPolyTraceMainframePlugin.dll
```

已解决的 GeoEast SDK 兼容点包括：

- `fw_mig.h` 旧 Qt 兼容分支问题：工程侧增加 `FW_QT4_SUPPORT`，让 GeoEast 兼容头走 Qt4/Qt5 分支，避开旧 Qt3 的 `qpointarray.h` 和 `QThread(unsigned int)` 写法。
- `WITH_TOOLTIP` 宏依赖的全局授权对象：在插件入口中显式提供 `g_pLicense`。
- `getoolkit.lib` 的隐含依赖：显式链接 `ngplicense.lib`、`licclient.lib`、`licbase.lib`、`surveyUI5.lib`、`dataset5.lib`。
- GeoEast 第三方库路径漂移：补齐 `libxml2`、Boost、`cpool.lib` 等 SDK 实际路径。

这与已经验证过的核心交付形成三层集成：

- 离线 CLI 可独立运行。
- Qt 启动器可调用算法和 GeoEast runner。
- GeoEast BO runner 已完成数据库读写，并能写入 `BOFaultPolygon`。
- GeoEast 主控插件可作为主界面入口启动 Qt 启动器。

## 构建命令

```powershell
.\scripts\build_geoeast_mainframe_plugin.ps1
```

## 验证要点

1. 构建完成后确认 DLL 和 `manifest.xml` 位于 GeoEast 插件目录。
2. 启动 GeoEast 后，在 Ribbon 中查找“断层多边形追踪”入口。
3. 点击入口后应启动 `faultpolytrace_launcher.exe`。
4. 如果入口不可见，优先检查 GeoEast 是否加载了 `GeoAttribute` 插件目录，以及当前 license 是否允许主框架加载相关模块。
