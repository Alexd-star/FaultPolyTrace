## 2. 连续运行稳定性

正式参数连续运行 50 次得到：

- 50 次结果 SHA256 完全一致。
- 最大总耗时 1672 ms。
- 峰值 Working Set 38,625,280 bytes。
- 首尾内存趋势 -0.006 MB。
- 句柄趋势 0。
- 失败注入检查通过。

该测试证明当前输入和参数下结果确定、进程资源趋势稳定。它不能替代长期服务运行、不同硬件和全部异常输入的内存分析。

本轮优化后另执行 10 次快速稳定性复核：最大总耗时 1405 ms，峰值 Working Set 38,371,328 bytes，内存趋势 -0.015 MB，句柄趋势 0，失败注入检查通过。该快速复核用于确认本轮流式解析和缓冲调整没有引入资源回归，不替代上述 50 次正式稳定性记录。

## 3. 内存控制

- 栅格、掩膜、分支和多边形使用标准容器和 RAII。
- 局部质量模块在栅格化前检查对象包围盒和最大单元预算。
- 拓扑诊断先做包围盒过滤，再做精确相交检查。
- CSV、JSON 和分支结果采用流式写出。
- GeoEast 对象转换为轻量 `Grid2D` 后再进入核心算法。

## 5. 优化边界

当前主要质量风险不是速度。后续优化应优先保证边界、误合并和对象粒度，不得为追求更低耗时删除拓扑检查或质量门禁。若处理更大网格，可继续评估拓扑空间索引、掩膜复用和可选诊断输出。
