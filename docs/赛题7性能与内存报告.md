## 4. 为什么比极早期版本更慢

极早期版本只做简单阈值分割和闭合边界输出，速度更快，但容易出现边界粗糙、漏检、交切解释不足等问题。当前主线增加了以下质量步骤：

- 分位数阈值，适配不同属性幅值。
- 弱响应延拓，改善断续断层。
- 骨架图分析，识别端点、交点和分支。
- 端点补连，提升断层连续性。
- 属性约束断层带，减少远离原始响应的过宽包络。
- 多外环边界追踪，避免一个连通区内只保留最大外环。
- 边界简化和平滑，提升展示质量。
- 拓扑诊断，检查开放环、自相交和异常交叉。

这些步骤会增加少量耗时，但换来更稳定的解释结果。当前核心耗时仍在 1 秒以内，性能不是主要瓶颈。

## 5. 内存风险控制

项目采取以下措施控制内存风险：

- 网格、掩膜、分支和多边形使用 `std::vector` 等标准容器管理。
- 核心算法不使用手工 `new[]/delete[]` 管理大数组。
- CSV、WKT、JSON 采用流式写出，避免构造超大中间字符串。
- 拓扑诊断先做包围盒过滤，再做精确线段相交判断。
- GeoEast runner 将数据库对象读取后转换为轻量 `Grid2D`，核心算法不直接持有 GeoEast 大对象。

正式提交前建议在 Visual Studio Debug 和 Release 下各运行一次官方数据，并保存控制台日志、诊断 JSON 和 GeoEast 叠合截图。

## 6. 后续性能优化方向

当前性能已经满足赛题，但如果要继续产品化，可优先做以下优化：

1. 拓扑诊断空间索引：将多边形边段按网格桶或 R-tree 分组，减少大规模输出时的两两比较。
2. 边界平滑增量化：只对长边界和展示层启用平滑，内部质控使用未平滑拓扑。
3. 掩膜复用：减少属性掩膜、残余掩膜、断层带掩膜之间的重复分配。
4. 输出开关：批量生产时可关闭图件和详细分支 CSV，只保留 GeoEast 结果和诊断 JSON。
5. 参数自动推荐：避免用户反复试参导致的整体工作流耗时。
