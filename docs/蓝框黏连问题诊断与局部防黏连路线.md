# 蓝框黏连问题诊断与局部防黏连路线

文档版本：V1.0  
日期：2026-05-22  
问题来源：用户在 `00_baseline_simplify2_02_结果叠加细查图.png` 中用蓝色框标注疑似黏连区域。

## 1. 结论

蓝框标注是有效问题，不应忽略。复核结果表明，部分蓝框区域确实命中了高风险疑似误合并多边形，尤其是多边形 `126`、`67`、`34` 等。这些对象通常具有以下特征：

- 面积偏大。
- 内部强响应段很多。
- 低属性背景比例高，约 65% 至 69%。
- 局部形态不是单纯细长断层带，而可能是几段近邻断层被同一个闭合包络圈住。

因此，该问题属于冲击满分阶段必须处理的质量风险：**近邻但不同脉络的断层不能被合成一个大圈**。

## 2. 根因分析

当前正式主线为了保证覆盖率和连续性，采用：

```text
骨架提取 -> 端点补连 -> 断层带缓冲 -> 属性包络约束 -> 闭运算 -> 闭合边界追踪
```

黏连主要来自以下叠加效应：

1. `belt-radius=3` 会把骨架线扩成断层带。
2. `post-belt-close-radius=1` 会修补局部小缝。
3. 默认主线使用合并断层带输出，能保持主干连续，但密集区可能过融合。
4. 一旦两个近邻断层在二值掩膜上连通，后续边界追踪只能生成同一个闭合多边形。
5. 部分桥接不是纯 0 属性，而是由低属性、闭运算和缓冲共同形成，因此旧版 `rootAntiMerge` 不一定能抓到。

### 3.5 WKT 后处理拆分实验

新增脚本：

```text
scripts\局部防黏连后处理实验.py
```

实验目录：

```text
examples\outputs\top_quality_experiments\local_antimerge_postprocess_20260522_1500
```

该实验尝试对多边形 `34` 和 `52` 在最终 WKT 层做后处理拆分：

```text
多边形 34 -> 2 个主体
多边形 52 -> 3 个主体
```

但结果失败：

```text
强响应覆盖率：94.9883%
弱响应覆盖率：91.2772%
强响应需复核连通域：32
```

失败原因：最终 WKT 多边形已经是闭合包络，内部切开后直接重追边界会把大范围内部区域当成外环，产生跨区大折线和覆盖率损失。因此，**局部防黏连不能在最终 WKT 层硬切，必须回到骨架/掩膜层处理**。

## 4. 正确技术路线

后续应在核心算法中增加“局部防黏连拆分”：

1. 在生成 `activeMask` 后、追踪多边形前执行。
2. 对每个连通断层带计算低属性比例、强响应段数量和形态指标。
3. 只对高风险连通体查找低属性桥接候选。
4. 切开候选桥后模拟连通体拆分。
5. 验证每个拆分主体必须满足：
   - 面积或像元数达到下限。
   - 主体内有足够强/弱响应支撑。
   - 主体形态仍为线状或断层带状。
   - 切掉的像元主要是低属性背景。
6. 通过验收才接受切分，否则自动回退。
7. 最后重新追踪闭合边界、面积过滤和拓扑诊断。

## 5. 产品策略

当前正式默认主线仍保持：

```text
rootAntiMerge = false
localAntiMerge = false
residualTrace = false
```

原因：

- 默认主线覆盖率、拓扑和性能最稳定。
- 全局 root-anti-merge 只能解决部分桥接，不能完整解决蓝框问题。
- 更强防黏连参数会增加过切风险。
- 最终 WKT 后处理拆分已经证明不可取。

下一步开发重点：

- 将 `局部防黏连候选诊断.py` 接入冲顶复核流程。
- 在 C++ 核心中实现掩膜层局部拆分，而不是 WKT 后处理。
- 先以高级开关启用，跑官方数据、蓝框区域和泛化数据回归。
- 只有在覆盖率、拓扑、多边形数量和蓝框视觉质量同时通过时，才考虑作为默认方案。

## 6. 2026-05-23 最新进展

已在 C++ 核心中新增默认关闭的 `localAntiMerge` 实验开关。它在 `activeMask` 掩膜层执行低属性窄桥切分，并输出以下诊断字段：

```text
localAntiMergeCandidateCutCells
localAntiMergeCutCells
localAntiMergeRejectedCutCells
localAntiMergeAcceptedComponents
localAntiMergeRejectedComponents
```

最新实验目录：

```text
examples\outputs\top_quality_experiments\local_antimerge_narrow_20260523_001702
examples\outputs\top_quality_experiments\root_vs_local_latest_20260523_002154
```

结论：

- 局部窄桥方案能稳定运行，拓扑为 0，强弱覆盖率不下降。
- 它能合理拆分多边形 34，但未能解决 52、67、126 等主要蓝框风险对象。
- 根系增强 `rootAntiMerge=true, supportRatio=0.25` 更接近蓝框根因，能拆分 67、126、40、33 等对象。
- 根系增强 + 局部窄桥会把多边形增至 213，且高风险候选没有下降，不建议默认叠加启用。

当前策略更新为：

```text
正式默认：rootAntiMerge=false, localAntiMerge=false
高级复核：rootAntiMerge=true, localAntiMerge=false
研发实验：localAntiMerge=true，仅用于对照和诊断
```

## 7. 2026-05-23 可行动低值桥复核

本轮进一步区分了两种容易混淆的对象：

- **疑似误合并对象**：诊断表中因为面积大、强响应段多、低值比例高而被标出，但它可能是合理的宽断层带或交切网络。
- **可行动低值桥对象**：切掉低属性桥后，两侧仍形成足够大的断层主体，且桥接像元数量达到下限。这类对象才是真正值得进入局部拆分的候选。

新增输出：

```text
局部防黏连候选摘要.json
```

最新复核目录：

```text
examples\outputs\quality_compare\compare_20260523_0315_actionable_bridge_score
```

结果显示：

| 方案 | 可行动低值桥候选 | 说明 |
|---|---:|---|
| 均衡主线 | 2 | 主要为多边形 34、52 一类局部分支/低值桥对象 |
| 根系防黏连 | 2 | 主要为多边形 34、54，说明根系切分解决的是另一类背景桥 |
| 局部窄桥防黏连 | 1 | 可行动候选减少，但高/中风险疑似黏连数量略升 |
| 根系加局部窄桥 | 1 | 可行动候选减少，但多边形数量继续上升 |

对局部图的判断是：剩余候选更像“主断层带旁附着小分支或小支线”的粒度表达问题，而不是明显跨大块空白的错误大圈。因此当前不能简单把所有候选都强拆。后续若继续推进局部桥方案，应增加更细的分支归属规则：小分支如果与主干在交切点处方向连续、属性连续，应允许作为同一断层带；若小分支与主干之间只靠低属性背景桥连接，才拆成独立多边形。

本轮产品判断：

```text
局部窄桥防黏连：进入高级候选，但不直接替代默认主线。
根系防黏连：仍是解释逻辑更稳的高级复核模式。
下一步：继续补真实工区/合成泛化回归，再决定是否把局部桥纳入默认预设。
```
