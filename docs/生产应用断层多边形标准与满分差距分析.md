# 生产应用断层多边形标准与满分差距分析

文档版本：V1.0  
日期：2026-05-22  
适用项目：FaultPolyTrace 赛题 7 冲击满分与产品级交付

## 1. 为什么要按生产标准重新看赛题

赛题要求“基于平面断层属性自动追踪断层多边形”，表面上是在一张属性图上生成闭合多边形；但在真实解释生产中，断层多边形不是孤立图形，而是后续构造解释和建模流程的控制对象。

实际生产里，断层多边形常用于：

- 表示断层在某一层位或平面上的交线影响范围。
- 约束层位自动追踪，让层位传播避开断层破碎区。
- 在构造图、等值图、平面图中表达断裂带和断块边界。
- 参与网格化、平滑、构造建模和储层建模。
- 支持圈闭边界、断层封堵、断块分割、井位部署和储量计算复核。
- 作为可编辑、可导入导出的解释成果保存。

外部资料也支持这个判断：

- DUG Insight 文档说明，断层多边形可以由断层与层位的交线生成，并在 Map View 中表达断层在层位上的表面形态；同一断层多边形对象可包含多个形状，且可以编辑、导入、导出和组合。[DUG Insight：Using Fault Polygons](https://help.dugeo.com/m/Insight/l/438752-using-fault-polygons)
- DUG 的层位追踪示例指出，断层多边形可用于约束 horizon propagation，避免层位追踪穿过断层影响区；多边形内部如果存在错误种子会导致传播结果变差。[DUG Insight：Using Fault Polygons in Horizon Picking](https://help.dugeo.com/m/learning/l/1010355-using-fault-polygons-in-horizon-picking)
- Petrosys 说明，使用 fault sticks 网格化时可自动计算断层多边形，结果可嵌入输出网格，也可保存到单独 fault polygon 文件，并可做空间平滑、编辑和回写。[Petrosys：Using Fault Sticks To Generate Mapping Polygons](https://www.petrosys.com.au/using-fault-sticks-to-generate-polygons/)
- SeisWare 的断层多边形功能包含输出图层名称、线宽、填充样式，以及“生成闭合多边形/生成边界折线”等选项，说明闭合性和图层表达是正式软件功能的一部分。[SeisWare：Fault Polygons/Contacts](https://help.seisware.com/pages/Content/FaultPolygons/FaultPolygons.html)
- Petrosys 对自动追踪解释的断层制图问题指出，断层附近需要合理清理和缓冲，过窄原始多边形可能不能满足后续动态模拟或变形区表达要求，因此需要可控宽度和迭代复核。[Petrosys：Mapping with Faults using Autotracked Interpretation](https://www.petrosys.com.au/mapping-with-faults-using-autotracked-interpretation/)
- 储层研究文献强调，断层相关分隔会影响井位、生产优化、剩余油风险和储层建模，因此断层解释成果的可靠性会传递到后续地质和工程决策。[Springer：Evaluation of reservoir compartmentalization](https://link.springer.com/article/10.1007/s13202-016-0285-z)

结论：赛题满分不能只靠“画出红线”。必须证明结果能作为正式解释对象进入 GeoEast，并能稳定支撑后续地图、层位、建模和复核工作。

## 2. 生产应用对断层多边形的质量要求

### 2.1 几何要求

正式断层多边形至少应满足：

- 每个结果必须闭合。
- 边界不能自相交。
- 不应出现异常多边形相交、交叉和拓扑混乱。
- 边界应沿断层属性响应自然贴合，不应系统性偏移。
- 线条应平滑，但不能为了平滑而明显脱离原始断层带。
- 宽度应能覆盖断层影响带，而不是只画一条中心线。
- 支持多个外环，因为一个工区内可能存在多个独立断层多边形。
- 面积、周长、像元数等统计量应可追溯。

### 2.2 地质解释要求

从解释角度看，结果应满足：

- 主断层和高属性响应必须优先覆盖。
- 弱但连续的线性响应应尽量召回，至少进入复核层。
- 近邻但没有属性支撑的不同断层不能被硬连成一个大圈。
- 真正交切、搭接或连续延伸的断层应允许形成合理网络。
- 断续断层可以补连，但补连必须受距离、方向和属性支撑约束。
- 小碎片和噪声不能大量进入正式结果。
- 面积阈值不能只是删除小结果，还应允许保留“面积小但细长且高属性”的有效小断层。

### 2.3 工程和产品要求

正式产品还需要：

- 支持外部文件和 GeoEast 数据库两条路径。
- 支持输入对象选择、输出命名、参数设置和结果颜色。
- 输出可在 GeoEast 平面成图中叠合查看。
- 提供自动验收报告、质量图、漏检复核图和误合并复核图。
- 参数、运行耗时、诊断结果和输出文件必须可回溯。
- 换数据后不能靠反复人工试参，应有自动参数推荐或至少三档通用预设。
- 算法核心耗时稳定小于赛题 1 分钟要求。
- 内存和文件写出稳定，不能出现溢出或泄漏。

## 4. 当前结果是否已经完美

当前正式主线已达到“比赛强交付基线”，但从冲击满分角度，还不能说绝对完美。最新自动验收结果：

```text

保留多边形：204
强响应覆盖率：99.6217%
弱响应覆盖率：96.9351%
强响应需复核连通域：3
弱线性需复核连通域：11
高风险疑似误合并候选：13
中风险疑似误合并候选：31
开放环/自相交/多边形相交：0/0/0
核心追踪耗时：421 ms
```

客观判断：

- 硬性赛题要求已经满足。
- 覆盖率和性能达到优秀水平。
- 拓扑质量达到正式提交要求。
- 仍有局部强弱响应漏检复核项，但强响应复核集中在端点、边界和交切附近，不是主干断层大范围漏追踪。
- 仍有疑似误合并候选，需要图件逐项确认。
- 防黏连增强模式已经能在不损失强弱响应覆盖率的情况下拆分 4 个基线多边形，但目前仍作为高级对照模式，不直接替代默认主线。

2026-05-22 的几何后处理复核发现：普通 Chaikin 平滑会使闭合环轻微向内收缩，导致少量已经识别到的端点高值像元在栅格覆盖统计中落到边界外。当前版本已改为“面积保持型平滑”：在保留平滑外观的同时，将平滑后面积轻微补偿到原始闭合带面积附近，并设置最大补偿比例，避免无约束外扩。该修复不是针对官方数据调参，而是修正平滑算法的系统性收缩。

因此，当前不是“有明显硬伤”的状态，而是“已可提交，但冲顶还要把少量局部不确定性解释清楚或继续自动化处理”的状态。

它会生成：

- `冲顶局部复核报告.md`。
- `复核清单.json`。

该工具解决的问题是：以后不再只靠整图肉眼判断，而是把每个可能扣分的局部点裁出来，逐项确认“应补追踪、应过滤、还是应防黏连拆分”。

### 5.2 自动参数推荐

新增脚本：

```powershell
python .\scripts\自动参数推荐.py `
  --dat "D:\BaiduNetdiskDownload\BGPCup2025\test.dat"
```

它会读取输入网格，分析：

- 网格大小和采样间隔。
- 全网格属性分位数。
- 非零属性比例。
- 高值连通域数量。
- 弱线性连通域尺度。
- 噪声和断层带宽度倾向。

并输出三档参数：

- `均衡推荐`：正式首跑。
- `稳健防误合并`：近邻断层容易黏连时使用。
- `高召回复核`：弱细线漏检较多时生成复核层。


这说明推荐逻辑已经使用与核心 C++ 一致的全网格分位数口径，而不是针对官方数据写死。

## 6. 冲顶质量门禁

后续任何优化进入正式主线前，必须同时满足：

| 门禁 | 目标 |
|---|---:|
| 强响应覆盖率 | >= 99.0%，推荐保持 >= 99.5% |
| 弱响应覆盖率 | >= 95.5%，推荐保持 >= 96.5% |
| 开放环 | 0 |
| 自相交 | 0 |
| 多边形异常相交 | 0 |
| 多边形数量 | 保持 200 个量级，不能暴涨到几千 |
| 核心耗时 | < 60000 ms，推荐 < 1000 ms |
| 强响应漏检复核 | 每个复核项都要有图件和说明 |
| 疑似误合并候选 | 高风险对象必须有局部图和处理策略 |
| GeoEast 展示 | 原始属性和结果多边形能在同一底图叠合 |

## 6.1 本轮面积保持型平滑结论

本轮对照了四组几何后处理方案：

| 方案 | 多边形 | 强响应覆盖率 | 弱响应覆盖率 | 拓扑 |
|---|---:|---:|---:|---|
| 旧主线：简化 2 + 平滑 1 | 204 | 99.5236% | 96.6313% | 0/0/0 |
| 关闭平滑 | 204 | 99.5563% | 96.7235% | 出现自相交和多边形相交 |
| 关闭简化、保留平滑 | 204 | 99.5236% | 96.6313% | 0/0/0 |
| 面积保持型平滑 | 204 | 99.6217% | 96.9351% | 0/0/0 |

结论：

- 强弱响应覆盖率提升来自边界几何保真，不来自降低阈值或启用高召回碎片层。
- 多边形数量仍为 204，没有碎片化。
- 拓扑仍保持开放环、自相交、多边形异常相交均为 0。
- 强响应剩余复核项仍为 3 个，主要位于数据边界、端点和交切附近，需要作为局部复核对象保留。

## 7. 下一步精准优化路线

### 7.1 先做局部复核，不做全局乱调

当前强响应漏检只有 3 个，弱线性复核 11 个。下一步应先看 `冲顶局部复核图`，判断它们是不是有效断层。若是有效断层，再做局部补追踪；若是孤立端点、边界噪声或非断层属性，则在文档中解释为什么过滤。

### 7.2 局部防黏连拆分进入候选，不直接替换主线

防黏连增强已证明：

```text
稳定基线：204 个多边形
防黏连增强候选：209 个多边形
防黏连支撑比例：0.25
强响应覆盖率：不下降
弱响应覆盖率：不下降
切掉强/弱响应像元：0/0
```

下一步应把 13 个高风险误合并候选逐图复核。只有确认跨越低属性背景、两侧走向不同、切开后仍有主体规模时，才把局部切分策略纳入默认主线。

### 7.3 残余弱响应作为复核层，而不是直接并入正式层

高召回实验曾经能覆盖更多弱线，但会带来几千个小碎片。正确产品策略不是回到碎片化结果，而是输出“残余复核层”，由用户或自动规则决定哪些进入正式结果。

### 7.4 建立更多泛化回归

当前已有 6 组合成泛化场景全部通过。后续要继续补：

- 密集小断层。
- 近邻曲线断层。
- 分叉断层。
- 多方向交切断层。
- 低信噪比弱断层。
- 宽窄断层带混合。

每组都要保存输入、输出、参数、诊断 JSON、局部复核图和报告。

## 8. 当前结论

FaultPolyTrace 当前已经满足赛题主要需求和评分标准，并具备国家级奖项竞争力。与“顶尖满分”之间的差距不在读写、闭合、界面、性能这些硬功能，而在更高层的质量证据链：

- 是否能解释每个少量漏检区域。
- 是否能证明误合并候选不是实际错误，或已被局部防黏连修复。
- 是否能让参数自动推荐适应新数据。
- 是否有足够清晰的 GeoEast 截图、演示视频和正式产品手册。

后续开发应围绕“局部复核、自动推荐、受控增强、可回溯验收”继续推进，而不是为了追求单张图更满而牺牲拓扑、解释粒度和泛化能力。
