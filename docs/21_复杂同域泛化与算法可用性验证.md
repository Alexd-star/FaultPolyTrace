# 复杂同域泛化与算法可用性验证

> 历史验证记录：本文的214基线用于复现当轮复杂同域实验，不是当前发布默认。当前200正式结果及候选晋级结论见`官方数据最新验收报告.md`和第22章。

## 1. 验证目的

本轮工作用于补足原有八类小型合成案例复杂度不足的问题。正式赛题结果仍以官方 `test.dat` 的214个保留多边形为稳定基线，新生成的数据仅用于检验算法能否在独立几何、复杂网络、近邻平行、独立交叉、分支、弱缺口和非均匀背景条件下保持覆盖、对象粒度、拓扑与性能。任何候选算法只有在官方结果不退化、复杂同域指标不退化并至少产生一项明确改善时，才具备进入正式默认线的条件。

## 2. 可获取公开资料及适用边界

本轮复核了项目登记的公开资料和相关论文数据来源。Thebe 数据集提供真实地震体及专家断层标签，可从同一采样位置生成平面不连续性属性，但输入属性需要自行计算，专家体素标签与赛题要求的带状断层多边形并不完全等价。F3 Netherlands 和 Penobscot 提供真实三维地震资料，但缺少可直接对应的平面断层多边形标准答案。CRACKS 提供真实纵向剖面和解释标注，不属于平面断层属性输入。FaultSeg3D 提供物理启发的合成地震和断层标签，可用于方法压力测试，但不能代替真实工区泛化结论。

主要来源如下：

| 资料 | 来源 | 本项目中的合理用途 | 不能据此宣称的内容 |
|---|---|---|---|
| Thebe专家解释地震数据 | https://doi.org/10.7910/DVN/YBYGBK | 真实地震属性生成链和专家切片辅助评价 | 不能等同于官方平面属性格式的直接精度 |
| F3 Netherlands | https://wiki.seg.org/wiki/F3_Netherlands | 独立工区属性生成和人工复核 | 无独立标注时不能报告Precision、Recall或IoU |
| Penobscot 3D | https://callforbids.cnsopb.ns.ca/2015/01/data-environment/digital-data.html | 独立工区运行和稳定性检查 | 无专家解释时不能证明地质正确性 |
| CRACKS | https://doi.org/10.5281/zenodo.13926822 | 纵向剖面跨域压力测试 | 不能作为赛题平面多边形成绩 |
| FaultSeg3D | https://github.com/xinwucwp/faultSeg | 物理启发合成资料和算法研究参考 | 不能单独证明真实资料泛化能力 |

截至本轮结束，没有找到可公开直接下载、同时满足“二维平面断层属性、独立真实工区、专家多边形真值、与赛题输出语义一致”四项条件的数据。因此采用公开真实资料辅助验证与同域可控复杂真值相结合的方式，不把不同输入域的指标混为一个泛化分数。

## 3. 官方统计量校准

官方 `test.dat` 网格为1501×701。输入属性约95.68%的像元为零，正响应约占4.32%，全图均值约0.0362；全图96.5%和98%分位值分别约为0.66和0.95。复杂同域生成器只使用这些整体统计量校准属性稀疏度和强弱分布，不读取官方坐标、对象编号、局部图形或输出多边形。

最终复杂基准同样采用1501×701网格。每例先生成26个独立真值对象，再渲染断层属性；包括12条非平稳曲线、3组近邻平行、3组独立交叉、2组分支结构和4处受控弱缺口。属性以零背景为主，叠加少量相关噪声。几何先于属性生成，真值不会由算法输出反推得到。

早期过饱和实验曾在每例放置102条长断层，真值面积占网格约64%，明显偏离官方数据分布。该轮结果只作为极端压力记录，不纳入正式泛化评价。校准后的真值带平均占据率约13%，正属性响应约4%，与赛题数据量级接近。

## 4. 质量指标

复杂基准同时评价以下内容：

1. 像元层：IoU、Precision、Recall和背景泄漏。
2. 边界层：Boundary Precision、Boundary Recall、Boundary F1、ASSD和HD95。
3. 中心线层：中心线覆盖率、走廊Precision和走廊F1。
4. 对象层：统计长路径真值与结果多边形之间的显著重叠关系，包括一对多、多对一、未关联和最大关联数，用于同一规则下的候选A/B压力比较。
5. 拓扑层：开放环、自相交、内环冲突、无效几何和结果间异常相交。
6. 工程层：核心执行时间、完整执行时间、确定性和候选模式相对开销。

对象严重度指标是本轮新增内容。旧口径中，一个结果即使与多个长路径真值发生显著重叠也只记为一次事件，容易低估网络耦合程度；新口径同时累计额外关联数量和最大关联数。需要注意，生成器中的真值对象表示完整长路径，而算法结果通常表示交点之间的多边形片段，两者对象粒度并不完全一致。因此这些数量是对象重叠压力代理，不是专家确认的地质误合并或过分割数量，也不适合脱离本基准单独解释。

## 5. 正式基线结果

八个复杂案例共包含208个真值对象。全部案例使用同一套正式参数，没有逐例调参。汇总结果如下：

| 指标 | 结果 |
|---|---:|
| IoU | 0.665353 |
| Precision | 0.935923 |
| Recall | 0.698300 |
| Boundary F1 | 0.925000 |
| 中心线走廊F1 | 0.942642 |
| 漏对象 | 0 |
| 无效多边形 | 0 |
| 异常相交 | 0 |
| 多对一重叠代理事件 | 9 |
| 多对一额外关联数 | 200 |
| 单个结果最大关联真值数 | 26 |
| 一对多重叠代理事件 | 35 |
| 一对多额外关联数 | 43 |
| 最大完整处理时间 | 约2秒 |

结果表明，正式算法在复杂稀疏属性图上仍保持较高Precision、较好边界贴合、完整中心线覆盖和合法拓扑，也没有出现完全未关联的长路径真值。对象重叠代理显示，密集交切网络中的结果片段与多条长路径真值存在较强耦合，提示分支归属仍值得继续研究；但由于真值长路径与输出片段粒度不同，不能据此断言存在同等数量的实际地质误合并。正式晋级判断仍以同一口径下候选相对基线是否改善为准。

## 6. 候选模块A/B结果

### 6.1 全局分支归属

分支归属候选在八例中执行了多尺度交点分析和候选根组构建，但最终几何与正式基线逐文件哈希完全相同。像元、边界和对象指标均未变化，因此不满足“至少一项明确改善”的晋级条件。当前模块能输出分支差异诊断，但尚未把方向配对结果转化为交切处的有效矢量分离。

### 6.2 受限弱路径

受限弱路径使IoU提高约0.0051，Precision提高约0.0105，Boundary F1提高约0.0023，但Recall轻微下降；误合并事件由9增至10，额外吞并对象由200增至202，过分割事件由35增至37。该模式改善了局部边界纯度，却损害了对象粒度，因此保持实验状态。

### 6.3 质量影子模式

质量影子模式与基线输出哈希完全相同，符合“不改变正式结果”的设计。复杂案例中每例检出约171至403个复核候选，完整耗时约4.4至11.4秒，明显高于约2秒的正式追踪。该模式适合按需质检，不应默认随每次正式追踪同步运行。后续优化应优先减少重复栅格化和候选窗口重复计算。

## 7. 拓扑检查补强

复杂基准最初发现三个结果按项目原拓扑口径为零问题，但按OGC/Shapely规则属于内部区域不连通。原因是大型多边形中多个内环在两个以上不同点接触。项目随后补充了环边界冲突检查和输出端清理：允许OGC有效的单点接触，拒绝线段重叠、真正穿越和多个不同接触点；冲突内环不会写入正式多边形。

修正后，复杂八例的无效多边形由3降为0。官方 `test.dat` 仍保持214个保留多边形、拓扑0/0/0，CSV SHA256仍为 `A2A9644692B1E6635B152823CAE192C9C6EF19320AB5EF4273D5B2DB90638ECF`，说明补强没有改变稳定交付基线。

## 8. 当前能力边界与后续方向

当前算法已经具备较强的平面属性覆盖、边界生成、闭合拓扑、运行速度和工程可用性。下一项真正值得投入的算法工作不是继续降低阈值或全图平滑，而是让分支方向归属能够影响最终断层对象构建。合理路线为：在交点附近建立多尺度方向轨迹，以路径属性连续性、转向代价、根系冲突和背景隔离构成全局代价；使用受约束图匹配确定分支配对；在栅格断层带重建前保留对象身份，使交叉位置共享局部响应但不无条件合并为同一对象。

这一增强必须先在独立交叉小型真值、复杂同域网络和官方数据三个层级运行。晋级要求为：复杂同域额外吞并对象显著下降，官方覆盖、边界、拓扑和结果哈希门控不退化，处理时间仍远低于一分钟。没有满足这些条件前，正式默认线继续保持当前200多边形稳定基线。

## 9. 复现入口

复杂基准生成与评价入口为 `scripts/运行复杂同域验证.py`。当前产品默认口径的12套验证结果位于 `outputs/evidence/adaptive_boundary_cross_domain_20260805/complex12`。脚本支持复用已有追踪结果，只重新计算评价指标，以便修改指标后快速复核：

```powershell
python scripts/运行复杂同域验证.py run `
  --dataset data/generated/planar_benchmark_official_complexity_modular12_20260803 `
  --exe build/faultpolytrace.exe `
  --output outputs/evidence/adaptive_boundary_cross_domain_20260805/complex12 `
  --modes adaptive_boundary `
  --baseline-profile current_product `
  --reuse-existing
```
