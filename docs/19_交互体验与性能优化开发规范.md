# FaultPolyTrace 交互体验与性能优化开发规范

## 1. 文档目的

本文档用于指导 FaultPolyTrace 独立软件与 GeoEast 集成控件的交互、配置、图层显示、异步任务、性能和发布质量改进。优化对象不是核心断层追踪算法，而是用户从启动软件到选择数据、查看图层、执行追踪、检查结果和调用 GeoEast 工具的完整操作链路。

本轮改进遵循三个原则。第一，窗口必须先可用，再执行数据库发现和大文件加载，不能让自动化行为阻塞首屏。第二，用户点击任何可见控件都必须获得结果、进度或明确的失败原因，不能静默返回。第三，独立软件与 GeoEast 控件共享相同的参数、视图和反馈语义，只保留数据来源与宿主能力带来的必要差异。

## 2. 已确认问题及根因

### 2.1 首次进入 GeoEast 控件未自动刷新目录

控件构造过程当前只执行界面创建、配置读取和状态更新，没有在窗口显示后发起网格及结果目录发现。数据库列表本身通过外部执行程序异步读取，因此可以在首屏显示后启动，不需要把刷新放入阻塞式初始化过程。

### 2.2 空下拉框没有配置引导

输入网格下拉框当前把“编辑框中存在文字”当作“已经取得可用目录”。旧配置保存的网格名即使不属于当前工区，也会使引导逻辑提前结束，最终打开一个没有列表项的下拉框。目录状态必须由本次数据库查询结果决定，不能由编辑框文字推断。

### 2.3 重新安装后出现旧路径、旧网格和旧 DAT

独立软件与控件分别把配置写入用户级应用配置目录。安装器更新程序文件时不会删除用户配置，这是桌面软件正常的持久化行为。当前不足在于配置恢复缺少有效性检查：已不存在的执行程序、旧版本示例文件和未经当前工区确认的网格名仍会被恢复到主界面。

### 2.4 刷新、配置和加载操作可能静默失效

多个操作在外部进程忙碌时直接返回，没有状态提示，也没有排队执行。配置窗口还允许在必需项无效时强制保存，随后刷新失败会让用户误以为按钮没有功能。

### 2.5 插件侧栏留白偏大

插件表单标签列固定最小宽度为 110 px，左侧栏固定最小宽度为 440 px。中文短标签不需要这么宽，因而形成明显空白。标签列应按当前语言和字体测量，侧栏应与独立软件采用同一初始宽度和拖动约束。

### 2.6 工区底图入口只能启动外部程序

当前实现直接启动 `GeoBasemap.exe`，没有传递当前项目、输入网格和结果对象，也没有验证进程是否在启动后立即退出。因此“启动请求成功”不等于“工区底图已打开并显示当前数据”。应先完善进程反馈，再优先通过 GeoEast 宿主通信能力传递当前对象。

### 2.7 图层复选框不易识别

原始网格和结果多边形属于独立的二元可见性状态，适合使用完整行可点击的图层开关。当前两个小复选框与“叠加查看”按钮同时存在，表达重复，而且首次用户不容易发现小型勾选区域。

### 2.8 视图默认不是平移模式

两套视图初始平移状态均为关闭，重置视图后也会退出平移。地图类结果查看器应默认支持左键拖动，工具栏只负责显示当前模式及在扩展交互工具出现后切换模式。

### 2.9 图层解析和绘制缺少阶段反馈

数据库导出过程已有外部进程状态，但网格文本解析、多边形读取和显示缓存构建仍可能占用界面线程。大文件场景中应将数据解析与界面绘制分离，并对“导出、读取、解析、构建、显示”分别反馈。

### 2.10 高级参数、极端值与停止失效

高级参数分组原先借用可勾选 `QGroupBox` 实现折叠。该控件的视觉形态与算法复选框相同，用户容易把“展开参数区”理解为“启用整组算法”。真正影响追踪结果的是属性约束、根系防黏连、局部桥分裂和弱响应补追等独立选项，分组标题不应具有启用语义。

分位数和最小面积原先允许输入 0。分位数 0 不是“无阈值”，因为分位数模式必须在 0 与 1 之间选择统计位置；极低分位数会把大部分网格作为活动区域，使骨架化、分支构图和连接检查的规模急剧增加。最小面积 0 则会关闭面积过滤，保留所有微小对象，增加矢量化、输出、拓扑检查和显示负载。两类设置都需要在界面入口阻止或明确分级告警，核心程序还必须独立校验非法值。

停止按钮原先只调用 `QProcess::terminate()`。在 Windows 控制台子进程不响应温和终止请求时，界面仍会等待；同时，进程结束回调可能继续执行刷新目录、导出结果和载入图层，使用户看到多个连续任务。停止必须被建模为取消状态：立即禁用重复点击、清空待执行标志、强制结束子进程，并让结束回调跳过全部后续任务。

## 3. 配置与首次运行设计

### 3.1 配置分类

配置分为三类，不能使用同一恢复规则。

| 配置类型 | 典型内容 | 恢复规则 |
|---|---|---|
| 用户偏好 | 语言、算法参数、颜色、线宽、面板宽度 | 跨会话保存，版本升级时迁移 |
| 环境配置 | GeoEast 根目录、数据根目录、数据库、项目、用户、执行程序 | 保存后每次启动重新验证，无效时自动检测或要求修正 |
| 临时会话 | 当前网格、当前结果、DAT 文件、图层可见性、运行状态 | 只有资源仍存在且属于当前环境时恢复，否则清空 |

密码不得写入配置文件。独立软件和 GeoEast 控件继续使用不同 INI 文件，避免两个入口相互覆盖，但共享配置迁移和有效性检查规则。

### 3.2 配置版本迁移

配置结构升级后提高 `configSchemaVersion`。迁移过程应完成以下处理：

1. 旧执行程序路径不存在时，重新从安装目录和 GeoEast 根目录检测。
2. GeoEast 根目录或数据根目录不存在时，清除旧值并重新检测。
3. 外部输入和 DAT 路径不存在时清空，不用示例数据替代。
4. 保存的网格和结果只作为“期望恢复项”，目录刷新确认存在后才能设为当前项。
5. 图层默认关闭，加载成功后按用户本次操作决定是否显示。
6. 全新用户默认简体中文；用户主动切换语言后保留选择。
7. 自动化验证使用隔离配置目录，不读写真实用户配置。

### 3.3 首次显示流程

窗口创建完成后立即显示首屏。首屏出现后的第一个事件循环执行环境检查：

1. 自动检测 GeoEast 根目录、执行程序和当前用户。
2. 若数据库配置完整，异步刷新网格，再刷新结果。
3. 若配置不完整，在数据区域显示非模态引导，不在启动阶段强制弹窗。
4. 若存在目录缓存，先显示缓存并标注“正在更新”，后台刷新后替换。
5. 自动刷新不清空用户日志，也不阻止用户调整参数和窗口大小。

## 4. 目录下拉框交互规范

网格和结果下拉框必须具有明确状态：未配置、正在刷新、可用、空目录、失败。列表中的提示项不作为数据对象，必须具有空数据标识并禁用相关显示和删除按钮。

点击下拉按钮时采用以下行为：

| 状态 | 操作结果 |
|---|---|
| 未配置 | 显示数据库配置说明并提供“自动检测”“配置数据库”入口 |
| 配置完整但未读取 | 自动启动刷新，列表显示“正在读取...” |
| 正在刷新 | 保持列表可见并显示进度，不重复启动任务 |
| 已读取且有对象 | 正常显示对象列表 |
| 已读取但为空 | 显示“当前项目暂无网格/结果”与刷新入口 |
| 刷新失败 | 显示错误摘要、查看日志和重试入口 |

编辑框中的旧文字不得作为目录有效性的判断条件。选择对象后，如果对应图层已经开启，则立即加载；如果图层关闭，则更新状态提示但不偷偷改变用户已经明确关闭的图层。

## 5. 图层与结果视图设计

### 5.1 图层开关

独立软件与插件统一使用两个 `LayerToggle`：原始网格、结果多边形。控件继承标准可点击按钮语义，整行可点击、支持空格键切换、具有清晰焦点边框，并使用 150 ms 左右的短动画表达开关变化。颜色只是辅助，文字、位置和开关状态共同表达可见性。

当两个开关同时打开时自然形成叠加结果，不再保留重复的“叠加查看”按钮。资源不存在时开关仍可点击，但应触发相应选择或配置引导；正在加载时显示小型活动指示，失败时恢复到关闭状态并显示原因。

### 5.2 默认交互

结果视图默认处于平移模式：左键拖动平移、滚轮围绕指针缩放、重置后保持平移。工具栏平移按钮默认高亮。视图无数据时保持普通箭头，数据可交互时使用张手和抓取光标。

### 5.3 加载状态

加载状态优先显示在视图区，不使用会遮挡整个应用的启动页。小于 150 ms 的操作不显示动画；超过 150 ms 显示当前阶段；超过 2 s 增加取消或查看日志入口。操作完成后提示自然消失，失败时保留可操作的错误说明。

## 6. 布局统一规范

中文界面标签列以 88 至 96 px 为宜，英文界面根据可见标签的字体宽度动态计算，并设置上限。左侧栏建议初始 420 px、最小 400 px、最大 600 px；分割线允许用户调整并保存合理宽度。输入框使用剩余空间，不使用不必要的固定长度。

独立软件与插件必须统一以下内容：菜单术语、工具栏顺序、参数分组、图层开关、颜色线宽透明度、默认平移、空状态、加载状态、失败提示、恢复默认范围、语言行为和窗口伸缩规则。

允许保留的差异包括：独立软件的外部文件、输出目录和历史记录；插件的 BOMapGrid、BOFaultPolygon、删除对象、工区底图和平面成图入口。

## 7. GeoEast 工区底图与平面成图

### 7.1 近期可靠性改进

启动 GeoBasemap 或 GeoMapping 前检查程序、工作目录和 GeoEast 环境。启动后记录进程号并在短时间内检查是否立即退出。启动失败、许可不可用和程序快速退出必须给出不同提示。数据库刷新不应禁用工区底图入口，因为两项操作不存在数据写冲突。

### 7.2 宿主集成方案

GeoEast SDK 已包含网格和断层多边形显示通信类型。正式实现应由主框架插件或轻量桥接模块把当前项目、BOMapGrid 名和 BOFaultPolygon 名发送给 GeoBasemap/GeoMapping。若当前宿主版本不支持该通信，则回退到受管理的外部启动和明确的图层树操作提示。

所有按钮必须满足以下条件之一：操作成功；显示正在处理；给出可执行的失败原因；在环境不支持时禁用并说明原因。不得出现点击后无反馈的入口。

## 8. 异步任务与性能方案

### 8.1 统一任务状态

建立操作状态枚举，至少覆盖空闲、刷新网格、刷新结果、导出网格、导出结果、解析网格、解析多边形、追踪、写入、删除和启动 GeoEast 工具。任务冲突时应排队或说明当前任务，不允许直接返回。

### 8.2 数据加载

外部进程继续使用 `QProcess`。网格和多边形解析放入后台线程，解析结果使用不可变数据对象传回界面线程；只有控件更新和绘制在主线程执行。大网格先生成适合当前视口的显示图像，导出和数值查询仍使用完整数据。

### 8.3 缓存

目录缓存以数据库、项目和用户组成环境签名；图层缓存以环境签名、对象名、修改时间或内容标识组成键。环境或对象变化时自动失效。缓存只用于加速显示，不得改变算法输入和写库结果。

### 8.4 优化顺序

1. 合并网格和结果目录查询，减少执行程序冷启动次数。
2. 使用结构化 JSON 返回目录，停止从日志文本推断对象名称。
3. 缓存解析后的网格图像和多边形路径。
4. 平移缩放只改变视图变换，不重复解析数据或重建全部路径。
   多边形显示应建立覆盖常用倍率和最高倍率的多分辨率缓存，按当前缩放选择相邻层，避免低倍率反复缩放超大位图。缓存层必须按需在后台生成：首次只准备当前倍率，跨越倍率档位后再补目标层，已有层在目标层准备期间继续显示，禁止在第一次开启图层时预生成全部倍率。原始网格应继续使用单独的数值图像缓存，不得在每层多边形缓存中重复栅格化。点击、松开、缩放和连续拖动期间不得重复描画全部矢量路径，也不得在鼠标移动事件中按距离周期性重建。缓存必须设置单层尺寸和像素上限，只提交画布内实际可见区域，并在结果图层、样式、数据或视口尺寸变化后失效；原始矢量路径继续作为几何事实源，不得用缓存反推或修改结果。坐标读数等辅助反馈应按显示刷新率节流，不应随高频鼠标事件重复触发布局与文本绘制。
5. 配置写入采用短延迟防抖，关闭窗口时强制同步。
6. 算法性能保持既有基准，不以牺牲结果质量换取界面速度。
7. 启动过渡窗在主窗口就绪后必须销毁而不只是隐藏；不确定进度条、属性动画和等待指示器仅在对应任务运行期间存活或可见，空闲状态不得保留持续动画。

### 8.5 参数安全与取消规范

参数校验采用三层防护。第一层是控件范围，排除分位数 0、最小面积 0、带宽半径 0 和最短分支 0。第二层是共享参数模型，独立软件与插件使用同一套错误和风险判断；根系防黏连、局部桥分裂和弱响应补追三项同时启用属于非法组合并阻止启动，单项按需功能及其它高负载参数则在运行前说明影响并要求确认。第三层是 C++ 核心防御校验，即使通过命令行或数据库执行程序绕过界面，也不能使用非有限数值、非法分位数、复杂大网格的零面积过滤或三项算法叠加进入失控计算。旧配置超出当前安全范围时应自动夹取到合法值、写回配置版本并在日志中说明，不得静默沿用。

高级参数区统一改为箭头折叠。折叠只控制可见性，不更改参数值、不触发预设变化、不启动追踪。按需算法选项保留独立复选框，并在提示中说明目标、可能增加或减少对象的原因及适用条件。

取消流程应满足以下时序：

1. 用户点击停止后立即写入取消标志，按钮显示“正在停止”并禁止重复点击。
2. 清空刷新网格、刷新结果、导出图层、删除结果等等待标志。
3. 使用 `QProcess::kill()` 结束当前执行程序，不在界面线程调用阻塞等待。
4. 收到进程结束或错误信号后先检查取消标志；取消任务只恢复界面并显示“任务已停止”。
5. 取消后不得自动刷新目录、重新导出、载入结果、显示完成横幅或写入历史成功记录。
6. 关闭窗口时若仍有任务，同样执行取消流程，避免残留后台进程。

目录刷新与图层载入还应记录已载入对象标识。同一数据库、项目、网格和结果未变化时，刷新列表或重新打开图层只更新可见性，不重复启动导出任务。目录查询还要记录“正在查询”状态，用户快速重复展开下拉框不得排入多个相同任务。网格目录与结果目录需要连续更新时必须串行执行，不能让两个零延迟任务竞争同一个 `QProcess`。只有对象选择发生变化、缓存文件失效或用户明确点击“重新载入”时，才重新读取数据；导出或解析失败时必须关闭相应图层开关并显示失败原因，不能保留“开关已打开、画布仍为空”的假状态。

追踪成功后不再自动启动一次数据库结果目录查询。程序直接把本次生成的对象加入结果列表并设为当前项，已有目录需要更新时由用户点击“刷新结果列表”。刷新、导出和载入任务不得把主按钮文字改成“追踪中”，否则会造成算法重复执行的错误观感；主按钮只有在真正执行断层追踪时才显示追踪状态。

## 9. 分阶段实施顺序

### P0 正确性与首次使用

- 配置版本迁移和无效资源清理。
- 窗口显示后的无感目录刷新。
- 空下拉框配置引导。
- 配置保存后自动刷新。
- 所有忙碌分支和错误分支提供反馈。
- 全新用户中文、图层关闭、视图默认平移。
- 工区底图启动状态可验证。

### P1 一致性与响应速度

- 左栏和标签宽度统一。
- 两套程序使用共享图层开关。
- 移除重复叠加按钮。
- 视图区加载状态统一。
- 网格和多边形解析异步化。
- 目录和图层缓存。

### P2 GeoEast 深度集成

- 使用结构化目录协议。
- 通过宿主通信接口打开工区底图或平面成图并传递当前对象。
- 完成不同 GeoEast 安装路径、许可状态和工区状态的兼容性回退。

## 10. 验收标准

### 10.1 全新电脑

- 用户配置目录不存在时，独立软件和插件均以中文打开。
- 不显示任何测试文件、开发目录、旧网格或旧结果。
- 插件窗口先显示，再后台检查数据库。
- 配置不完整时点击网格下拉框可直接获得配置引导。

### 10.2 旧配置升级

- 存在的用户参数和显示偏好得到保留。
- 不存在的 EXE、DAT、输入和输出路径自动清除或重新检测。
- 旧网格只有在当前项目目录中存在时才恢复。
- 升级过程不崩溃，不要求用户手工删除 INI。

### 10.3 操作反馈

- 所有可见按钮均有实际行为。
- 操作超过 150 ms 时出现反馈，完成或失败后状态明确。
- 任务忙碌时再次点击不会静默失效。
- 工区底图启动失败时在 2 s 内给出可理解原因。

### 10.4 视图与布局

- 两套程序默认平移，滚轮缩放正常。
- 图层开关整行可点击，键盘可操作，状态清楚。
- 选择已存在且开关开启的网格或结果后自动显示。
- 1280×720、1366×768、1920×1080 和高 DPI 环境无文字遮挡、控件重叠或异常留白。
- 左侧栏可拖动且保持完整控件所需的最小宽度。

### 10.5 性能与稳定性

- 自动刷新不阻塞首屏和窗口拖动。
- 官方 `test.dat` 解析和显示期间界面保持响应。
- 重复显示同一图层能够命中缓存，时间明显低于首次加载。
- 连续刷新、切换图层、运行、停止和关闭不会崩溃或残留失控进程。
- 核心算法对象数量、拓扑、结果哈希和性能指标不得退化。

## 11. 发布要求

实现完成后必须从同一干净 Git 提交重新构建 CLI、独立软件、GeoEast Launcher、BO Runner、主框架插件、发布 ZIP 和 Windows 安装器。随后执行自动化回归、两套界面功能核对、参数一致性、官方数据复现、安装器隔离运行、GeoEast 真实工区操作和逐文件哈希检查。只有这些结果一致，才能替换作品提交目录中的代码包和说明材料。

## 12. 本轮实施记录

本轮开发已将本文 P0 项目和直接影响使用体验的 P1 项目落实到独立软件与 GeoEast 插件。两套程序使用共享的 `LayerToggle` 图层开关，整行均可点击，具备键盘焦点、悬停反馈、短时状态动画和颜色标识；原始网格与结果多边形仍是两个相互独立的显示状态，同时开启时自然形成叠加视图，不再增加含义重复的第三个按钮。视图区启动后默认处于平移状态，重置视图后仍保持平移，滚轮只在视图区执行缩放，参数控件继续由滚轮过滤器保护。

配置版本已提升至 4。配置目录支持通过 `FPT_CONFIG_ROOT` 隔离，自动化测试、安装器烟测和人工验收可以使用独立配置位置，不再污染真实用户配置。启动时会核验执行程序、GeoEast 根目录、数据根目录和 DAT 文件；失效路径自动回退到当前环境的检测结果，未启用 DAT 导入时不恢复历史 DAT 路径。网格名只在数据库刷新后确认存在时恢复，占位提示文字不会再被当作真实网格名或输出对象名保存。

GeoEast 插件在主窗口显示后延迟启动目录发现，窗口首屏不被数据库访问阻塞。配置完整时依次刷新网格和结果；配置不完整时只显示非模态状态提示，用户点击空下拉框后再进入配置引导。插件目录解析已改为使用执行程序的原始标准输出，不再从翻译、着色或过滤后的日志文本反向推断对象名称，从而消除了同一工区中独立软件可以列出结果而插件显示空列表的问题。

显示性能采用“文件身份缓存 + 图像缓存 + 路径复用”方案。网格和多边形文件以绝对路径、文件大小和修改时间组成缓存键，同一对象重复显示时不再解析文本；网格图像仅在数据变化时重建，平移和缩放只改变视图变换。首次载入前显示状态文字并切换等待光标，后台数据库导出继续使用 `QProcess`，所有忙碌分支均给出可见反馈。该方案不改变核心算法输入、结果几何、GeoEast 写库内容和正式参数。

工区底图与平面成图经过实际 GeoEast 运行验证：这两个程序需要 GeoEast 当前工区创建的会话参数，普通的无参数 `startDetached()` 可能短暂启动后立即退出。因此入口现会优先切换到已经运行的官方窗口；若独立启动请求快速退出，则自动切回 GeoEast 主窗口并说明从顶部工具栏打开的方法，不再把“进程创建成功”误报为“工区视图已经可用”。插件内真实图层视图不依赖该官方窗口，可继续完成网格、结果和叠加检查。

自动验收规则已同步更新，不再把固定宽度标签、传统小复选框和重复叠加按钮当作合格条件。当前规则检查响应式标签、共享图层开关、默认关闭图层、默认平移、配置版本迁移、目录引导、真实图层载入、GeoEast 读写入口和参数一致性。正式发布仍须执行第 11 章规定的完整构建与回归流程。
