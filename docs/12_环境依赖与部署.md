# 第12章 环境依赖与部署

## 12.1 独立软件环境

独立软件正式支持 Windows 10/11 x64。发布包自带 Qt 运行库、平台插件、图标、帮助文档、示例数据、核心执行程序和应用本地 Visual C++ 运行库，用户不需要预先安装 Qt、Python、Visual Studio 或开发工具。安装器采用当前用户级安装，不修改系统 `PATH`；便携版可以从普通文件夹运行，但必须保留完整目录结构。

新电脑首次启动时，软件使用 Windows 标准用户目录保存配置、缓存和结果。文档目录被 OneDrive、域策略或安全软件重定向且不可写时，程序会依次改用当前用户本地数据目录和临时目录，不向受保护的安装目录写入。开始计算前会检查输入文件可读性、输出名称、目录写权限、磁盘空间、输入输出冲突和已有结果覆盖。

## 12.2 开发环境

开发环境通常需要：

| 类型 | 说明 |
|---|---|
| 操作系统 | Windows。 |
| 编译器 | Visual Studio C++ 工具链。 |
| Qt | 用于独立软件和 GeoEast 启动器。 |
| GeoEast | 用于 BO runner、主控插件和现场验证。 |
| Python | 用于质量图、诊断和报告脚本。 |
| PowerShell | 用于构建、打包和验收脚本。 |

## 12.3 GeoEast 环境

GeoEast 集成需要有效 license、正确版本的 GeoEast 安装目录、可访问数据库和目标工区。若 GeoMapping 或平面成图功能提示无 license，需要先确认 license 年份、版本和安装目录是否匹配。GeoEast-RC、NGP、iECO 等目录或产品名可能对应不同组件或版本，现场部署时应以实际可运行的 GeoEast 主程序为准。

## 12.4 部署流程

源码部署到 GeoEast 可运行：

```powershell
.\scripts\部署到GeoEast.ps1
```

发布交付建议使用发布包中的安装或启动入口，而不是让用户从源码目录查找 exe。GeoEast 集成部分使用 `安装GeoEast插件.cmd` 部署：脚本会检测常见安装位置，要求 GeoEast 已退出，覆盖前备份既有插件并在复制后核对文件哈希；路径受保护时会给出管理员权限提示，不能写死开发者机器目录。

## 12.5 部署验证

部署后至少验证四件事：独立软件能在空白配置下打开；核心 CLI 能在含中文和空格的路径中运行示例数据；GeoEast 菜单入口能打开启动器；GeoEast 中能读取网格并写入结果。安装器自动测试还应覆盖当前用户安装、程序依赖、官方数据运行、结果哈希和卸载。完整验证见 `docs/13_测试说明.md`。
