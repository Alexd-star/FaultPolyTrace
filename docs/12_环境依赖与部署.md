# 第12章 环境依赖与部署

## 12.1 独立软件环境

独立软件面向 Windows 桌面环境。发布包应自带 Qt 运行库、平台插件、图标、帮助文档、示例数据和核心执行程序。用户不应需要手动安装 Qt 或 Visual Studio 才能打开发布包。

## 12.2 开发环境

开发环境通常需要：

| 类型 | 说明 |
|---|---|
| 操作系统 | Windows。 |
| 编译器 | Visual Studio C++ 工具链。 |
| Qt | 用于独立软件和 GeoEast 启动器。 |
| GeoEast | 用于 BO runner、主控插件和现场验证。 |
| Python | 用于质量图、诊断和报告脚本。 |
| PowerShell | 用于构建、打包和验收脚本。 |

## 12.3 GeoEast 环境

GeoEast 集成需要有效 license、正确版本的 GeoEast 安装目录、可访问数据库和目标工区。若 GeoMapping 或平面成图功能提示无 license，需要先确认 license 年份、版本和安装目录是否匹配。GeoEast-RC、NGP、iECO 等目录或产品名可能对应不同组件或版本，现场部署时应以实际可运行的 GeoEast 主程序为准。

## 12.4 部署流程

源码部署到 GeoEast 可运行：

```powershell
.\scripts\部署到GeoEast.ps1
```

发布交付建议使用发布包中的安装或启动入口，而不是让用户从源码目录查找 exe。GeoEast 集成部分应在安装或部署脚本中检测目标 GeoEast 路径，不能写死开发者机器目录。

## 12.5 部署验证

部署后至少验证四件事：独立软件能打开；核心 CLI 能运行示例数据；GeoEast 菜单入口能打开启动器；GeoEast 中能读取网格并写入结果。完整验证见 `docs/13_测试说明.md`。
