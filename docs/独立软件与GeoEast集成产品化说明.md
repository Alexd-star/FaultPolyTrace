# 独立软件与 GeoEast 集成产品化说明

## 1. 建设目标

FaultPolyTrace 需要同时满足两类交付场景：一类是评审或用户在没有 GeoEast 环境的电脑上直接运行独立软件，完成外部网格文件读取、断层多边形追踪、结果查看和文件导出；另一类是在 GeoEast 平台内作为集成工具使用，读取 GeoEast 数据库中的 BOMapGrid 对象，并将闭合断层多边形写回数据库。

本轮产品化改造的原则是：算法核心共用，界面外壳拆分。独立桌面软件和 GeoEast 集成控件不再放在同一个 Qt 窗口里，也不再通过同一个窗口混合两套使用逻辑。独立软件默认面向外部文件、结果查看、历史记录和文件导出，同时提供可选的 GeoEast 数据库数据源模式；GeoEast 集成控件面向 GeoEast 平台内的 BOMapGrid 选择、BOFaultPolygon 写回和平台内操作提示。这样既满足赛题“独立运行也可集成 GeoEast”的要求，也避免界面拥挤、路径混乱、评审双击入口误判和后续维护时互相污染。

## 2. 产品形态

### 2.1 独立软件形态

独立软件入口为发布包根目录的 `FaultPolyTrace.exe`，源码位于 `standalone_app/qt_desktop`。同时保留 `01_打开图形界面.cmd` 作为兼容入口。用户打开后默认进入外部文件处理流程，界面会自动定位发布包内的 `bin/faultpolytrace.exe` 和示例网格文件。用户可以选择外部网格文件，设置输出目录和结果名称，点击【开始追踪】后生成 CSV 多边形、GeoJSON、诊断 JSON、拓扑 CSV 和枝干 CSV，并可在界面中切换【原始网格】、【结果多边形】和【叠加视图】。

独立软件不强制依赖 GeoEast 数据库，适合评审快速验证算法模块可独立运行，也适合后续扩展为正式安装版软件。当用户电脑存在 GeoEast 环境并完成数据库配置时，独立软件也可以切换到【GeoEast数据库】数据源，通过 `faultpolytrace_geoeast_runner.exe` 读取 BOMapGrid、写入 BOFaultPolygon，并在本地输出真实图层缓存用于查看。

### 2.2 GeoEast 集成形态

GeoEast 集成控件入口为 `geoeast_plugin/qt_launcher/faultpolytrace_launcher.exe`，源码仍位于 `geoeast_plugin/qt_launcher`。它通过 `geoeast_plugin/bo_runner/faultpolytrace_geoeast_runner.exe` 与 GeoEast 数据库交互。用户在 GeoEast 菜单中点击“断层多边形追踪”后，看到的是数据库连接、输入网格、输出多边形、显示样式和必要算法参数。点击【刷新网格】可读取数据库中的 BOMapGrid 列表，点击【开始追踪】后结果写回 GeoEast 数据库，随后在 GeoEast 底图、平面成图或工区底图中叠加查看。

集成控件保留环境变量和安装目录自动配置能力，优先读取 `FPT_GEOEAST_ROOT`、`FPT_GEOEAST_DATA_ROOT`、`FPT_GEOEAST_USER`、`FPT_GEOEAST_DB`、`FPT_GEOEAST_PROJECT` 等变量。没有变量时，界面允许用户手动填写，并保存到配置文件。独立软件中的 GeoEast 数据库字段只在用户主动选择【GeoEast数据库】数据源后出现；普通外部文件流程不会要求用户理解 BOMapGrid、BOFaultPolygon、PG 主机或项目名。

## 3. 关键能力

### 3.1 配置记忆

独立软件关闭后会保存输入文件、输出目录、输出名称、视图模式、颜色线宽、透明度、算法参数、数据源模式和可选 GeoEast 数据库配置。再次打开时自动恢复上次配置，避免每次重新填写。配置文件位于系统用户配置目录，而不是程序安装目录，因此更适合普通用户权限和发布包只读目录。GeoEast 集成控件继续使用自己的配置文件保存平台内数据库和工程相关信息，两者互不覆盖。

### 3.2 参数模板

用户可以通过【文件】菜单导出参数模板 JSON，也可以导入已有模板。模板记录算法参数，不绑定某台电脑的绝对路径，适合团队复用和答辩现场快速切换方案。界面同时提供【恢复默认配置】入口，用于回到推荐的防黏连增强方案。

### 3.3 结果预览

独立模式支持读取矩阵网格和 GeoEast DAT 五列采样格式，界面以白底彩色属性图显示原始响应，并支持显示结果多边形或叠加结果。GeoEast 数据库模式运行完成后，会由 BO Runner 导出真实网格缓存和真实多边形 CSV 缓存，独立软件用同一套真实图层查看控件显示结果。该查看能力用于快速核对追踪结果是否贴合原始断层响应，正式图件和质量评估仍以脚本生成的白底质量图和验收报告为准。

当前版本已修复官方 `test.dat` 大文件载入卡死风险。旧实现会一次性读取约 82 MB 文件并拆成字符串列表；新实现采用流式解析 Line/CMP/X/Y/Value，并按核心算法相同的 Line-X、CMP-Y 坐标方向构造图层，同时缓存色图，缩放和平移不再重复解析大文件。

### 3.4 耗时反馈

状态栏显示处理耗时，格式为 `xxx ms (x.xxx s)`。这项信息用于证明算法核心处理满足赛题 1 分钟内完成的性能要求，也便于用户比较不同参数组合的耗时影响。

### 3.5 发布包去个人化

发布脚本会在打包阶段清理文档、脚本和配置中的个人路径、用户名和本机数据路径。发布包根目录的 `FaultPolyTrace.exe` 来自 `standalone_app/qt_desktop`；`qt_launcher/faultpolytrace_launcher.exe` 来自 `geoeast_plugin/qt_launcher`。二者都携带各自需要的 Qt 运行库和 `qt.conf`，保证换电脑后不会因为硬编码路径或 Qt DLL 混用导致启动失败。

## 5. 后续建议

后续若继续向正式安装产品推进，建议增加安装器、卸载器、桌面快捷方式、开始菜单入口、版本升级检测和安装目录权限检查。同时可继续强化独立模式的数据管理，例如增加历史任务列表、结果缩略图、批量处理队列和一键导出质量报告。
