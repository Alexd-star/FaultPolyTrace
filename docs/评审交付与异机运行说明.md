# FaultPolyTrace 评审交付与异机运行说明

## 1. 本文目的

本文说明 FaultPolyTrace 在比赛评审、异机复核和普通用户演示时应该如何打开、如何验证、遇到运行库问题时如何处理。本文关注的是交付可靠性，不改变算法原理和质量指标。

## 2. “算法模块可独立运行”的含义

赛题中的“算法模块应可独立运行，也可以集成到 GeoEast 平台中”不是要求评审必须直接双击命令行核心程序完成全部处理，而是要求核心算法不依赖 GeoEast 数据库和主控平台也能处理外部网格文件。

本项目对应两类入口：

| 入口 | 定位 | 是否需要 GeoEast |
|---|---|---|
| `bin/faultpolytrace.exe` | 离线命令行算法核心，适合批处理、回归验证和外部文件处理 | 不需要 |
| `02_运行离线演示.cmd` | 对命令行核心的双击封装，适合评审快速验证独立运行能力 | 不需要 |
| `qt_launcher/faultpolytrace_launcher.exe` | 图形化参数启动器，适合用户选择 GeoEast 数据库、网格和参数 | 执行 GeoEast 数据读写时需要 |
| `geoeast_plugin/bo_runner/faultpolytrace_geoeast_runner.exe` | GeoEast BO 数据库读写适配程序 | 需要 |
| GeoEast 菜单入口 | 集成到 GeoEast 平台后的用户入口 | 需要 |

因此，评审人员在没有 GeoEast 的电脑上也可以运行 `02_运行离线演示.cmd`，看到算法读取外部网格、生成闭合多边形 CSV 和诊断 JSON；在具备 GeoEast 的电脑上，再通过图形启动器或 GeoEast 菜单完成数据库读写闭环。

## 3. 为什么不建议直接双击 `faultpolytrace.exe`

`faultpolytrace.exe` 是命令行程序，需要 `--input` 和 `--output` 参数。没有参数时，它不会知道应该读取哪个网格、输出到哪里，因此不会开始计算。

当前版本已经做了防误判处理：直接双击无参数时，程序会显示中文说明和推荐入口，不再一闪而过。正式评审仍推荐双击发布包根目录的：

```text
01_打开图形界面.cmd
02_运行离线演示.cmd
03_查看命令行帮助.cmd
```

这样评审能明确看到产品入口、离线演示入口和命令行帮助，不会把“无参数退出”误判为软件故障。

## 4. Qt 运行库和加载路径策略

Qt 启动器使用 GeoEast 自带 Qt 5.15.2 构建。发布包的 `qt_launcher` 目录会随包携带以下内容：

- `faultpolytrace_launcher.exe`
- `qt.conf`
- `Qt5Core.dll`
- `Qt5Gui.dll`
- `Qt5Widgets.dll`
- `Qt5Svg.dll`
- `platforms/qwindows.dll`
- `imageformats/`
- `iconengines/`
- `styles/`
- `translations/`
- Visual C++ 运行库 DLL

`qt.conf` 将 Qt 插件搜索路径限制在启动器目录内，减少系统 PATH、其它 Qt 安装目录或 GeoEast 环境变量造成的版本混用风险。

如果出现“无法定位程序输入点”或类似 Qt 入口错误，优先判断为 Qt DLL 版本混用。处理方式是重新解压完整发布包，或重新运行：

```powershell
.\scripts\build_qt_launcher.ps1
```

不要把单个 `faultpolytrace_launcher.exe` 拷到其它目录后单独运行。

## 5. 发布包推荐结构

发布包根目录应包含：

```text
README_先打开我.md
01_打开图形界面.cmd
02_运行离线演示.cmd
03_查看命令行帮助.cmd
bin/faultpolytrace.exe
qt_launcher/
docs/
examples/
scripts/
src/
geoeast_plugin/
prerequisites/
```

其中 `02_运行离线演示.cmd` 会使用发布包自带合成网格，在 `outputs/offline_demo_时间戳` 下生成结果，便于评审复查。

## 6. 异机运行前检查清单

在把发布包发给评审或在新电脑上演示前，应检查以下事项：

| 检查项 | 预期结果 |
|---|---|
| 发布包为完整 ZIP 解压目录 | 不只复制单个 exe |
| `01_打开图形界面.cmd` 可打开窗口 | 无 Qt 入口错误 |
| `02_运行离线演示.cmd` 可完成计算 | 生成 CSV 和 JSON |
| `bin/faultpolytrace.exe` 无参数时显示中文说明 | 不一闪而过 |
| `qt_launcher/Qt5Widgets.dll` 版本 | 5.15.2 |
| `qt_launcher/qt.conf` 存在 | Qt 插件从本目录加载 |
| `prerequisites/vc_redist.x64.exe` 存在 | 可用于缺少 VC 运行库的电脑 |

## 7. GeoEast 集成运行说明

有 GeoEast 环境时，可以通过 `scripts/部署到GeoEast.ps1` 部署。部署脚本会保留两个入口：

1. `GeoEast-RC/bin/faultpolytrace_launcher.exe`：兼容旧菜单路径。
2. `GeoEast-RC/bin/FaultPolyTraceLauncher/`：包含 Qt 运行库的完整启动器目录，推荐新菜单指向此目录下的 `faultpolytrace_launcher.exe`。

如果用户手动在 GeoEast 中添加外部程序菜单，推荐选择：

```text
C:\Users\26312\GeoEast\GeoEast-RC\bin\FaultPolyTraceLauncher\faultpolytrace_launcher.exe
```

这样可以避免启动器从 GeoEast 主程序目录、系统 PATH 或其它 Qt 安装目录加载到不匹配的 DLL。
