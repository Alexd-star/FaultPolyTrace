# 第4章 开发者文档

## 4.1 开发目标

FaultPolyTrace 的开发目标是保持算法核心、独立软件、GeoEast 集成和发布验收四条线清晰分离。任何界面优化都不应破坏核心算法参数；任何 GeoEast 适配修改都不应污染独立文件模式；任何发布包调整都应通过自动验收脚本复查。

## 4.2 代码分层

项目主要分为五层：

1. 核心算法层：`src/core/`
2. 数据读写层：`src/io/`
3. 命令行入口：`src/app/`
4. 独立桌面软件：`standalone_app/qt_desktop/`
5. GeoEast 集成：`geoeast_plugin/`

核心算法层不应直接依赖 Qt 控件或 GeoEast SDK。GeoEast SDK 相关逻辑应集中在 BO runner 和适配层中。独立软件和 GeoEast 启动器可共享本地化文本、参数定义和运行器调用逻辑，但界面布局和使用流程应按各自场景保持独立。

## 4.3 构建建议

常用开发构建顺序：

```powershell
.\scripts\build.ps1
.\scripts\run_smoke_test.ps1
.\scripts\build_desktop_app.ps1
.\scripts\检查独立软件界面功能.ps1
.\scripts\build_qt_launcher.ps1
.\scripts\检查GeoEast插件界面功能.ps1
```

如果修改 GeoEast 数据库读写，应额外构建并现场验证：

```powershell
.\scripts\build_geoeast_bo_runner.ps1
```

## 4.4 修改原则

- 修改算法默认参数后必须重新运行官方 `test.dat` 验收。
- 修改 UI 布局后必须截图或自动检查遮挡、按钮状态、前置提示和图层显示。
- 修改发布包脚本后必须运行发布包验收和客户机可移植性检查。
- 修改文档后应同步更新 `README.md`、`PROJECT_INDEX.md` 和 `docs/文档目录.md`。

## 4.5 待确认开发事项

根据当前审计，代码自动项没有失败。仍需人工确认 GeoEast 现场效果，包括菜单入口、自动配置、数据库对象写入、结果叠加显示和演示视频。若后续新增安装器、自动更新或更多语言，需要建立单独分支和独立验收脚本。
