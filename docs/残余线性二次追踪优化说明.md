# 残余线性二次追踪优化说明

文档版本：V1.1  
更新日期：2026-05-22  
适用对象：FaultPolyTrace 高召回复核能力

## 1. 定位结论

残余线性二次追踪不是当前正式交付主线的默认功能，而是用于解释人员复核弱响应漏检区域的高级功能。

当前正式主线采用“贴合融合推荐”方案：

```text
ridge-belt + 属性约束断层带 + 端点补连 + 多外环闭合追踪
residual-trace = false
root-anti-merge = false
separate-branch-belts = false
```

这条主线在官方数据上的当前指标为：

| 指标 | 当前正式主线 |
|---|---:|
| 保留多边形 | 204 |
| 强响应覆盖率 | 约 99.62% |
| 弱响应覆盖率 | 约 96.94% |
| 开放环 | 0 |
| 自相交 | 0 |
| 多边形相交诊断 | 0 |
| 核心追踪耗时 | 约 0.42 至 0.45 秒 |
| 总耗时 | 约 1.30 至 1.36 秒 |

因此，正式交付时不应把残余二次追踪直接说成默认稳健方案。更准确的表述是：主线结果已满足赛题闭合、面积过滤、交切处理、性能和 GeoEast 集成要求；残余二次追踪用于进一步复核细弱线性响应。

## 2. 为什么不能默认开启

残余二次追踪的目标是补足主线结果之外仍有线性特征的弱响应区域。它确实能提高局部召回，但也会引入两个产品风险：

1. 结果碎片化：大量短小残余块会被输出成独立闭合多边形，多边形数量可能从 200 个量级膨胀到数千个。
2. 解释噪声：部分弱响应可能是噪声、属性边缘或非断层线性纹理，默认输出会增加人工复核负担。

赛题要求的是“断层多边形自动追踪”，不是把所有非零像元都围起来。正式结果应优先保证主要断层带连续、闭合、贴合、拓扑干净，再把弱残余作为可解释的复核对象。

## 3. 算法机制

残余二次追踪只在主追踪完成后运行，核心步骤如下：

1. 根据较低分位数构建残余弱响应掩膜。
2. 去掉已经被正式多边形覆盖的区域。
3. 在剩余区域中寻找细长、连续、属性值足够高的连通块。
4. 判断残余块是否接近已有断层带，或是否满足更严格的独立线性断层条件。
5. 将通过门控的残余块转为闭合多边形，并进入统一面积过滤和拓扑诊断。

残余块必须同时通过形态、强度、长度和规模约束，避免把大片弱背景误认为断层。

## 4. 当前正式主线参数

GeoEast 启动器“贴合融合推荐”以及验收脚本使用以下参数：

```text
trace-mode = ridge-belt
threshold-mode = percentile
percentile = 0.98
weak-percentile = 0.965
weak-connect-radius = 1
max-weak-component-cells = 20000
min-weak-component-aspect = 3
belt-radius = 3
post-belt-close-radius = 1
attribute-constrained-belt = true
attribute-envelope-radius = 1
min-branch-length = 4
min-junction-branch-length = 2
min-junction-branch-mean = 0.94
max-gap-distance = 12
max-gap-angle = 55
min-gap-support-ratio = 0.25
separate-branch-belts = false
root-anti-merge = false
residual-trace = false
residual-percentile = 0.955
residual-fill-radius = 4
residual-min-cells = 2
residual-trace-min-length = 6
residual-trace-max-cells = 80
min-area = 120
```

说明：`residual-percentile` 等残余参数保留在配置中，是为了用户切换到高召回复核模式时有一致的默认值；正式主线通过 `residual-trace = false` 关闭二次输出。

## 6. 建议使用方式

正式比赛演示和默认产品流程：

- 使用“贴合融合推荐”。
- 保持残余二次追踪关闭。
- 用漏检质控图查看尚未覆盖的细弱响应。
- 只在解释人员需要复核弱线段时启用高召回预设。

高召回复核流程：

- 开启“残余二次追踪”。
- 观察新增多边形是否集中在真实线性残余处。
- 若出现大量短碎片，应提高 `residual-trace-min-length`、降低 `residual-trace-max-cells` 或关闭独立残余追踪。
- 高召回结果应作为辅助解释层，不建议直接覆盖正式结果。

## 7. 后续优化方向

为了把残余二次追踪做成真正企业级能力，下一步不应继续靠手动调参，而应增加自动门控：

1. 计算残余块与主断层走向的一致性。
2. 识别残余块是否跨越低值背景桥，防止误合并。
3. 给每个残余块输出“补追踪原因”和“过滤原因”。
4. 按风险等级输出为正式层、复核层、忽略层。
5. 把新增残余结果纳入固定回归门槛，确保召回提升不以碎片化和误合并为代价。
