# FaultPolyTrace Qt 启动器界面优化规划

文档版本：V1.0  
编制日期：2026-05-31  
适用对象：FaultPolyTrace Qt 启动器、GeoEast 集成入口、评审演示发布包  
目标：在不影响现有算法、GeoEast 数据库读写和离线运行能力的前提下，将当前启动器优化为更接近 GeoEast 原生工具风格、更清晰、更易操作、更适合评审展示和正式交付的界面。

## 2. 赛题界面要求复核

赛题要求界面满足以下能力：

1. 提供友好的用户交互界面。
2. 支持输入数据选择。
3. 支持输出数据命名。
4. 支持必要计算参数设置。
5. 可以读写外部文件。
6. 可以读写 GeoEast 数据库。
7. 适合集成到 GeoEast 平台中使用。

当前版本已经具备核心功能，但界面体验仍偏“开发调试表单”。主要问题不是功能缺失，而是信息组织和视觉层级不够产品化。所有连接参数、输入输出、计算参数和日志几乎堆在同一个窗口里，用户一打开就会看到大量字段，不容易判断“第一步做什么、第二步做什么、哪些参数必须改、哪些参数可以默认”。

## 3. GeoEast 原生界面风格观察

根据用户提供的 GeoEast `GeoMapping`、`GeoBasemap`、`Crossplot and Histogram` 截图，以及本机 GeoEast 目录中的头文件和图标资源，可以归纳出以下界面特征。

### 3.1 总体结构

GeoEast 典型界面不是现代 Web 卡片式布局，而是经典专业桌面软件布局：

1. 顶部标题栏显示模块名和项目名。
2. 标题栏下方是菜单栏，包含文件、编辑、视图、图层、工具、属性、帮助等。
3. 菜单栏下方是小图标工具栏，图标通常为 16 到 24 像素。
4. 左侧是对象树或图层树。
5. 中央是主要工作区或空白画布。
6. 右侧可能是色标、属性条或辅助面板。
7. 底部是状态栏，显示坐标、项目名、当前操作状态。

这种界面风格的重点不是“装饰”，而是“专业、密集、稳定、可扫描”。对 FaultPolyTrace 来说，最应该借鉴的是信息分区和工具栏工作流，而不是做大面积渐变、卡片或现代营销式界面。

### 3.2 控件与布局规律

本机可参考的 GeoEast 头文件包括：

```text
C:\Users\26312\GeoEast\GeoEast-RC\include\sfp\io5\workareabase\ui_workareaframe.h
C:\Users\26312\GeoEast\GeoEast-RC\include\sfp\io5\workareabase\ui_dlgworkarea.h
```

这些文件显示 GeoEast 仍大量使用 Qt Widgets 的经典布局：

1. `QGridLayout`、`QHBoxLayout`、`QVBoxLayout` 组合。
2. `QGroupBox` 用于参数分组。
3. `QTableWidget` 用于对象列表。
4. `QFrame` 横线用于区分内容区和底部按钮区。
5. `QPushButton` 尺寸相对克制，例如高度约 24 到 28 像素。
6. 对话框底部常见“确定/关闭/取消”按钮，右对齐。

因此，FaultPolyTrace 的新界面应继续使用 Qt Widgets 原生控件，少量 QSS 调整即可，不宜做成过度现代化的 Web 风格。

### 3.3 可复用图标资源

用户指定的两个资源目录均存在可参考图标：

```text

```

其中 `qcichart/icon` 更适合当前启动器，例如：

| 图标 | 可用于 |
|---|---|
| `fileOpen.png` | 选择外部文件、选择 DAT |
| `fileSave.png` | 保存配置、输出结果 |
| `refresh.png` | 刷新网格列表 |
| `reload_db.png` | 连接或刷新 GeoEast 数据库 |
| `polygonShape.png` | 断层多边形结果 |
| `mapsetting.png` | 参数设置 |
| `tipParameter.png` | 高级参数提示 |
| `dataanalysis.png` | 质量诊断、结果分析 |

实施时建议只复制必要的小图标到项目自有目录，例如：

## 4. 当前界面问题诊断

当前界面截图显示，功能虽然完整，但存在以下问题。

### 4.1 信息层级过平

当前界面把 GeoEast 连接、输入输出、样式、参数和日志全部直接展开。用户第一次打开时，视觉上没有明确主线，不知道应先看哪个区域。

应改为“常用操作优先，高级参数折叠”的结构。默认只展示能完成一次追踪所需的必要信息，高级参数通过标签页或高级按钮展开。

### 4.2 参数暴露过多

当前参数区一次显示近二十个参数。对于解释人员或评审来说，大多数参数并不需要立即调整。过多参数会带来两种负面影响：

1. 用户误以为必须理解每个参数才能运行。
2. 评审看到界面会觉得这是开发调试工具，而不是正式产品。

应把参数分成三层：

1. 基础参数：预设、最小面积、输出样式、追踪模式。
2. 推荐高级参数：阈值、分位数、带宽、平滑。
3. 专家参数：防黏连、弱响应补追、拓扑保护、残余复核。

### 4.3 GeoEast 数据库模式和外部文件模式没有清楚区分

赛题要求既能读写外部文件，也能读写 GeoEast 数据库。当前界面更偏 GeoEast 数据库，外部文件能力没有以独立入口呈现。

应在界面顶部提供“数据来源模式”切换：

```text
GeoEast 数据库 | 外部文件
```

GeoEast 模式显示数据库、项目、网格、输出 BOFaultPolygon。外部文件模式显示输入文件、输入格式、输出目录、输出 CSV/GeoJSON/WKT 和质量图选项。

### 4.4 日志区域占位固定但缺少运行摘要

当前底部日志区能显示文本，但缺少结构化摘要，例如：

1. 当前步骤。
2. 运行耗时。
3. 多边形数量。
4. 拓扑状态。
5. 是否写入成功。
6. 输出位置。

正式界面应保留日志，但默认给用户一个“结果摘要条”，日志作为可展开细节。

### 4.5 缺少 GeoEast 风格的菜单栏、工具栏和状态栏

当前窗口更像普通对话框。GeoEast 原生界面明显依赖菜单栏、工具栏和状态栏。为了靠近 GeoEast 风格，应加入：

1. 菜单栏：文件、数据、追踪、视图、帮助。
2. 工具栏：打开文件、连接数据库、刷新网格、运行、停止、结果样式、帮助。
3. 状态栏：项目名、数据源、当前状态、耗时。

## 5. 目标界面设计方向

### 5.1 产品定位

新界面应定位为“GeoEast 风格的专业解释工具启动台”，而不是独立炫酷软件。设计服务于构造解释人员、评审人员和开发验收人员的任务，不追求花哨。

设计关键词：

```text
专业、稳定、清晰、紧凑、可扫描、与 GeoEast 一致
```

不采用：

```text
大面积营销式卡片、强渐变背景、夸张圆角、大字号标题、复杂动画
```

### 5.2 视觉基调

推荐视觉策略为“克制型产品 UI”：

| 项目 | 建议 |
|---|---|
| 主背景 | Windows/GeoEast 风格浅灰 |
| 内容面板 | 白色或极浅灰 |
| 分隔线 | 1px 灰色线 |
| 主色 | GeoEast 蓝或当前项目蓝 |
| 强调色 | 只用于运行按钮、选中项、状态提示 |
| 字体 | Qt/Windows 默认中文界面字体，不额外引入特殊字体 |
| 控件高度 | 24 到 28 像素为主 |
| 图标尺寸 | 工具栏 16 或 24 像素 |

界面应看起来像 GeoEast 的一个工具，而不是另一个完全不同生态的程序。

## 6. 推荐新版界面结构

### 6.1 总体布局

建议从 `QDialog` 升级为 `QMainWindow`，或保留 `QDialog` 但内部模拟主窗口结构。更推荐 `QMainWindow`，因为它天然支持菜单栏、工具栏、状态栏和中央工作区。

推荐结构：

```text
┌─────────────────────────────────────────────────────────────┐
│ 标题栏：FaultPolyTrace - 断层多边形自动追踪                  │
├─────────────────────────────────────────────────────────────┤
│ 菜单栏：文件  数据  追踪  视图  帮助                         │
├─────────────────────────────────────────────────────────────┤
│ 工具栏：打开  连接  刷新  运行  停止  样式  诊断  帮助        │
├───────────────┬───────────────────────────────┬─────────────┤
│ 数据源与对象树 │ 工作流主面板                    │ 参数属性面板 │
│               │                               │             │
│ GeoEast/文件   │ 输入输出 / 结果摘要 / 日志       │ 基础/高级参数 │
│ 网格列表       │                               │             │
├───────────────┴───────────────────────────────┴─────────────┤
│ 状态栏：Project / Data Source / Status / Elapsed             │
└─────────────────────────────────────────────────────────────┘
```

窗口建议默认尺寸：

```text
1100 x 760
```

最低可用尺寸：

```text
1024 x 700
```

### 6.2 顶部菜单栏

菜单栏建议如下：

| 菜单 | 功能 |
|---|---|
| 文件 | 打开外部网格、选择 DAT、选择输出目录、退出 |
| 数据 | 连接 GeoEast、刷新网格、导入 DAT 为 BOMapGrid、检查数据范围 |
| 追踪 | 开始追踪、停止追踪、恢复推荐参数、打开高级参数 |
| 视图 | 显示/隐藏日志、显示/隐藏高级参数、打开输出目录 |
| 帮助 | 用户手册、算法说明、版本信息、环境检查 |

菜单不需要很复杂，但它能让界面更像 GeoEast 原生模块，并给评审一种“完整工具”的观感。

### 6.3 工具栏

工具栏建议使用小图标加 tooltip，文字可选。按钮顺序建议：

| 图标动作 | 推荐图标来源 | 行为 |
|---|---|---|
| 打开外部文件 | `fileOpen.png` | 切换到外部文件模式并选择输入 |
| 连接数据库 | `reload_db.png` | 检查 GeoEast 环境并读取项目 |
| 刷新网格 | `refresh.png` | 刷新 BOMapGrid 列表 |
| 输出设置 | `fileSave.png` | 定位输出命名区域 |
| 结果样式 | `polygonShape.png` | 设置颜色、线宽、填充 |
| 参数设置 | `tipParameter.png` 或 `mapsetting.png` | 打开高级参数页 |
| 开始追踪 | 项目自有图标或 play 图标 | 执行追踪 |
| 停止 | stop 图标 | 终止进程 |
| 质量诊断 | `dataanalysis.png` | 查看运行结果摘要 |
| 帮助 | `help-l.png` | 打开用户手册 |

工具栏按钮不应做大面积彩色背景，保持 GeoEast 小图标工具栏风格。

### 6.4 左侧数据源与对象树

左侧面板用于回答“当前从哪里读数据”。建议宽度约 240 到 280 像素。

内容结构：

```text
数据来源
  ○ GeoEast 数据库
  ○ 外部文件

GeoEast 项目
  数据库：ndp
  项目：BGPCup2026_Test7
  用户：26312
  [连接/刷新]

对象列表
  Surface Attributes
    test7_fault_attribute_bo
    test7_fault_attribute
  Fault Polygons
    FaultPolyTrace_Result
```

对于外部文件模式：

```text
外部文件
  输入文件：...
  格式：auto / matrix / geoeast-dat
  输出目录：...
  [浏览] [运行离线追踪]
```

左侧应尽量像 GeoBasemap 的图层树，使用 `QTreeWidget` 或 `QTreeView`，而不是只用下拉框。

### 6.5 中央工作流主面板

中央面板是用户完成任务的主路径。建议使用 `QTabWidget` 或顶部步骤条，默认显示“任务概览”。

推荐四个页签：

1. 数据输入。
2. 输出与样式。
3. 运行与结果。
4. 日志。

默认页“运行与结果”应包含：

```text
当前任务摘要
  输入：test7_fault_attribute_bo
  输出：FaultPolyTrace_Result
  参数预设：防黏连增强
  结果颜色：青色
  面积阈值：120

[开始追踪] [停止] [打开输出目录] [查看手册]

运行结果
  状态：就绪 / 运行中 / 成功 / 失败
  多边形数量：-
  拓扑：-
  耗时：-
```

日志不应一直占据太大面积。建议默认高度 160 到 220 像素，支持展开。

### 6.6 右侧参数属性面板

右侧面板用于回答“算法怎么跑”。建议宽度约 300 到 340 像素。

参数组织建议：

| 页签 | 内容 |
|---|---|
| 基础 | 参数预设、追踪模式、面积阈值、结果样式 |
| 阈值与断层带 | 阈值模式、分位数、弱响应分位、带宽半径、闭合半径 |
| 拓扑与防黏连 | 根系防黏连、局部桥防黏连、最大断距、最大夹角 |
| 边界与复核 | 简化容差、平滑次数、残余复核、补追限制 |

默认只展开“基础”。高级页签保留，但不要让用户第一眼就被所有字段压住。

### 6.7 底部状态栏

状态栏建议显示：

```text
Project: BGPCup2026_Test7 | Source: GeoEast | Grid: test7_fault_attribute_bo | Status: Ready | Elapsed: -
```

运行中显示：

```text
Tracing... 读取网格 / 追踪 / 写入数据库 / 完成
```

状态栏比日志更适合展示当前阶段。

## 7. 外部文件与 GeoEast 数据库双模式规划

### 7.1 GeoEast 数据库模式

GeoEast 模式保留当前 Runner 调用逻辑，但界面重新组织：

1. 连接设置默认折叠，只显示数据库、项目、用户摘要。
2. 点击“连接设置”后展开 GeoEast 根目录、数据根目录、PG 主机端口、Runner 路径。
3. “刷新网格”按钮放在左侧对象树顶部和工具栏中。
4. 输出对象命名放在中央“输出与样式”页，避免被连接参数淹没。
5. 运行时在状态栏显示 GeoEast 写入阶段。

### 7.2 外部文件模式

外部文件模式需要补成正式功能入口，建议直接调用 `bin/faultpolytrace.exe`，而不是 GeoEast runner。

界面字段：

| 字段 | 说明 |
|---|---|
| 输入文件 | 支持 `.txt`、`.dat`、矩阵文本 |
| 输入格式 | auto、matrix、geoeast-dat |
| 输出目录 | 默认发布包或项目的 `outputs` |
| 输出名称 | 默认 `FaultPolyTrace_Result_时间戳` |
| 是否生成诊断 | 默认开启 |
| 是否生成前后对比图 | 可选，若 Python 环境可用则启用 |

外部文件模式的意义很大：它直接证明“算法模块可独立运行”，也让没有 GeoEast 的评审电脑可以验证功能。

## 8. 启动过渡动画规划

用户提到 GeoEast 打开时有过渡动画。可以做，但必须非常克制，不能拖慢启动速度。

建议方案：

1. 使用 `QSplashScreen`。
2. 显示项目自有启动图，而不是直接复制 GeoEast 官方启动图。
3. 启动画面尺寸约 `450 x 245`，风格参考 GeoEast 蓝色地球图，但品牌改为 `FaultPolyTrace`。
4. 显示时间不固定等待，原则是“界面加载完成即关闭”。
5. 若界面加载非常快，最短显示 300 ms，最长不超过 800 ms。
6. 提供环境变量或配置项关闭：

```text
FPT_DISABLE_SPLASH=1
```

启动流程：

```text
main.cpp 创建 QApplication
显示 QSplashScreen
初始化图标资源和主窗口
加载设置
主窗口 show
splash finish
```

不应在启动画面期间连接数据库、刷新网格或执行耗时检查。数据库连接应由用户点击或后台异步触发，避免“启动动画变成卡顿遮羞布”。

## 9. 技术实现路线

### 9.1 推荐重构方式

建议采用渐进式重构，不一次性推翻当前逻辑。

第一阶段仍保留 `FaultTraceDialog` 的核心方法：

1. `configureGeoEastEnvironment`
2. `commonConnectionArgs`
3. `traceArgs`
4. `runTrace`
5. `refreshGrids`
6. `saveSettings`
7. `loadSettings`

同时把 UI 构建拆成多个小函数：

```text
buildMenuBar()
buildToolBar()
buildDataSourcePanel()
buildWorkflowPanel()
buildParameterPanel()
buildStatusBar()
buildLogPanel()
```

这样先解决界面层级问题，不动 Runner 调用逻辑，风险最低。

第二阶段再考虑拆类：

| 类 | 职责 |
|---|---|
| `FaultTraceWindow` | 主窗口、菜单、工具栏、状态栏 |
| `DataSourcePanel` | GeoEast/外部文件数据源选择 |
| `OutputStylePanel` | 输出命名、颜色、线宽、样式 |
| `TraceParameterPanel` | 参数预设和高级参数 |
| `RunLogPanel` | 日志、结果摘要、错误展示 |
| `SplashScreen` | 轻量启动画面 |

### 9.2 Qt 技术选型

推荐控件：

| 功能 | 控件 |
|---|---|
| 主窗口 | `QMainWindow` |
| 菜单栏 | `QMenuBar` |
| 工具栏 | `QToolBar` |
| 主区域分割 | `QSplitter` |
| 左侧对象树 | `QTreeWidget` |
| 中央页签 | `QTabWidget` |
| 参数分组 | `QFormLayout` + `QGroupBox` |
| 高级参数 | `QTabWidget` 或 `QToolBox` |
| 运行状态 | `QProgressBar` + `QLabel` |
| 日志 | `QPlainTextEdit` 优先于 `QTextEdit` |
| 启动画面 | `QSplashScreen` |
| 图标资源 | `QResource` + `.qrc` |

`QPlainTextEdit` 比 `QTextEdit` 更适合日志，因为它轻、更像控制台输出。

### 9.3 样式策略

不建议写大段 QSS。更稳妥的方式：

1. 使用 Qt/Windows 原生控件。
2. 少量设置边距、间距、工具栏图标尺寸。
3. 只对状态标签、结果摘要、颜色预览做局部样式。
4. 不自定义滚动条。
5. 不使用大圆角、阴影、渐变卡片。

建议尺寸：

```text
主窗口默认：1100 x 760
左侧面板：260 px
右侧参数：320 px
工具栏图标：24 x 24
普通按钮高度：26 px
表单标签宽度：80 到 110 px
日志默认高度：180 px
```

## 11. 运行状态与错误提示设计

错误提示要从“程序员日志”改为“用户能处理的问题”。

| 场景 | 当前可能表现 | 新界面应提示 |
|---|---|---|
| Runner 不存在 | 进程启动失败 | 未找到 GeoEast Runner，请检查路径或重新部署 |
| Qt DLL 混用 | 入口错误 | 请从完整发布包或 `FaultPolyTraceLauncher` 目录启动，不要单独复制 exe |
| GeoEast 根目录错误 | 运行失败 | GeoEast 根目录无效，请选择包含 `NGP` 和 `GeoEast-RC` 的目录 |
| 数据库未连接 | bad allocation 或连接异常 | 数据库连接失败，请检查许可证、PG host、数据库和项目 |
| 输入网格不存在 | runner 报错 | 未找到指定 BOMapGrid，请刷新网格列表或检查数据集管理 |
| 输出对象重名 | 写入失败或覆盖 | 输出对象已存在，请确认覆盖或更换名称 |
| 参数导致结果过碎 | 结果不理想 | 建议切换到“防黏连增强”或“均衡推荐”预设 |

日志仍保留原始输出，但界面顶部应显示一句清晰摘要。

## 13. 分阶段实施计划

### 阶段一：界面结构重排

目标：不改 Runner 调用逻辑，只重排界面。

任务：

1. 增加菜单栏、工具栏、状态栏。
2. 引入左中右三栏布局。
3. 把连接设置折叠或移动到左侧。
4. 把参数拆成基础和高级。
5. 把日志改为底部可展开区域。

验收：

1. GeoEast 模式仍能刷新网格。
2. GeoEast 模式仍能开始追踪。
3. 参数命令行与旧版本一致。
4. 界面默认窗口不拥挤。

### 阶段二：外部文件模式产品化

目标：让“独立运行”在图形界面中可见、可操作。

任务：

1. 增加 GeoEast/外部文件模式切换。
2. 外部文件模式调用 `bin/faultpolytrace.exe`。
3. 支持选择输入文件、输出目录、输入格式。
4. 运行后显示输出 CSV、诊断 JSON、拓扑 CSV。

验收：

1. 无 GeoEast 环境也能通过界面跑合成数据。
2. 发布包离线演示与图形界面路径一致。

### 阶段三：图标与 GeoEast 风格打磨

目标：让界面视觉更像 GeoEast 工具。

任务：

1. 建立 `assets/icons/geoeast_style` 图标子集。
2. 增加 `resources.qrc`。
3. 工具栏使用 16/24 像素图标。
4. 统一按钮高度、表单间距、面板宽度。
5. 增加轻量启动画面。

验收：

1. 启动器 3 秒烟测通过。
2. 启动时间不明显增加。
3. 发布包仍包含所有资源。
4. 在 1366 x 768 下无明显挤压。

### 阶段四：结果摘要与错误提示

目标：让用户不用看长日志也能知道结果是否成功。

任务：

1. 解析 runner 输出中的多边形数量、耗时、拓扑信息。
2. 在运行摘要区显示成功、失败、警告。
3. 常见错误转成中文解释。
4. 提供“复制日志”“打开输出目录”按钮。

验收：

1. 成功运行后显示多边形数量、耗时、拓扑状态。
2. 失败时能看到明确处理建议。

## 15. 主要风险与控制措施

| 风险 | 控制措施 |
|---|---|
| 改 UI 时破坏 Runner 参数 | 保留现有 `traceArgs()` 逻辑，先只重排控件 |
| 使用 GeoEast 图标存在授权不确定 | 优先复制少量内部评审资源；正式对外发布可重绘或使用项目自有图标 |
| 启动画面拖慢软件 | 使用 `QSplashScreen`，不做数据库连接，不固定等待 |
| 高级参数隐藏后用户找不到 | 提供“高级参数”页签和工具栏入口 |
| 外部文件模式与 GeoEast 模式混淆 | 顶部明确模式切换，字段随模式变化 |
| 低分辨率显示不完整 | 使用 `QSplitter`、滚动参数面板和最小尺寸测试 |

## 16. 推荐下一步

建议下一步先执行“阶段一：界面结构重排”，不要立刻做复杂动画或完整预览。原因是当前最大问题是信息架构，不是配色。

优先级如下：

1. 建立 GeoEast 风格主窗口骨架：菜单栏、工具栏、左中右分区、状态栏。

3. 增加外部文件模式入口，让赛题“独立运行”要求在界面上可见。
4. 最后再做图标资源、启动画面和视觉细节。
