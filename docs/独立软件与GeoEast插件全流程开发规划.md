# FaultPolyTrace 独立软件与 GeoEast 插件全流程开发规划

文档版本：v1.0
编写日期：2026-06-03
适用项目：赛题 7“基于平面断层属性的断层多边形自动追踪”
适用对象：开发者、测试人员、答辩准备人员、后续产品化维护人员
当前状态：待用户审阅

## 1. 文档目标

本文件用于把 FaultPolyTrace 后续开发工作从头到尾规划清楚，重点解决四个问题。

第一，明确独立软件和 GeoEast 插件不是同一个界面、不是同一套使用逻辑，而是共享核心算法的两条产品线。独立软件面向没有 GeoEast 环境的用户，重点是外部文件处理、结果显示、历史记录、模板和发布包可用性。GeoEast 插件面向 GeoEast 工区用户，重点是读取 BOMapGrid、写回 BOFaultPolygon、自动配置数据库环境、在 GeoEast 中查看叠加结果。

第二，把界面、功能、性能、操作方式、代码结构、测试方式和交付验收完整写清楚。后续开发不允许再出现“改了独立软件却破坏 GeoEast 控件”“添加按钮但没有功能”“显示参数与实际命令行参数不一致”“路径写死到某台电脑”“结果图能跑但质量退化”等问题。

第三，把赛题满分要求和企业级产品要求放到同一套验收体系里。赛题要求是最低边界，产品级要求还包括异机可安装、依赖完整、操作直观、错误提示清晰、性能稳定、历史可追溯、文档可交付、测试可复现。

第四，为后续实施提供分阶段计划。本文不是简单想法列表，而是可以指导代码开发、测试和发布的开发文档。每个阶段都应有明确目标、涉及文件、测试命令、验收标准和风险控制。

## 2. 总体原则

### 2.1 双线交付原则

FaultPolyTrace 后续必须保持“两套外壳，一个核心”的架构。

独立软件为 `standalone_app/qt_desktop/FaultPolyTrace.exe`，发布包根目录入口为 `FaultPolyTrace.exe`。它不显示 GeoEast 数据库、项目、用户、密码、BOMapGrid 列表等字段。它只处理外部文件和本地结果。

GeoEast 插件由三部分组成：主控入口插件、Qt 集成控件和 BO Runner。主控入口负责在 GeoEast 里提供按钮或菜单；Qt 集成控件负责参数交互和运行日志；BO Runner 负责连接 GeoEast 数据库、读取 BOMapGrid、写入 BOFaultPolygon。

核心算法程序为 `bin/faultpolytrace.exe`，由独立软件和 GeoEast Runner 共同调用。算法参数、质量指标、输出格式和诊断逻辑应以核心程序为准，界面只负责采集参数和展示结果。

### 2.2 不耦合原则

独立软件不得重新加入 GeoEast 数据库字段。GeoEast 控件不得加入独立软件的完整历史记录、外部文件图像管理和本地结果浏览职责。共享逻辑应放到核心 CLI、公共参数定义或脚本中，而不是把两套界面强行合并。

### 2.3 全控件可用原则

软件界面中不允许出现没有功能的按钮、菜单、输入框、下拉框、状态栏字段或图标。每个显示出来的控件必须满足三个条件：用户知道它做什么；点击或编辑后确实有动作；动作结果可以验证。未来功能如果暂时未实现，不应作为可见控件放在正式界面中。

### 2.4 显示即真实原则

界面显示的参数必须真实传递到核心算法。界面保存的模板必须包含这些参数。日志里显示的命令行必须能解释实际运行行为。结果视图显示的数据必须来自真实输出文件或真实 GeoEast 数据库对象，不能只显示静态示意图。

### 2.5 性能不退化原则

新增界面、模板、历史记录、图像预览和诊断功能，不得拖慢核心算法。核心追踪性能以核心 CLI 为准，界面启动和绘图也要有独立性能门禁。任何算法质量增强都必须通过覆盖率、防黏连、拓扑、耗时和内存回归，不能为了某一个指标牺牲其他指标。

### 2.6 可追溯原则

所有测试输出目录必须带时间戳或版本标记。所有关键实验、发布包、截图和报告都要能追溯到参数、代码提交和数据来源。后续不要覆盖掉重要历史结果，特别是官方数据对比、蓝框黏连诊断、残余复核层、白底质量图和 GeoEast 截图。

## 3. 用户角色与场景

### 3.1 独立软件用户

独立软件用户可能是评审专家、答辩演示人员、没有 GeoEast 环境的普通用户，或者只想处理外部网格文件的解释人员。用户期望双击程序后能直接看到软件界面，能打开示例数据，能选择自己的 DAT 或网格文件，能点击开始追踪，能看到原始属性图、结果多边形、叠加结果，能保存结果和图片。

独立软件不能要求用户理解 GeoEast 数据库、BOMapGrid、BOFaultPolygon、PG 主机、项目名、Runner 路径等概念。它要像一个完整桌面产品，而不是开发调试工具。

### 3.2 GeoEast 用户

GeoEast 用户已经在 GeoEast 工区中工作，关注的是从当前数据库读取指定平面断层属性数据，生成断层多边形并写回数据库。他们希望工具像 GeoEast 内置功能一样出现：有菜单或按钮入口，有 GeoEast 风格界面，有输入网格下拉框，有输出对象名，有必要参数，有运行日志，有“结果写入成功后去哪里查看”的提示。

GeoEast 用户不希望看到独立软件的本地历史记录、外部输出目录、示例数据路径等非平台字段。平台场景的核心是读库、写库、显示和复核。

### 3.3 开发和测试人员

开发人员需要清楚每个功能应该改哪些文件，不能为了修 UI 去动算法核心，也不能为了修 GeoEast 插件去改独立软件。测试人员需要按本文提供的矩阵验证每一个控件、每一个输出、每一个发布包入口。

### 3.4 答辩和交付人员

答辩人员需要一套稳定、可复现、中文化的交付材料：软件包、操作手册、算法原理、质量图、GeoEast 叠加截图、性能报告、内存报告、演示视频和常见问题说明。

### 4.2 异机运行要求

发布包必须包含 Qt DLL、VC 运行库或安装提示、`qt.conf`、平台插件、图像格式插件、示例数据、中文帮助文档和默认参数模板。发布包内不得残留开发机个人路径、用户名、网盘路径或固定 GeoEast 数据目录。

独立软件换电脑后应满足：双击能打开；默认示例能加载；点击开始能输出结果；不安装 GeoEast 也能完整演示。GeoEast 插件换电脑后应满足：部署脚本能检测 GeoEast 根目录；缺少 GeoEast 时提示明确；不应影响独立软件运行。

### 4.3 安装器目标

当前发布包可以继续使用便携 ZIP。下一阶段若推进正式产品化，应增加安装器。安装器应提供桌面快捷方式、开始菜单入口、安装目录选择、卸载入口、VC 运行库检测、可选 GeoEast 集成部署、默认文档打开入口。安装器不是赛题最低要求，但对“企业级交付”非常重要。

## 5. 独立软件规划

### 5.1 独立软件定位

独立软件是完整桌面应用，不是 GeoEast 控件的“脱壳版”。它应承担外部文件处理全流程：输入、预览、参数、运行、结果查看、导出、历史、模板、帮助。

源码目录：

```text
standalone_app/qt_desktop/
  main.cpp
  FaultPolyTraceWindow.h
  FaultPolyTraceWindow.cpp
  FaultPolyTraceDesktop.pro
```

发布入口：

```text
FaultPolyTrace.exe
```

核心调用：

```text
bin/faultpolytrace.exe
```

### 5.2 独立软件窗口布局

独立软件建议保持 GeoEast 风格的桌面窗口，不做网页式营销界面。窗口应支持最小化、最大化、缩放和 DPI 适配。默认窗口大小建议不小于 1280 x 760，最小窗口建议不小于 1100 x 680。窗口缩小时左侧参数区应使用滚动条，中央视图不应挤压到无法识别。

主界面分为五个区域。

第一，顶部菜单栏。菜单应包含【文件】、【编辑】、【视图】、【断层】、【工具】、【帮助】。每个菜单项都必须有真实动作，例如打开数据、保存模板、打开模板、恢复默认、导出 PNG、打开输出目录、查看帮助、查看关于。

第二，顶部工具栏。工具栏保留常用动作：打开数据、保存当前配置、平移模式、放大、缩小、重置视图、开始追踪、停止、导出 PNG、打开输出目录、帮助。图标大小要比当前小图标更清楚，建议 20 到 24 像素，并配合文字或工具提示。放大缩小图标必须使用符合用户直觉的放大镜加号和放大镜减号，不使用左右箭头。

第三，左侧参数面板。参数面板按业务分组显示，不要全部堆在一个大框里。推荐分组为“数据与输出”“显示样式”“追踪参数”“形态与拓扑约束”“枝干细节与修补”“防黏连参数”“历史记录”。每组控件要有统一标签宽度，输入框不能被遮挡，长路径使用工具提示展示完整路径。

第四，中央视图区。中央视图区应提供至少四种视图：任务预览、原始网格、结果多边形、叠加结果。任务预览用于在未运行时说明当前输入、输出、参数和状态；原始网格用于显示属性值色图；结果多边形用于只看追踪结果；叠加结果用于核对多边形是否贴合原始断层响应。视图必须白底或浅色背景，不使用黑底作为默认。

第五，底部日志与状态栏。日志区显示命令行、运行过程、错误信息和输出文件路径。状态栏显示当前鼠标坐标、当前视图模式、核心耗时、总耗时、输出状态和就绪状态。耗时格式使用 `300 ms (0.300 s)` 或 `1414 ms (1.41 s)`。

### 5.4 独立软件参数要求

界面参数必须与核心 CLI 保持一致。当前必须覆盖以下参数类别。

追踪参数：追踪模式、阈值模式、固定阈值、分位数、最小面积。

形态与拓扑约束：闭合半径、带宽半径、带后闭合、属性约束断层带、属性包络半径、最大断距、最大夹角、平滑次数、简化容差。

枝干细节与修补：弱响应分位、弱延伸半径、最短分支、交切短枝、交切均值、残余二次追踪、补追最短、补追上限。

防黏连参数：根系防黏连、根系半径、支撑比例、主体点数、主体比例、弱保护阈值、弱保护半径、局部桥防黏连、低值阈值、桥半径、局部主体、局部比例、桥点下限、低值比例。

显示参数：颜色、线宽、透明度、视图模式、缩放比例。

每个参数都要同时接入四个位置：界面控件、配置记忆、模板保存、命令行参数生成。缺一项都视为不完整。

### 5.5 独立软件错误处理

独立软件必须对常见错误给出明确中文提示。

输入文件不存在时，提示“请选择可读取的外部网格文件”，并保留当前界面。核心算法程序不存在时，提示发布包中应存在 `bin/faultpolytrace.exe`。输出目录不可写时，提示用户更换目录。核心进程退出码非 0 时，日志显示标准输出、标准错误和失败命令。CSV 未生成时，不能只说“无法读取 CSV”，还要说明可能原因：核心程序未启动、输出目录不可写、输入格式错误或算法异常。

## 6. GeoEast 插件规划

### 6.1 GeoEast 插件组成

GeoEast 集成由三层组成。

第一层是主控入口插件，源码目录为：

```text
geoeast_plugin/mainframe_plugin/
```

它负责在 GeoEast 主界面提供菜单、工具栏或 Ribbon 入口，点击后启动 Qt 集成控件。主控入口不承载复杂业务逻辑。

第二层是 Qt 集成控件，源码目录为：

```text
geoeast_plugin/qt_launcher/
```

它负责 GeoEast 场景下的用户交互，包括环境配置、网格刷新、输入选择、输出命名、参数设置、日志显示和运行提示。

第三层是 BO Runner，源码目录为：

```text
geoeast_plugin/bo_runner/
```

它负责连接 GeoEast 数据库，读取 BOMapGrid，调用核心算法，写入 BOFaultPolygon，并输出日志和诊断信息。

### 6.2 GeoEast 控件窗口布局

GeoEast 控件应保持接近 GeoEast 自带模块的风格：菜单栏、工具栏、左侧参数区、右侧预览或任务说明、底部日志和状态栏。界面不应显得像网页，也不应使用过大的卡片布局。

左侧分组建议为“GeoEast 环境”“数据管理”“追踪参数”“形态与拓扑约束”“防黏连与复核”“运行与日志”。数据库和路径配置可以放在一个“数据库与环境底层配置”弹窗中，主界面只显示当前连接摘要，避免主界面拥挤。

底部日志显示 Runner 命令、数据库连接、读取对象、写入对象、核心耗时、总耗时、错误提示和查看结果建议。

### 6.5 GeoEast 数据一致性要求

手工导入 DAT 与程序导入 DAT 可能因坐标、采样间隔、空间范围设置不同而显示比例不一致。GeoEast 控件应在日志中显示关键网格元信息，帮助用户核对。

### 6.6 GeoEast 查看结果操作

1. 打开 GeoEast 中的 GeoBasemap 或 GeoMapping。
2. 在图层树中加载原始平面断层属性网格。
3. 在断层多边形或 Fault Polygons 图层中加载输出对象。
4. 设置结果颜色为高对比颜色，例如青色、品红或亮黄色，避免与红色属性背景混在一起。
5. 调整线宽和透明度。
6. 放大到局部区域核对是否存在漏检、断裂、误合并和边界偏移。

## 7. 核心算法与共享能力规划

### 7.1 核心算法职责

核心算法负责数据处理，不负责界面。它应提供稳定 CLI 接口，支持外部文件输入，输出 CSV、GeoJSON、诊断 JSON、拓扑 CSV、枝干 CSV 和性能信息。它还应支持 GeoEast Runner 传递的参数。

核心源码目录：

```text
src/core/
src/io/
src/app/
```

核心模块职责如下。

| 模块 | 职责 |
| --- | --- |
| `Grid2D` | 网格数据结构、尺寸、坐标和值访问 |
| `AsciiGridIO` | 外部网格、DAT、GeoASCII 读取 |
| `BinaryMask` | 阈值、形态学处理、掩膜操作 |
| `SkeletonGraph` | 骨架、端点、交点、枝干拓扑 |
| `Segmentation` | 连通域和区域分割 |
| `FaultTracer` | 断层追踪主流程、补连、防黏连、残余处理 |
| `Polygon` | 多边形边界、面积、周长、简化和平滑 |
| `Topology` | 闭合、自相交、多边形异常相交检查 |
| `DiagnosticsIO` | 输出诊断、分支、拓扑和 JSON |

### 7.2 质量目标

一个好结果应满足以下标准。

1. 该识别的主要断层响应尽量覆盖。
2. 主要黑色或高响应线状断层连续追踪出来。
3. 不出现大量无意义碎片。
4. 不把相邻但无连续根系支撑的断层误合并。
5. 每个正式结果多边形都是闭合区域。
6. 边界平滑自然，不明显锯齿。
7. 交切位置拓扑干净，不自相交，不产生异常重叠。
8. 面积统计准确，面积阈值过滤可解释。
9. 弱残余不被忽略，可通过残余复核层提示。
10. 核心处理时间满足赛题 1 分钟要求，并争取秒级完成。

### 7.3 参数预设

建议保留三类正式预设。

贴合融合推荐：默认预设，平衡覆盖率、连续性、边界贴合和防黏连。用于大多数数据。

防黏连增强：用于相邻断层容易被错误合成大圈的场景。启用根系防黏连和局部桥防黏连，但必须保证覆盖率不明显下降。

快速预览：用于快速查看数据大致效果，减少平滑、诊断和复杂复核，适合大数据初步测试，不作为最终提交结果。

预设切换必须只调整参数，不改变算法代码路径。预设参数应记录到文档和模板文件中。

### 7.4 残余复核层

残余复核层不是正式多边形结果的一部分，而是质量复核提示层。它用于标记弱线性残余、端点微缺口、边界截断和局部包络不足。正式结果层保持闭合拓扑和稳定粒度，复核层用于说明弱残余已被检测和记录。

独立软件可以在结果导出中提供残余复核层文件。GeoEast 插件可以后续考虑把复核层写成单独对象或导出 GeoJSON，但不应把弱残余无脑并入正式多边形，避免破坏闭合和防黏连。

## 8. 性能规划

### 8.1 核心算法性能门禁

赛题要求核心处理部分 1 分钟内完成。项目内部应采用更高标准。

| 数据类型 | 目标 | 警戒线 | 失败线 |
| --- | ---: | ---: | ---: |
| 合成小数据 | 小于 100 ms | 500 ms | 1000 ms |
| 官方 test.dat | 小于 2 s | 5 s | 60 s |
| 大网格压力数据 | 小于 15 s | 30 s | 60 s |

每次算法改动后必须运行性能回归。若新增边界简化、平滑、复核或诊断导致耗时翻倍，必须分析根因：是重复遍历、栅格化低效、WKT 解析重复、图像生成慢，还是数据结构复制过多。不能只接受“功能多所以慢”。

### 8.2 UI 性能门禁

独立软件启动时间目标小于 3 秒。GeoEast 控件启动时间目标小于 3 秒。打开界面时不应同步执行耗时数据库扫描。刷新 BOMapGrid 可以由用户主动点击，运行时按钮状态要防止重复点击。

图像预览应避免每次参数变化都完整重绘大图。可采用缓存原始网格图、结果多边形图层和叠加图层的方式。缩放和平移应只改变视图变换，不重新运行算法。

### 8.3 内存门禁

核心算法应使用 RAII、连续容器和流式输出。大网格下避免无必要复制整张网格。诊断图、质量图和 UI 预览图要区分内存生命周期，窗口关闭后释放。

内存测试应记录峰值内存。若引入历史记录缩略图，应限制缩略图数量和尺寸，不把所有大图常驻内存。

## 13. 风险与应对

### 13.1 UI 再次耦合风险

风险：后续为了省事把 GeoEast 字段加回独立软件，或把独立软件历史记录加到 GeoEast 控件。

应对：所有需求先判断属于哪条线，跨线功能必须通过核心 CLI 或公共配置模型共享，不共享界面控件。

### 13.2 参数不一致风险

风险：界面显示一个参数，但命令行没有传；模板保存了旧参数；Runner 参数缺失。

应对：建立参数映射表和参数一致性测试，每次新增参数必须同时修改界面、模板、配置、CLI、Runner 和文档。

### 13.3 结果质量退化风险

风险：修复黏连导致覆盖率下降，提升覆盖率导致误合并增加。

应对：使用综合评分和多指标门禁，不允许只看单一指标。每次算法改动都保留旧结果对比。

### 13.4 发布包依赖风险

风险：换电脑后缺 Qt DLL、VC 运行库、平台插件或示例数据。

应对：打包脚本强制复制依赖，发布包测试在干净目录运行，安装器阶段增加依赖检测。

### 13.5 GeoEast 许可证和版本风险

风险：GeoEast 模块因 license 年份或版本不匹配无法打开。

应对：插件文档明确 license 检查方法，Runner 仍可独立测试数据库读写；最终截图必须在有效 license 环境中完成。

## 14. 需要用户参与的事项

以下事项必须在用户本机或 GeoEast 环境中确认。

1. GeoEast 主控按钮是否稳定显示。
2. GeoEast 平面成图或底图是否可打开。
3. 原始属性图和输出多边形叠加是否范围一致。
4. 颜色、线宽和图层显示是否符合演示需要。
5. 真实官方数据或老师指定数据是否能完整运行。
6. 最终用户手册中的截图是否与实际界面一致。

这些事项不是让用户承担开发工作，而是因为 GeoEast license、工区、数据库和显示模块属于本机环境，必须用真实环境验收。
