# 第5章 项目架构说明

## 5.1 总体架构

FaultPolyTrace 采用“算法核心 + 多入口应用 + GeoEast 适配 + 自动验收”的架构。核心算法负责把属性网格转换为闭合多边形；命令行程序提供自动化运行能力；独立软件提供面向普通用户的可视化操作；GeoEast 插件提供平台内数据库读写和菜单入口；脚本体系提供构建、打包、验收和质量诊断。

当前架构服务的主线场景是平面断层属性网格处理。系统可以对接外部 DAT/ASCII 文件和 GeoEast `BOMapGrid`，并输出 CSV、GeoJSON、诊断 JSON、图件证据或 GeoEast `BOFaultPolygon`。架构只围绕赛题要求和可交付能力展开：自动追踪、面积统计、交切和分支处理、独立运行、GeoEast 集成、外部文件与数据库读写、友好界面和 1 分钟内完成处理。

```text
外部 DAT/ASCII 文件 ─┐
                    ├─> 数据读写层 ─> 核心算法层 ─> CSV/JSON/图件
GeoEast BOMapGrid ──┘                        └─> BOFaultPolygon

独立软件 ───────┐
命令行程序 ─────┼─> 调用核心执行程序
GeoEast 启动器 ─┘
```

## 5.2 模块关系

`src/core/` 是项目中心。`src/io/` 把外部数据转换为统一网格结构。`src/app/main.cpp` 负责把命令行参数转为算法配置。独立软件和 GeoEast 启动器负责收集用户输入，再通过执行程序运行算法或 BO runner。BO runner 在 GeoEast 环境中把数据库对象转换为核心算法可处理的网格，并把结果写回 GeoEast。

## 5.3 数据流

外部文件模式的数据流为：选择输入文件、读取网格、执行追踪、输出 CSV 和诊断 JSON、在真实图层控件中显示原始网格与多边形结果。GeoEast 模式的数据流为：配置数据库、刷新网格列表、选择 `BOMapGrid`、BO runner 导出或读取网格、执行追踪、写入 `BOFaultPolygon`、在 GeoEast 或内置图层控件中查看结果。

## 5.4 架构边界

核心算法不负责窗口控件，也不负责 GeoEast 菜单。界面不直接改写算法内部结构，而是通过参数和执行程序调用。GeoEast 连接失败、license 失败、数据库对象不存在等问题应在 BO runner 或启动器层明确提示，不应表现为算法错误。

架构边界还包括赛题范围边界：当前核心算法只处理平面断层属性网格及等价 GeoEast 网格对象。与当前输入、输出、验收和用户操作无关的能力，不写入界面功能、不写入交付承诺，也不作为当前开发目标。

## 5.5 质量保障架构

项目把质量保障分为算法质量、拓扑质量、性能质量、界面质量、发布质量和现场证据。算法质量由官方 `test.dat` 验收、质量评估图和残余复核层证明；拓扑质量由开放环、自相交和异常相交诊断证明；性能质量由核心耗时和总耗时证明；界面质量由自动点击和截图检查证明；发布质量由发布包验收和客户机可移植性检查证明。
