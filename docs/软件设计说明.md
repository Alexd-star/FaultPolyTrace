# 软件设计说明

本文是 FaultPolyTrace 的软件设计说明，面向第十三届“东方杯”赛题 7 的正式提交、答辩和后续维护。

## 1. 总体架构

```text
CLI / Qt 启动器 / GeoEast 入口
        |
        v
FaultPolyTrace 核心算法库
        |
        +-- Grid2D 网格模型
        +-- 阈值分割
        +-- 形态学处理
        +-- 连通域分析
        +-- 骨架化和骨架图
        +-- 多边形追踪和统计
        +-- 面积过滤
        +-- 拓扑诊断
        |
        v
IO 适配器
        |
        +-- ASCII/DAT 文件读取
        +-- CSV/JSON 结果输出
        +-- GeoEast BOMapGrid 读取
        +-- GeoEast BOFaultPolygon 写入
```

核心算法库与 GeoEast SDK 解耦，便于独立测试和性能优化。GeoEast 相关代码集中在 `geoeast_plugin/bo_runner` 和适配器中。

## 2. 当前可执行程序

### 2.1 离线 CLI

`faultpolytrace.exe` 用于外部文件测试和批处理。常用参数：

- `--input`：ASCII 网格输入。
- `--output`：CSV 多边形输出。
- `--trace-mode`：`region` 或 `ridge-belt`。
- `--threshold-mode`：`fixed` 或 `percentile`。
- `--threshold`：固定阈值。
- `--percentile`：分位数阈值。
- `--min-area`：最小保留面积。
- `--simplify-tolerance`：多边形边界简化容差。
- `--smooth-iterations`：边界平滑次数。
- `--diagnostics`：运行诊断 JSON。

### 2.2 GeoEast Runner

GeoEast runner 用于数据库读写验证和 Qt 启动器调用。核心能力：

- 连接 GeoEast 数据库。
- 打开指定项目。
- 读取指定 `BOMapGrid`。
- 调用核心算法。
- 写入指定 `BOFaultPolygon`。

### 2.3 Qt 启动器

Qt 启动器提供友好界面：

- GeoEast 根目录和数据根目录配置。
- 数据库、项目、用户、密码配置。
- 输入网格刷新和选择。
- 输出多边形命名。
- 官方 DAT 导入。
- 算法参数设置。
- 运行日志显示。

### 2.4 GeoEast 主控插件

主控插件用于在 GeoEast Ribbon 中提供 `断层多边形追踪 -> 赛题7` 入口。插件本体保持轻量，只负责启动 Qt 启动器；数据库读写仍由 BO runner 完成，避免在主控进程中承载复杂算法和数据写入逻辑。

部署脚本：

```powershell
.\scripts\部署到GeoEast.ps1
```

部署目标：

```text
GeoEast-RC\bin\plugins\GeoAttribute\FaultPolyTraceMainframePlugin
GeoEast-RC\bin\faultpolytrace_launcher.exe
GeoEast-RC\bin\faultpolytrace_geoeast_runner.exe
```

## 3. 输出数据

### 3.1 CSV 输出

主要字段：

- `id`
- `status`
- `area`
- `perimeter`
- `cell_count`
- `mean_value`
- `max_value`
- `wkt`

`status` 取值：

- `kept`：保留。
- `filtered`：被面积阈值过滤。

### 3.2 JSON 诊断

诊断信息用于测试报告和答辩材料：

- 输入输出路径。
- 追踪模式。
- 阈值模式。
- 算法参数。
- 网格大小。
- 多边形数量。
- 开放环数量。
- 自相交数量。
- 多边形相交数量。
- 骨架统计。
- 耗时。
- 分段耗时：读入、追踪、拓扑诊断、写出。

### 3.3 GeoEast 输出

GeoEast 输出对象：

```text
BOFaultPolygon
```

推荐结果名：

```text
FaultPolyTrace_Result
```

结果可在 `Combined Fault Polygons` 的属性浏览器或 Basemap 中查看。

## 4. 设计原则

1. 算法核心保持确定性和可解释性。
2. GeoEast 读写与算法逻辑分离。
3. 默认参数要能稳定处理官方数据。
4. 所有重要参数和诊断结果都要可追溯。
5. 输出前必须检查闭合性和拓扑问题。
6. UI 以实际解释工作流为中心，不做无关装饰。

## 5. 性能设计

性能目标是显著优于赛题要求的 1 分钟。当前官方数据贴合融合推荐主线参数下，核心追踪耗时约 490 ms，总耗时约 1484 ms；在包含完整质量评估图生成的验收流程中，总体仍保持秒级。主要优化包括：

- 分位数阈值使用 `std::nth_element`，避免全量排序。
- 拓扑诊断增加多边形和线段包围盒剪枝，避免平滑后大量无效相交检测。
- GeoEast DAT 采用字符级快速解析和哈希索引，减少文本读入开销。
- CSV/WKT 写出采用流式输出，减少大字符串临时分配。
- 核心数据结构使用 `std::vector` 和 RAII，减少手工内存风险。

## 6. 质量验收设计

软件提供自动质量验收脚本：

```powershell
.\scripts\一键总验收.ps1
```

验收流水线包括：

1. 构建离线算法。
2. 运行合成数据烟测。
3. 使用官方数据运行推荐参数。
4. 生成白底质量评估图。
5. 生成漏检质控图。
6. 输出本次验收报告。
7. 构建和部署 GeoEast 组件。
8. 生成发布包。

当前官方数据综合质量指标：

```text
保留多边形数量: 204
强响应覆盖率: 约 99.5%
弱响应覆盖率: 约 96.6%
非零响应覆盖率: 约 94.1%
开放环: 0
自相交: 0
多边形异常相交: 0
核心追踪耗时: 约 490 ms
```
