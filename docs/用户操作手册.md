# FaultPolyTrace 用户操作手册

文档版本：V1.0  
适用软件：FaultPolyTrace 断层多边形自动追踪工具  
适用平台：Windows、GeoEast-RC、Qt 启动器、命令行运行环境  
文档对象：构造解释人员、地球物理解释人员、软件验收人员、竞赛评审人员、系统管理员

## 1. 文档说明

本手册用于指导用户安装、配置、运行和验证 FaultPolyTrace。文档按正式软件用户手册编写，内容覆盖产品概述、运行环境、数据准备、功能说明、操作步骤、参数说明、结果检查、故障处理和附录。

本手册参考的软件文档编制思路包括 GB/T 8567-2006《计算机软件文档编制规范》和 ISO/IEC/IEEE 26514 软件用户信息相关规范。文档面向最终用户，不包含开发协作过程、内部调试对话和个人操作分工。

## 2. 产品概述

FaultPolyTrace 是面向平面断层属性数据的断层多边形自动追踪工具。软件基于输入的二维断层属性网格，自动识别断层响应带，提取闭合断层多边形，并输出面积、周长、属性统计和拓扑诊断结果。

软件支持两类运行方式：

- GeoEast 集成运行：从 GeoEast 数据库读取 `BOMapGrid`，将结果写入 `BOFaultPolygon`，并可在 GeoEast 平面成图中叠加显示。
- 独立运行：读取外部 DAT、矩阵文本等网格文件，输出 CSV、WKT、诊断 JSON 和对比图。

软件设计目标：

- 自动追踪平面断层属性上的断层多边形。
- 生成闭合区域，满足断层多边形解释要求。
- 支持面积统计和面积阈值过滤。
- 合理处理断层交切、分叉、弱响应和局部断续。
- 提供可配置参数和多种预设，适应不同数据质量和地质场景。
- 提供 GeoEast 集成、外部文件运行、结果展示和质量检查能力。

## 2.1 软件入口与随包文档

正式发布包中的独立软件入口为发布包根目录的 `FaultPolyTrace.exe`。用户也可以双击 `01_打开图形界面.cmd` 打开相同的软件界面。独立软件不要求先启动 GeoEast，适用于外部文件读取、参数设置、结果查看、PNG 导出、历史记录和参数模板管理。

GeoEast 集成入口由部署脚本安装到 GeoEast 主界面菜单中。菜单按钮启动的是 `GeoEast-RC/bin/faultpolytrace_launcher.exe`，便携依赖和随包文档位于 `GeoEast-RC/bin/FaultPolyTraceLauncher/`。用户通常不需要手动进入该目录，只需要在 GeoEast 菜单中点击“断层多边形追踪”入口。

软件内部【帮助】菜单包含以下文档入口：

| 菜单项 | 作用 |
| --- | --- |
| 【帮助提示】 | 显示 5 到 10 分钟快速操作提示 |
| 【用户操作手册】 | 打开本文档，说明独立软件和 GeoEast 集成完整操作 |
| 【产品说明书】 | 打开企业级产品说明书，适合评审、培训和正式交付 |
| 【项目目录结构】 | 打开项目目录结构与文件作用说明，适合排查入口、源码、脚本和发布包位置 |

文档入口采用相对路径查找，不依赖开发者电脑上的固定目录。若软件提示“文档未找到”，请检查当前发布包或 GeoEast 便携启动器目录下是否存在 `docs` 目录；若缺失，请重新运行发布包打包脚本或 GeoEast 部署脚本。

FaultPolyTrace 的按钮和菜单均应在执行前检查必要条件。若用户提前点击某个操作，软件会通过弹窗、状态栏或日志给出提示：

| 操作 | 前置条件 | 未满足时的提示 |
| --- | --- | --- |
| 【开始追踪】外部文件模式 | 已选择可读取的输入文件，核心执行程序存在 | 提示选择输入文件或检查 `bin/faultpolytrace.exe` |
| 【开始追踪】GeoEast 数据库模式 | GeoEast 执行程序、根目录、数据根目录、数据库、项目、用户、输入网格和输出名称完整 | 弹窗列出缺失项，并提供【打开数据库配置】入口 |
| 【刷新网格】 | GeoEast 数据库配置完整 | 弹窗列出缺失项，引导进入数据库配置 |
| 【删除当前结果】 | GeoEast 数据库配置完整且输出多边形名称非空 | 先弹窗确认，避免误删 |
| 【查看叠加】 | 已生成或载入结果 CSV | 结果不存在时结果面板提示预计输出位置 |
| 【打开 CSV/GeoJSON/诊断 JSON】 | 对应结果文件已存在 | 文件不存在时弹窗提示 |
| 【打开用户操作手册/产品说明书】 | 发布包或便携启动器中存在 `docs` 目录 | 提示检查发布包文档目录或重新部署 |

## 2.3 数据目录与已有结果选择

独立软件和 GeoEast 集成插件均提供“已有结果”选择能力，用于复查历史结果、切换当前输出对象或清理旧结果。该功能的含义随数据源不同而不同：

| 数据源 | 输入对象列表 | 已有结果列表 | 典型用途 |
| --- | --- | --- | --- |
| 外部文件 | 用户通过【打开 DAT 文件】或【浏览】选择本地 DAT、CSV、矩阵文本等网格文件 | 软件扫描当前“输出目录”下的结果 CSV 文件 | 载入历史 CSV 结果、与当前原始网格叠加查看、打开 GeoJSON/诊断文件、导出 PNG |
| GeoEast 数据库 | 点击【刷新网格】后读取当前项目中的 `BOMapGrid` 对象 | 点击【刷新结果】后读取当前项目中的 `BOFaultPolygon` 对象 | 选择已有结果作为当前输出名、覆盖写入、删除旧结果、在 GeoEast 工区底图或平面成图中复核 |

选择外部输入文件后，若文件可读取，软件会自动载入原始网格并切换到原始网格视图。此时如果尚未运行追踪，结果区会明确提示“已载入原始网格，尚未运行追踪”，避免用户误以为当前画面已经是处理后的叠加结果。

选择 GeoEast 数据库源并保存数据库配置后，软件会自动刷新输入网格列表，并继续刷新已有结果列表。若网络、项目名或数据库配置不完整，软件会列出缺失项并引导用户进入数据库配置窗口。运行追踪成功后，结果会写入当前项目的 `BOFaultPolygon/<输出名称>`，日志和结果面板会同时显示数据库对象名以及本地视图缓存 CSV 路径。

输入网格或已有结果下拉框为空时，控件仍保持可点击。用户点击下拉箭头后，软件按以下顺序处理：

1. 检查执行程序、GeoEast 根目录、数据根目录、数据库、项目和用户名。
2. 配置不完整时，弹窗逐项列出缺失或无效内容，并提供【打开数据库配置】入口。
3. 配置完整但尚未读取目录时，自动刷新当前项目的 `BOMapGrid` 或 `BOFaultPolygon` 列表。
4. 数据库查询成功但项目中确实没有结果时，下拉框显示“当前项目暂无结果”，用户可再次点击进行刷新。
5. 独立软件处于外部文件模式且输出目录没有结果 CSV 时，软件提示先完成追踪或检查输出目录，不再显示无响应的空列表。

主窗口左侧参数区与右侧结果视图区之间设有可拖动分隔线。将鼠标移动到两区边界，光标变化后按住左键向左或向右拖动，即可调整参数区宽度。软件会保存最后一次调整的位置，并在下次启动时恢复。

为保证控件完整、美观和可读，左侧参数区设置了产品级宽度边界：最小宽度为 420 px，最大宽度为 760 px。拖到最小时，输入框、浏览按钮、颜色框、结果查看按钮和参数控件仍应完整显示；拖到最大时，右侧图像视图区仍保留足够空间。若旧配置文件中保存了过窄宽度，软件启动时会自动恢复到最小美观宽度。英文界面字段较长时，可适当向右拖宽参数区。

【颜色】输入框显示当前结果多边形颜色。颜色框不仅显示十六进制颜色值，也会显示对应背景色；当颜色较深时自动使用白色文字，颜色较浅时自动使用黑色文字。点击右侧【颜色】按钮可重新选择颜色，新的颜色会用于结果多边形显示、PNG 导出和运行参数。

选择历史 `BOFaultPolygon` 对象后，软件会调用 GeoEast 执行程序把该对象导出为本地 CSV 视图文件，并自动载入结果视图区。若同时选择了对应原始网格，可进行叠加查看；若只选择历史结果，则可单独查看结果多边形。正式复核仍建议在 GeoEast 自带【工区底图】或【平面成图】中完成，因为官方图层树能够显示真实数据库对象、样式和工程坐标上下文。

## 3. 适用范围

FaultPolyTrace 不依赖某一个固定样例数据。凡是能够表达为规则二维网格的平面断层属性数据，均可作为输入。

典型适用数据：

- 沿层断层属性。
- 断层概率属性。
- 相干、曲率、蚂蚁体、边缘增强等断裂响应属性。
- AI 或传统算法生成的平面断层概率图。
- GeoEast `BOMapGrid` 网格对象。
- 外部 DAT 或规则矩阵文本。

推荐数据条件：

- 网格坐标、行列号或采样间隔完整。
- 高属性值代表断层、断裂或断层带可能性更高。
- 数据允许存在噪声、断续、交切、弱响应和局部缺失。
- 断层响应具有一定线性、带状或脊线特征。

不推荐直接输入的数据：

- 无空间坐标或采样间隔信息的非规则散点。
- 高值和低值含义不确定的属性。
- 与断层无明显相关性的随机噪声图。
- 未经投影或坐标校正、空间位置明显错误的数据。

## 4. 术语说明

| 术语 | 含义 |
| --- | --- |
| 平面断层属性 | 表示断层或断裂可能性的二维属性网格 |
| 断层多边形 | 围绕断层响应带形成的闭合区域 |
| 闭合区域 | 多边形首尾闭合，可计算面积 |
| Ridge-Belt | 先提取断层脊线，再扩展成断层带多边形的追踪模式 |
| 分位数阈值 | 按属性值排序自动确定阈值，例如 0.98 表示提取最高 2% 响应 |
| 弱响应延拓 | 在强响应附近吸收弱但连续的属性，以减少漏识别 |
| 残余复核层 | 对未进入正式多边形层的弱线性残余、边界截断或局部端点缺口生成的质控提示层，不等同于正式结果错误 |
| 面积过滤 | 按用户设定的最小面积过滤小噪声多边形 |
| 拓扑诊断 | 检查开环、自交、多边形相交等几何问题 |

## 6. 安装与部署

### 6.1 自动部署

在项目根目录打开 PowerShell，执行：

```powershell
.\scripts\部署到GeoEast.ps1
```

部署脚本会完成以下操作：

- 构建 GeoEast Runner。
- 构建 Qt 启动器。
- 构建或更新主控插件。
- 生成产品图标。
- 复制可执行文件、图标和插件到 GeoEast 目录。

部署完成后，重新启动 GeoEast。

### 6.2 手动启动

未通过 GeoEast 菜单启动时，可直接运行：

```text
<GeoEast安装根目录>\GeoEast-RC\bin\faultpolytrace_launcher.exe
```

也可在项目目录中运行开发版启动器：

```powershell
.\geoeast_plugin\qt_launcher\faultpolytrace_launcher.exe
```

### 6.3 GeoEast 菜单入口

GeoEast 重启后，在主界面功能区查找：

```text
断层多边形追踪
```

点击后应弹出 FaultPolyTrace Qt 启动器。若入口未显示，可通过 GeoEast 菜单定制功能添加外部程序入口，程序路径选择 `faultpolytrace_launcher.exe`。

菜单图标推荐选择：

```text
<GeoEast安装根目录>\GeoEast-RC\bin\faultpolytrace.ico
```

```text
<GeoEast安装根目录>\GeoEast-RC\bin\faultpolytrace.png
```

## 7. 数据准备

### 7.1 GeoEast 数据库输入

GeoEast 集成运行时，输入数据应为目标项目中的 `BOMapGrid` 网格对象。

示例配置：

```text
数据库: ndp
项目: <目标项目名>
用户: <GeoEast用户名>
密码: 空
输入网格: <BOMapGrid名称>
输出多边形: FaultPolyTrace_Result
```

正式使用时，数据库、项目、用户、输入对象和输出对象应按实际项目填写。

### 7.2 外部文件输入

独立运行支持外部文件输入。典型文件：

```text
DAT 文件: 每行包含行号、道号、X、Y、属性值
矩阵文件: 规则二维数值矩阵
```

外部 DAT 可通过启动器导入 GeoEast，也可通过命令行直接处理。

### 7.3 官方 DAT 手工导入 GeoEast

赛题 7 官方 `test.dat` 是采样点列表，列含义为 `Line`、`CMP`、`X`、`Y`、`Value`。该文件不能在 GeoEast `Import Grid` 中按普通网格文件直接导入，否则 GeoEast 可能把 `Line=800` 或 `CMP=300` 误识别为网格坐标、网格数量或采样间隔。

如需使用 GeoEast 官方 `Import Grid` 手工导入，应先使用 FaultPolyTrace 提供的转换脚本生成标准网格 ASCII：

```powershell
python <项目根目录>\FaultPolyTrace\scripts\转换官方DAT为GeoEast标准网格ASCII.py `
  --input <官方test.dat路径> `
  --output <项目根目录>\FaultPolyTrace\examples\outputs\geoeast_ascii_import_YYYYMMDD_HHMMSS\test7_fault_attribute_geoeast_grid_ascii.txt `
  --grid-name test7_fault_attribute_ascii
```

脚本会同时生成 `*.导入说明.md`，其中列出 GeoEast `Header Item`、`Body Item` 和 `DataBody Start` 的配置值。导入完成后应确认网格属性为：

```text
Minimum X: 622993.9
Minimum Y: 4334420.1
X Grid Number: 1501
Y Grid Number: 701
X/Y Grid Spacing: 10
```

### 7.4 数据命名建议

建议按数据来源、参数方案和版本命名结果对象：

```text
FaultPolyTrace_Result_Balanced
FaultPolyTrace_Result_Conservative
FaultPolyTrace_Result_Recall
FaultPolyTrace_Result_WideBelt
FaultPolyTrace_Result_v01
```

不建议反复覆盖同名结果，正式验收前应保留不同参数方案的对比对象。

用于选择输入网格和输出多边形对象。

| 字段 | 说明 |
| --- | --- |

### 8.2.1 结果查看

GeoEast 插件提供独立的 `结果查看` 分组，用于管理输出对象、查看 runner 导出的真实图层缓存，并打开 GeoEast 官方成图窗口。该分组不再把删除、显示和数据选择混在同一行，也不使用固定示意图代替真实结果。

| 功能 | 说明 |
| --- | --- |
| 显示原始网格层 | 控制本窗口真实图层视图区是否显示 runner 导出的原始网格 |
| 显示结果多边形层 | 控制本窗口真实图层视图区是否显示 runner 导出的保留断层多边形 |
| 载入真实视图 | 读取最近一次追踪生成的网格缓存和多边形 CSV 缓存 |
| 导出 PNG | 将当前真实图层视图区导出为 PNG 图片 |
| 打开工区底图 | 启动 GeoEast 自带 GeoBasemap，在官方图层树中查看数据库对象 |
| 打开平面成图 | 启动 GeoEast 自带 GeoMapping，在官方图层树中查看数据库对象 |
| 查看步骤 | 打开 GeoEast 平面成图叠加查看指南 |
| 删除当前结果 | 删除当前 `输出多边形` 名称对应的 `BOFaultPolygon` 结果对象 |

注意：插件本窗口显示的是 runner 实际导出的原始网格和结果多边形缓存，适合快速核对追踪结果是否生成、颜色是否清楚、输出对象是否正确。GeoEast 官方窗口中的显示或关闭仍由 GeoBasemap 或 GeoMapping 的图层树控制，应在官方图层树中手动勾选或取消勾选 `Grids` 与 `Fault Polygons` 对象。

删除当前结果属于高风险操作。点击 `删除当前结果` 后，软件会弹出二次确认窗口。确认后仅删除当前项目中与 `输出多边形` 同名的 `BOFaultPolygon` 对象，不删除输入网格，也不删除其它解释对象。

### 8.3 追踪参数

用于选择参数预设和修改算法参数。启动器提供多种预设，适用于不同数据质量和解释目标。

| 预设 | 适用场景 | 特点 |
| --- | --- | --- |
| 贴合融合推荐 | 官方数据、细长断层带、正式自动交付 | 使用属性约束断层带、弱响应延拓和多外环追踪，残余二次追踪默认关闭，兼顾连续性与防误合并 |
| 防黏连增强 | 近邻断层疑似被错误连成一片，且默认结果覆盖率已经较高 | 在贴合融合推荐基础上启用根系防黏连，并采用切后验收和自动回退，优先切除低属性背景桥 |
| 均衡推荐 | 常规断层属性、一般解释场景、比赛演示 | 准确性、连续性和拓扑稳定性平衡 |
| 保守高精度 | 强响应清楚、噪声较多、误识别风险较高 | 高阈值、强剪枝，结果更干净 |
| 弱响应高召回 | 断层连续但强弱变化明显，存在漏识别风险 | 放宽残余二次追踪，优先补全弱段，适合作为人工复核方案 |
| 宽断层带 | 断层属性呈宽带状或边界较厚 | 加大闭运算和带宽半径 |
| 细碎断裂 | 小断裂多、分支短、面积小 | 保留更多短分支和小多边形 |

### 8.4 日志区


## 9. 参数说明

| 参数 | 推荐范围 | 作用 |
| --- | --- | --- |
| 追踪模式 | ridge-belt / region | `ridge-belt` 适合线状断层属性，`region` 适合块状区域 |
| 阈值模式 | percentile / fixed | `percentile` 适合不同数据自动归一，`fixed` 适合已标准化属性 |
| 分位数 | 0.95-0.99 | 控制强响应提取比例，值越高越保守 |
| 固定阈值 | 0-1 或按属性值范围 | 固定阈值模式下使用 |
| 最小面积 | 按项目比例设置 | 过滤小噪声多边形 |
| 闭运算半径 | 0-3 | 填补小断口，连接近邻响应 |
| 弱延拓分位 | 0 或 0.93-0.97 | 在强响应附近吸收弱连续响应 |
| 弱延拓半径 | 0-3 | 控制弱响应延拓范围 |
| 最大弱连通域 | 5000-20000 | 限制弱延拓吸收的大面积弱背景 |
| 弱连通域长宽比 | 3-6 | 只保留更像线状断层的弱响应连通域 |
| 带宽半径 | 1-4 | 控制断层带多边形宽度 |
| 带后闭合 | 0-2 | 在断层带成形后填补小缺口，减少串珠状分段 |
| 属性约束断层带 | 开/关 | 用原始属性包络约束骨架缓冲区，使边界更贴近原始断层响应 |
| 属性包络半径 | 0-3 | 控制原始属性带允许向外扩展的范围 |
| 最短分支 | 3-8 | 剪除短毛刺和孤立分支 |
| 最大断距 | 6-16 | 控制端点自动连接距离 |
| 最大夹角 | 35-65 | 控制端点连接方向一致性 |
| 根系防黏连 | 开/关 | 识别不同断层主干之间的低属性桥接，防止近邻断层误合并 |
| 防黏连支撑 | 0.20-0.98 | 推荐从 0.25 开始；数值越高切分越激进，可能把结果拆碎；正式默认关闭该功能 |
| 最小主体 | 自动或按像元设置 | 切开后每个主体至少需要达到的像元数，0 表示自动 |
| 主体比例 | 0.08-0.20 | 切开后每个主体相对于原连通体的最小比例，用于避免把连续断层切成小碎片 |
| 简化容差 | 0-8 | 减少边界顶点并保持形态 |
| 平滑次数 | 0-2 | 平滑多边形边界 |

## 10. GeoEast 集成运行流程

### 10.1 打开启动器

1. 启动 GeoEast。
2. 打开目标数据库和项目。
3. 点击 `断层多边形追踪` 菜单入口。
4. 确认 FaultPolyTrace 启动器正常打开。

### 10.2 刷新输入网格

1. 检查 GeoEast 根目录、数据根目录、数据库、项目和用户。
2. 点击 `刷新网格`。
3. 在输入网格下拉框中选择目标 `BOMapGrid`。
4. 若列表为空，检查项目中是否存在网格对象，或使用外部 DAT 导入。

### 10.3 设置输出对象

在 `输出多边形` 中输入结果对象名。推荐不同参数方案使用不同名称。

示例：

```text
FaultPolyTrace_Result_Balanced
```

### 10.4 选择参数预设

首次运行推荐选择 `贴合融合推荐`。该预设是正式主交付模式，适合作为默认输出。若结果需要优化，可按以下原则切换：

- 漏识别明显：选择 `弱响应高召回`，并将其作为复核结果与默认结果叠加比较。
- 近邻断层被连成大圈：选择 `防黏连增强`，并重点检查日志中的根系防黏连候选切分、接受切分和回退切分数量。
- 噪声多、误识别多：选择 `保守高精度`。
- 断层带太窄：选择 `宽断层带`。
- 小断裂丢失：选择 `细碎断裂`。

参数区中的 `残余二次追踪` 是高级复核开关。正式主交付模式默认关闭，只保留弱响应延拓和属性约束断层带；高召回或全覆盖复核时可开启，并通过 `补追最短` 和 `补追上限` 控制补追强度。数值越放宽，越容易捕捉细弱断层，但也越需要检查是否出现误合并和碎片化。

参数区中的 `根系防黏连` 也是高级增强开关。它不是简单按距离把相邻断层拆开，而是先判断候选桥接是否缺少属性支撑，再检查切开后是否形成两个足够大的主体。如果切开后只得到一个大主体加很小碎片，程序会自动回退该切分。正式默认仍推荐 `贴合融合推荐`；只有当叠合图中明确看到相邻不同脉络被连成一片时，才建议使用 `防黏连增强` 生成对照结果。

### 10.5 开始追踪

1. 点击 `开始追踪`。
2. 等待日志输出完成信息。
3. 检查拓扑诊断结果。
4. 确认输出对象已写入 GeoEast 数据库。

成功日志示例：

```text
FaultPolyTrace GeoEast runner completed.
Grid: 1501 x 701
Effective threshold: 0.95
Polygons: 204 total, 204 kept
Suppressed internal rings: 5
Topology open rings: 0
Topology self-intersections: 0
Topology polygon intersections: 0
Output BOFaultPolygon: FaultPolyTrace_Result_Balanced
Elapsed: 约 1-3 秒级
```

使用官方测试数据和 `贴合融合推荐` 参数时，最新离线验收结果为：

```text
Grid: 1501 x 701
Polygons: 232 total, 214 kept
Topology open rings: 0
Topology self-intersections: 0
Topology polygon intersections: 0
Core trace time: 约 574 ms
Elapsed time: 约 1433 ms
Strong coverage: 约 99.846%
Weak coverage: 约 97.149%
```

正式主线要求 `Topology polygon intersections` 为 0。若该数值大于 0，应结合叠加图检查是否存在误合并、局部交切处理异常或过度补追。历史高召回复核实验中曾出现数千个小多边形和较多接触诊断记录，这类结果只用于弱响应复核，不作为默认交付。

### 10.6 删除旧结果对象

当同一个输出名已经生成过结果，而本次不再需要该对象时，可在 GeoEast 插件中删除。

操作步骤如下：

1. 在 `输出多边形` 中填写要删除的结果对象名。
2. 确认当前项目为目标项目。
3. 点击 `结果查看` 分组中的 `删除当前结果`。
4. 阅读确认窗口，确认对象名无误。
5. 点击 `Yes` 或 `是`。
6. 等待日志显示删除完成。
7. 回到 GeoEast 数据浏览或数据集管理器刷新对象列表。

删除完成后，如果 GeoEast 平面成图中已经加载了该图层，应在图层树中移除或刷新该图层。若不刷新，画面中可能仍保留旧的显示缓存。

### 10.7 显示或关闭原始网格与结果图层

GeoEast 插件本身不直接接管 GeoBasemap 或 GeoMapping 的官方图层树。本窗口的 `显示原始网格层` 和 `显示结果多边形层` 控制的是 runner 导出的真实图层缓存，用于快速查看本次追踪产生的实际网格与多边形。GeoEast 官方显示应在 GeoEast 平面成图或工区底图窗口中完成。

推荐操作步骤如下：

1. 在 GeoEast 中打开 GeoBasemap 或 GeoMapping。
2. 在图层树中加载输入 `BOMapGrid` 原始网格。
3. 在图层树中加载输出 `BOFaultPolygon` 结果对象。
4. 勾选原始网格图层，查看原始断层属性。
5. 勾选结果多边形图层，查看追踪结果。
6. 同时勾选两个图层，查看叠加效果。
7. 取消勾选原始网格图层，仅查看结果多边形。
8. 取消勾选结果多边形图层，仅查看原始网格。
9. 如颜色不清楚，在结果多边形图层属性中调整线色、线宽或透明度。

建议正式验收截图至少包含三张：原始网格单独显示、结果多边形单独显示、原始网格与结果多边形叠加显示。

### 11.3 独立软件结果查看

独立桌面软件运行完成后，不需要再到 GeoEast 平面成图中查看结果。软件会在当前窗口内完成“原始网格、结果多边形、叠加结果”的显示，并在左侧提供结果文件入口。

标准操作流程如下：

1. 双击发布包根目录的 `FaultPolyTrace.exe`。
2. 在左侧【数据与输出】中选择输入文件，确认“输入格式”“输出目录”和“输出名称”。首次打开软件时，“输入文件”为空，不会自动选中随包测试文件，用户应主动选择本次需要处理的数据。
3. 在左侧【追踪参数】中选择预设模板。首次使用建议选择【防黏连增强】。
4. 点击【开始追踪】。
5. 等待底部状态栏显示耗时，例如 `耗时: 1384 ms (1.4 s)`。
6. 运行成功后，中央视图区会自动切换到【叠加结果】。
7. 如需只看原始属性图，在“视图内容”中选择【原始网格】。
8. 如需只看多边形边界，在“视图内容”中选择【结果多边形】。
9. 如需复核贴合效果，在“视图内容”中选择【叠加结果】。
10. 在左侧【结果查看】中点击【打开CSV】查看多边形属性表。
11. 点击【GeoJSON】查看或交给 GIS 软件读取结果边界。
12. 点击【诊断JSON】查看参数、耗时、拓扑和质量诊断。
13. 点击【输出目录】打开所有结果文件所在文件夹。
14. 点击【导出PNG】保存当前视图区图像。

独立软件默认输出目录为：

```text
%USERPROFILE%\Documents\FaultPolyTraceOutputs
```

每次运行至少会生成以下文件：

```text
FaultPolyTrace_Result.csv
FaultPolyTrace_Result.geojson
FaultPolyTrace_Result.diagnostics.json
FaultPolyTrace_Result.branches.csv
FaultPolyTrace_Result.topology.csv
```

如果运行结束后没有生成 CSV，软件不会把任务标记为完成，而会在日志和左侧【结果查看】中提示“运行结束但未找到结果 CSV”。此时应优先检查输入文件格式、输出目录写入权限、输出名称是否合法，以及日志中核心算法程序给出的错误信息。

在只选择输入文件但尚未点击【开始追踪】时，中央视图区只表示“原始网格已载入”，左侧【结果查看】会提示“已载入原始网格，尚未运行追踪；当前不是处理后的叠加结果”。此时【查看叠加】、【打开CSV】、【GeoJSON】和【诊断JSON】不会被当作已有结果使用。只有本次追踪成功完成，或用户从【历史记录】载入已有结果后，软件才会启用这些结果查看入口。

【恢复默认参数】用于恢复推荐的算法参数和显示参数，包括预设模板、阈值模式、分位数、面积阈值、平滑、简化、防黏连、颜色、线宽和透明度等。该操作不会修改“输入文件”“输出目录”“输出名称”和 GeoEast 数据库连接配置，也不会删除已经生成的结果文件。若需要更换输入数据，应使用【打开 DAT 文件】或“输入文件”右侧的【浏览】按钮；若需要更改输出位置，应在“输出目录”中单独设置。

### 11.4 独立软件连接 GeoEast 数据库

独立桌面软件也提供可选的 GeoEast 数据库数据源模式，用于满足“独立运行的软件既能处理外部文件，也能在配置正确时读写 GeoEast 数据库”的交付要求。该模式不是 GeoEast 插件窗口的简单复制，而是作为独立软件中的一种数据源切换存在。默认仍为【外部文件】，只有当用户将“数据源”切换为【GeoEast数据库】时，界面才显示输入网格下拉框、【刷新网格】、【数据库配置】和【删除结果】等数据库相关入口。

标准操作流程如下：

1. 双击发布包根目录的 `FaultPolyTrace.exe`。
2. 在左侧【数据与输出】中将“数据源”切换为【GeoEast数据库】。
3. 点击【数据库配置】。
4. 在弹窗中点击【自动检测】，软件会尝试识别执行程序、GeoEast 根目录、GeoEastData 数据根目录、数据库名、PG 主机端口和用户名。
5. 检查“项目”字段。项目名不能由软件安全猜测，应以 GeoEast 当前打开的项目为准。
6. 点击【检查配置】。若弹窗提示缺失项，应先返回补齐。
7. 点击【应用并保存配置】。
8. 点击【刷新网格】读取当前项目中的 `BOMapGrid` 列表。
9. 在“输入网格”中选择目标平面断层属性网格。
10. 在“输出名称”中填写要写入的 `BOFaultPolygon` 对象名。
11. 设置追踪参数、颜色、线宽和面积阈值。
12. 点击【开始追踪】。
13. 运行完成后，结果会写入 GeoEast 数据库，同时在本软件输出目录生成真实网格缓存、结果 CSV、GeoJSON 和诊断文件。
14. 中央视图区会切换到【叠加结果】，用于快速查看真实原始网格和真实结果多边形。

数据库配置项来源如下表所示。正式交付时，不要求用户知道内部环境变量或命令行参数，只需要按表中来源确认即可。

| 配置项 | 推荐获取方式 | 是否可自动检测 | 说明 |
|---|---|---:|---|
| 执行程序 | 发布包或 GeoEast 部署目录中的 `faultpolytrace_geoeast_runner.exe` | 是 | 用于调用 GeoEast BO 数据读写。若不存在，应重新部署插件或发布包。 |
| GeoEast 根目录 | 包含 `NGP` 和 `GeoEast-RC` 两个子目录的安装根目录 | 是 | 例如安装目录 `GeoEast`，不要误选 `GeoEast-RC` 或 `NGP` 的内部子目录。 |
| GeoEast 数据根目录 | `GeoEastData` 根目录，通常包含 `pgdata` 和 `DATA` | 是 | 手动选择时应选择数据根目录本身，不要只选到某个项目或某个数据库子目录。 |
| PG 主机 | 本机通常为 `127.0.0.1` | 是 | 远端数据库由管理员提供主机地址。 |
| 端口 | 本机通常为 `5433` | 是 | 如果 GeoEast 数据库端口被修改，应以管理员配置为准。 |
| 数据库 | 通常为 `ndp` | 是 | 软件会优先从环境变量或 `pgdata` 目录识别。 |
| 项目 | GeoEast 主控标题、打开项目窗口或项目管理工具中的项目名 | 否 | 该项必须与要处理的 GeoEast 项目一致，否则刷新网格列表会失败或为空。 |
| 用户 | GeoEast 登录用户名，通常与 Windows 用户名一致 | 是 | 若 GeoEast 使用专门用户，应填写 GeoEast 用户名。 |
| 密码 | GeoEast 数据库或项目用户密码 | 否 | 无密码环境可留空；若数据库要求密码，应由管理员提供。 |

GeoEast 数据库模式会在运行前自动配置 `NGP`、`IECO`、`NDPDIR`、`NGPDIR`、`GEOEAST`、`PG_HOME`、`NGP_DBDATA_PATH`、`NGPDATA` 和 `PATH`，并根据界面填写的主机和端口写入 `hostname.pg`。如果刷新网格失败，应优先检查 GeoEast 根目录、数据根目录、数据库名、项目名、用户名和 license 是否正确。

【删除结果】用于删除当前“输出名称”对应的 GeoEast `BOFaultPolygon` 对象。该操作会弹出二次确认窗口，只删除结果多边形对象，不删除输入网格，也不删除本地输出文件。

### 11.5 大数据真实图层查看说明

官方 `test.dat` 大约 82 MB，包含 `1501 x 701` 个采样点。旧版本界面曾在主线程中一次性读取整个文件并拆成字符串列表，容易造成窗口假死或崩溃。当前版本已改为流式读取：先识别数据格式，再按行扫描 Line/CMP/X/Y/Value，按与核心算法一致的坐标方向构造真实网格，并缓存原始属性色图。缩放、平移和图层开关只重绘缓存图层，不重新解析 82 MB 文件。

因此，独立软件中间视图区显示的内容不再是固定示意图，而是来自真实输入文件、真实 GeoEast 网格缓存或真实结果 CSV/WKT。若用户只想查看原始响应，可选择【原始网格】；若只想查看闭合多边形，可选择【结果多边形】；若要检查贴合程度，应选择【叠加结果】并根据需要勾选或取消【显示原始网格层】、【显示结果多边形层】。

## 13. 结果质量检查

结果验收不应只看多边形数量，应综合检查以下指标。

### 13.0 自动质量验收

产品提供自动质量验收脚本，适合正式提交前复查：

```powershell
.\scripts\一键总验收.ps1 -SkipGeoEastBuild -SkipPackage
```

该命令会自动生成：

```text
多边形 CSV
运行诊断 JSON
拓扑明细 CSV
骨架分支 CSV
白底官方风格质量图
漏检质控图
本次验收报告
```

输出目录采用时间戳命名，便于复查和归档。

### 13.1 几何闭合性

日志中应满足：

```text
Topology open rings: 0
```

若存在开环，应降低边界简化强度或检查输入数据是否存在异常空洞。

### 13.2 拓扑稳定性

推荐满足：

```text
Topology self-intersections: 0
```

`Topology polygon intersections` 是多边形接触、交切和近邻相交的质控记录，断层交切场景下不要求为 0。若该数值明显高于同类数据的历史结果，或叠加图中出现大范围异常闭合圈，应降低最大断距、降低带宽半径、收紧补追参数或提高面积过滤阈值。

### 13.3 覆盖性

主要强响应断层带应被多边形覆盖。若明显漏识别：

- 使用 `弱响应高召回`。
- 降低分位数阈值。
- 降低最短分支。
- 提高最大断距和最大夹角。
- 检查色标是否导致视觉误判。

### 13.4 连续性

同一条连续断层不应被过度切碎。若分段过多：

- 提高最大断距。
- 提高最大夹角。
- 降低最短分支。
- 适当启用弱响应延拓。

若不同断层被误连：

- 降低最大断距。
- 降低最大夹角。
- 关闭弱响应延拓。
- 降低带后闭合。
- 使用 `保守高精度`。

### 13.5 边界贴合度

边界应自然贴合断层属性带。需要注意：断层多边形是闭合区域，不是中心线。只画多边形边界时，边界会位于断层响应线两侧，视觉上可能出现“红线和黑线之间有空隙”。因此正式检查应同时查看：

- 边界叠加图：检查多边形轮廓是否顺着断层走向。
- 半透明填充图：检查闭合多边形区域是否覆盖原始断层响应。

若填充区覆盖断层响应，但边界看起来在两侧，这是正常的闭合多边形表达。若填充区也没有覆盖断层响应，则属于漏识别或坐标错位，应重新检查输入坐标、阈值和弱延拓参数。

若多边形过窄，增加带宽半径或属性包络半径；若多边形过宽，降低带宽半径、开启属性约束断层带或提高分位数。

### 13.6 面积过滤

小噪声多边形过多时，提高最小面积；小断层丢失时，降低最小面积。

### 13.7 性能

赛题要求核心处理部分 1 分钟内完成。官方规模数据通常为 1 秒级，GeoEast 数据库读写耗时受数据库状态、磁盘和环境影响。

## 14. 常见问题与处理

### 14.1 启动器无法打开

检查：

- `faultpolytrace_launcher.exe` 是否存在。
- Qt 运行库是否与启动器构建版本一致。若提示“无法定位程序输入点”，通常是启动器目录中混入了旧版 `Qt5*.dll`，应使用 GeoEast 自带 Qt 5.15.2 的 `windeployqt` 重新部署。
- GeoEast 根目录是否正确。

### 14.2 刷新网格失败

检查：

- 数据库名称是否正确。
- 项目名称是否正确。
- 用户名和密码是否正确。
- PG 主机和端口是否正确。
- GeoEast 数据根目录是否正确。
- `hostname.pg` 是否存在或能由启动器自动生成。

### 14.3 找不到输入网格

处理方法：

- 在 GeoEast 数据浏览中确认 `成图 -> 网格 -> <All>` 是否存在目标对象。
- 使用 `刷新网格` 重新读取对象列表。
- 使用外部 DAT 导入生成 `BOMapGrid`。
- 检查对象名是否输入错误。

### 14.4 结果对象不存在

检查：

- 日志中是否显示写库成功。
- 输出对象名是否与查看对象名一致。
- 是否写入了正确项目。
- 是否因权限或重名对象导致写入失败。

### 14.5 平面成图无法打开

若出现 GeoMapping license 提示，应检查：

- license 文件是否与当前 GeoEast 版本匹配。
- license 年份是否有效。
- license 是否放在 GeoEast 要求目录。
- GeoEast 是否已重启。

该问题属于 GeoEast 模块授权问题，不代表 FaultPolyTrace 算法或写库失败。

### 14.6 结果看起来断断续续

首先确认显示对象是多边形边界，不是中心线。细长闭合多边形在全图显示时可能呈现分段边界效果。

若确认主要断层响应未被覆盖，可按以下顺序调整：

1. 切换 `弱响应高召回`。
2. 将分位数从 0.98 降至 0.975 或 0.97。
3. 将最大断距适当提高。
4. 将最短分支降低。
5. 检查弱延拓是否引入大面积弱背景，必要时提高弱连通域长宽比或降低最大弱连通域。
6. 放大局部检查是否存在交切或真实断裂中断。

### 14.7 噪声多边形过多

处理方法：

- 切换 `保守高精度`。
- 提高分位数。
- 提高最小面积。
- 提高最短分支。
- 降低弱延拓半径或关闭弱延拓。

### 14.8 GeoEast 中原始网格显示成巨大版面

如果手动导入官方 `test.dat` 后，工区底图中显示为巨大版面，而结果多边形只占很小一点，应优先核对该网格对象的头信息。

使用官方赛题数据验收时，正确输入网格应为由官方 `test.dat` 按标准网格方式生成或由 FaultPolyTrace 导入生成的 `BOMapGrid`。其典型头信息为：

```text
X Minimum: 622993.9
Y Minimum: 4334420.1
X GridNum: 1501
Y GridNum: 701
Space: 10
```

如果手动导入对象显示：

```text
X Minimum: 800
Y Minimum: 800
X GridNum: 800
Y GridNum: 800
Space: 800
```

说明 GeoEast ASCII 导入格式解释错误。此类对象不应作为追踪输入，也不应用于叠合评价。详细说明见 `docs\GeoEast网格导入与显示问题说明.md`。

处理方法：

1. 在平面成图中隐藏或移除错误导入的网格对象。
2. 使用正确导入的官方原始网格对象作为原始网格图层。
3. 使用 `FaultPolyTrace_Result_Check` 或本次输出对象作为断层多边形图层。
4. 执行 `Refresh All` 或重新打开平面成图。
5. 如需重新导入官方 DAT，优先在 FaultPolyTrace 启动器中使用 `从官方 DAT 导入/覆盖输入网格`。
6. 如需坚持使用 GeoEast 官方 `Import Grid`，先按第 7.3 节转换为标准网格 ASCII，再按生成的导入说明配置格式映射。

## 18. 正式结果层与残余复核层

从当前版本开始，FaultPolyTrace 的推荐交付不再只看一个结果文件，而是分为两个层级：

1. **正式结果层**：即 `result.csv` 或写入 GeoEast 的断层多边形对象。该层必须满足闭合、多边形面积可统计、可按面积阈值过滤、拓扑合法、可进入 GeoEast 平面成图叠合显示等要求。正式层用于提交、展示、统计和数据库入库。
2. **残余复核层**：即 `残余复核层.csv` / `残余复核层.geojson` / `残余复核层总览.png`。该层只提示未并入正式层的少量弱线性残余、边界截断、端点微缺口或局部包络不足，不会改变正式多边形结果。

这样设计的原因是：真实生产中不能为了追求“看起来覆盖所有细线”而把所有弱碎片都写进正式结果，否则会导致几千个串珠状小多边形，影响解释人员使用，也容易制造误合并。正确做法是让正式层保持干净稳定，让复核层承担“提示哪里值得再看一眼”的作用。

### 18.1 生成残余复核层

离线生成示例：

```powershell
python .\scripts\生成残余复核层.py `
  --dat "<官方test.dat路径>" `
  --csv ".\examples\outputs\quality_compare\compare_20260523_054601\02_root_antimerge\result.csv" `
  --out-dir ".\examples\outputs\quality_compare\compare_20260523_054601\02_root_antimerge\残余复核层"
```

输出文件包括：

- `残余复核层.csv`：表格化复核候选，包含候选类型、根因、优先级、像元数量、最大值、均值、形态比、附近多边形编号、处理建议和 `LINESTRING`。
- `残余复核层.geojson`：标准 GeoJSON 线对象，可供后续 GIS 或可视化工具读取。
- `残余复核层总览.png`：白底图，左侧为正式结果层，右侧叠加彩色复核线。
- `局部复核图`：逐个候选的局部放大图。
- `残余复核层报告.md`：中文报告，说明候选数量、根因统计和使用原则。

### 18.2 如何判断复核层候选

复核层候选不是错误清单，而是质控提示。常见类型如下：

| 类型 | 含义 | 处理建议 |
|---|---|---|
| 数据边界截断 | 响应贴近数据边界，可能只显示了一部分 | 默认不外推，除非有外部解释依据 |
| 弱线性残余响应 | 属性值较弱但呈线性，未进入正式层 | 保留为复核提示，不默认写入正式多边形 |
| 断层端点轻微未包络 | 离正式多边形很近的端点小缺口 | 可用受控端点微补处理 |
| 主断层附近局部包络不足 | 主断层旁少量弱响应未覆盖 | 可局部补包络，补后必须检查拓扑和黏连 |

在 GeoEast 中查看时，建议先打开正式断层多边形结果，再对照复核层总览图或局部复核图。若复核候选被确认是真实断层，应优先调整参数或启用局部微补重新运行，而不是直接把复核线当成正式断层多边形。
