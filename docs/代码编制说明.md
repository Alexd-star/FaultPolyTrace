# 代码编制说明

本文说明 FaultPolyTrace 的源码组织、构建方法、核心模块职责和维护规范，用于满足赛题“代码编制说明文档”要求。

## 1. 源码目录

```text
src/app                 离线命令行入口
src/core                算法核心
src/io                  文件读写、诊断输出
geoeast_plugin/bo_runner        GeoEast 数据库读写 runner
geoeast_plugin/qt_launcher      Qt 图形启动器
geoeast_plugin/mainframe_plugin GeoEast 主控 Ribbon 插件
scripts                 构建、运行、测试、部署、打包脚本
tests                   测试说明和回归门禁
```

## 2. 核心模块职责

| 模块 | 主要职责 |
|---|---|
| `Grid2D` | 二维网格数据模型，保存网格尺寸、原点、采样间隔和属性值 |
| `Segmentation` | 固定阈值和分位数阈值分割，生成二值断层属性掩膜 |
| `BinaryMask` | 形态学开闭运算、膨胀、腐蚀、骨架化 |
| `SkeletonGraph` | 骨架端点、交点、分支提取，断点补连，短分支剪枝 |
| `FaultTracer` | 连通域搜索、边界追踪、断层带生成、多边形统计 |
| `Polygon` | 面积、周长、边界简化、边界平滑 |
| `Topology` | 闭合性、自相交、多边形相交诊断 |
| `AsciiGridIO` | ASCII 网格、GeoEast DAT、CSV/WKT 文件读写 |
| `DiagnosticsIO` | JSON 诊断和拓扑明细 CSV 输出 |

## 4. 运行与回归测试

烟测：

```powershell
.\scripts\run_smoke_test.ps1
```

官方数据性能回归：

```powershell
.\scripts\性能回归检查.ps1
```

默认门禁：

- 官方数据平滑场景总耗时不超过 5000 ms。
- 开放环、自相交均为 0。
- 多边形接触/交切诊断不超过官方数据历史阈值 500。
- 强响应覆盖率不低于 85.0%。
- 弱响应覆盖率不低于 86.5%。
- 非零响应覆盖率不低于 85.0%。

说明：当前回归门禁不再把固定多边形数量作为唯一标准。多边形数量受面积阈值、带宽、弱响应延拓、残余二次追踪和交切处理策略影响，正式验收采用覆盖率、拓扑、视觉叠加和耗时综合评价。

## 5. 编码规范

- 核心算法保持与 GeoEast SDK 解耦，便于离线测试。
- GeoEast 相关代码集中在 `geoeast_plugin` 目录。
- 使用 C++17 标准库容器和 RAII 管理内存。
- 参数通过命令行、Qt 界面、`.ini` 或环境变量传入，避免写死项目名和用户名。
- 新增功能后必须更新中文文档和回归脚本。
- 修改核心算法后必须运行烟测和性能回归。

## 6. 关键设计取舍

- 使用 Ridge-Belt 模式处理细长、交切、断续断层属性，增强对地质解释场景的适配性。
- 多边形保持闭合环内部表示，输出 WKT 时补首点闭合。
- 面积过滤不删除记录，而是使用 `kept/filtered` 状态，便于审查阈值影响。
- 拓扑诊断保留明细 CSV，便于定位异常边。
- 主控插件保持轻量，只启动 Qt 启动器，降低对 GeoEast 主进程稳定性的影响。
