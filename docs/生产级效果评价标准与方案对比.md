# 生产级效果评价标准与方案对比

文档版本：V1.1
日期：2026-05-23  
适用范围：FaultPolyTrace 赛题 7 冲顶开发、答辩验收、后续企业级产品化

## 1. 重要结论

断层多边形自动追踪不能把某一个固定多边形数量当成唯一标准。`204` 只是当前均衡主线在官方数据上的稳定回归锚点，不是最终质量目标。

真正的质量目标是：

1. 该覆盖的断层响应要尽量覆盖，尤其是强响应主断层。
2. 近邻但不属于同一脉络的断层不能被错误包成一个大圈。
3. 输出必须是闭合多边形，不能有开放环、自相交或异常相交。
4. 边界要贴近断层属性带，不能明显偏离或过度粗糙。
5. 结果粒度要适合解释人员使用，不能碎成几千个小胶囊，也不能把多条断层合成少数大面。
6. 面积统计、面积阈值过滤、GeoEast 读写和界面操作必须完整。
7. 算法核心耗时必须远低于赛题 1 分钟要求，企业工程目标是秒级。

因此，后续判断“效果好不好”，必须看覆盖、黏连、拓扑、粒度、边界和耗时的组合，而不是只看多边形数量。

## 2. 生产级质量门禁

任一方案必须先通过以下硬门槛：

| 门槛 | 要求 | 原因 |
|---|---:|---|
| 开放环 | 0 | 赛题要求每个多边形闭合 |
| 自相交 | 0 | 自交多边形在解释和数据库中不可靠 |
| 异常相交 | 0 | 相邻断层结果不能拓扑混乱 |
| 核心耗时 | < 60 秒 | 赛题性能要求 |
| 强响应覆盖率 | >= 99% | 主断层不能明显漏追踪 |
| 弱响应覆盖率 | >= 95.5% | 细弱断层带应有较高召回 |

通过门禁以后，再用综合评分比较方案优劣。

## 3. 综合评分维度

新增脚本：

```powershell
python .\scripts\综合质量评分.py
```

评分采用 100 分制：

| 分项 | 分值 | 含义 |
|---|---:|---|
| 覆盖与漏检 | 35 | 强、弱、非零响应覆盖率，以及未覆盖复核连通域 |
| 防黏连 | 25 | 高/中风险疑似误合并越少越好，同时纳入安全拆分收益和剩余可行动低值桥风险 |
| 粒度、边界与碎片 | 15 | 不固定多边形数量，但惩罚碎片化、极端数量和过宽背景包络 |
| 拓扑合法 | 15 | 开放环、自交、异常相交必须为 0 |
| 性能 | 10 | 核心处理秒级，总耗时稳定 |

防黏连评分不能只看“疑似误合并数量”。真实生产中，长断层、交切断层和宽断层带本来就可能包含多个强响应段。如果只按强响应段数量强拆，会把合理解释对象切碎。因此当前评分额外引入两类因果指标：

| 指标 | 作用 |
|---|---|
| 安全拆分收益 | 候选方案相对基线切掉低值背景桥、且不损失强响应时加分 |
| 可行动低值桥风险 | 仍存在明确低属性桥、切开后两侧主体足够大的候选时扣分 |
| 远背景包络比例 | 衡量多边形是否包入过多远离弱响应的 0 值背景，用于检查边界是否过宽 |

这三项的意义是把“看起来像黏连”拆成可解释证据：是否真的切掉了背景桥、是否损失了有效响应、是否仍有可明确处理的桥接对象。这样才能避免顾此失彼。

等级解释：

| 等级 | 说明 |
|---|---|
| 冲顶优秀 | 可作为满分/超额分目标，但仍建议配合人工复核图 |
| 正式交付 | 已达到比赛提交和工程演示要求 |
| 可复核使用 | 可作为高级复核或实验模式 |
| 研发实验 | 只能用于算法探索，不能作为默认交付 |

## 5. 蓝框黏连的进一步诊断

对比基线和根系防黏连：

```text
examples\outputs\quality_compare\compare_20260523_0315_actionable_bridge_score\02_root_antimerge\diff_from_balanced
```

核心结论：

| 指标 | 数值 |
|---|---:|
| 发生覆盖变化的基线多边形 | 6 |
| 被候选结果拆成多段的基线多边形 | 6 |
| 切掉强响应像元 | 0 |
| 切掉弱响应像元 | 1 |
| 无基线来源候选多边形 | 0 |

被拆分对象包括：

```text
67, 126, 40, 33, 109, 110
```

其中 `67`、`40`、`33` 等主要切掉 0 值背景桥，没有损失强弱响应，方向合理。`126` 发生 1 个弱响应像元损失，该像元值约为 `0.70`，周围有大片 0 值背景和少量强弱响应点。它更像“拆分后残余复核点”，不应为了这一个弱点重新把大圈黏回去，但应进入残余复核层或局部微补候选。

## 6. 当前产品策略

当前建议提供两个正式预设和一个研发实验模式，而不是只给一个结果：

1. **均衡主线**
   - 默认稳健方案。
   - 适合首次运行、答辩演示、GeoEast 数据库写入。
   - 优点是速度快、拓扑稳定、结果粒度稳定。

2. **根系防黏连**
   - 高级质量方案。
   - 适合用户发现近邻断层被包成大圈时启用。
   - 优点是能按根系脉络拆开一部分蓝框黏连对象。
   - 注意：仍需配合差异诊断复核少量弱响应损失。

局部窄桥防黏连暂保留为研发实验开关，不建议作为普通用户默认模式。

3. **局部窄桥防黏连**
   - 研发实验/候选增强方案。
   - 适合低属性窄桥明确、用户需要检查“本不该合并的邻近断裂”时使用。
   - 本轮对官方数据可减少 1 个可行动低值桥候选，但高/中风险疑似黏连数量略升。
   - 是否进入默认预设，需要通过更多真实工区和合成泛化数据确认。

## 7. 下一步冲顶方向

### 7.1 改进防黏连收益评价

当前“疑似误合并”统计主要看单个多边形内部强响应段和低值比例，不能充分反映“一个大圈被合理拆成几个小圈”的收益。因此下一步应把 `防黏连差异诊断` 的结果纳入综合评分：

- 拆分后没有强响应损失，加分。
- 只切掉低值背景桥，加分。
- 拆分后弱响应损失，扣分。
- 出现无来源新多边形或碎片暴涨，扣分。

### 7.2 做残余复核层或局部微补

对 `126` 中 1 个弱响应损失点，不应靠扩大整体多边形解决。更合理的方式是：

- 若该点与已有断层带距离很近，输出为“残余复核层”。
- 若局部图确认它是端点或分支的一部分，采用局部微补。
- 微补必须满足：不跨越 0 值背景、不合并相邻断层、不破坏拓扑。

### 7.3 更多泛化回归

根系防黏连不能只在官方数据上确认。还需要在以下场景回归：

- 近邻平行断层。
- 交切断层。
- 强弱变化断层。
- 宽断层带。
- 噪声强背景。
- 小断层密集区。

## 8. 结论

当前项目已经达到正式交付水平，但冲顶优秀还需要继续完善：

- 不再把 `204` 当成唯一目标。
- 已建立生产级综合评分和方案对比流程。
- 根系防黏连是当前解决蓝框黏连的正确方向。
- 下一步重点不是盲目调参数，而是把“拆分收益”和“弱响应复核/微补”纳入算法闭环。
