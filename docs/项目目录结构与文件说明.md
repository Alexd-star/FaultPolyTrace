# FaultPolyTrace 项目目录结构与文件说明

本文档用于说明 FaultPolyTrace 代码仓库、发布包、GeoEast 集成文件和中文文档的目录组织。新用户、评审专家和后续开发人员可通过本文快速判断“从哪里启动软件”“哪个目录放源码”“哪个目录放发布文件”“哪个文档解释操作流程”。

## 1. 推荐阅读路径

首次使用产品时，建议按以下顺序阅读：

1. `README.md`：了解项目目标、核心能力和快速入口。
2. `docs/用户操作手册.md`：按步骤完成外部文件追踪、GeoEast 数据库追踪和结果查看。
3. `docs/GeoEast使用指南.md`：在 GeoEast 中配置菜单入口、读取网格和查看断层多边形。
4. `docs/算法原理说明.md`：理解断层属性追踪、闭合多边形、面积过滤和防黏连策略。
5. `docs/发布说明与验收清单.md`：核对交付包、评分项和验收证据。

开发人员建议同时阅读：

1. `docs/开发指南.md`
2. `docs/代码编制说明.md`
3. `docs/独立软件与GeoEast集成解耦说明.md`
4. `docs/独立软件与GeoEast插件全流程开发规划.md`

## 2. 用户入口

### 2.1 独立软件入口

独立软件入口位于发布包根目录：

```text
release/FaultPolyTrace_v*/FaultPolyTrace.exe
```

也可以使用兼容入口：

```text
release/FaultPolyTrace_v*/01_打开图形界面.cmd
```

独立软件应能在不启动 GeoEast 的情况下完成外部文件处理。用户可以选择 DAT、矩阵文本或 CSV 网格文件，设置输出目录和参数，运行后在软件中查看原始网格、结果多边形和叠加结果。若选择 `GeoEast数据库` 数据源，则需要在【数据库配置】中配置 GeoEast 根目录、数据根目录、数据库、项目和用户信息。

### 2.2 GeoEast 集成入口

GeoEast 集成入口由部署脚本安装到 GeoEast 主程序菜单中。部署完成后，GeoEast 菜单按钮会启动：

```text
GeoEast-RC/bin/faultpolytrace_launcher.exe
```

便携启动器和相关依赖同步放在：

```text
GeoEast-RC/bin/FaultPolyTraceLauncher/
```

该目录应包含 Qt 运行库、图标、执行程序、帮助文档和必要资源。GeoEast 集成场景下，用户主要选择输入 BOMapGrid、输出 BOFaultPolygon 名称、显示颜色和算法参数，然后点击【开始追踪】写入 GeoEast 数据库。

### 2.3 命令行入口

核心算法命令行入口位于发布包：

```text
release/FaultPolyTrace_v*/bin/faultpolytrace.exe
```

源码构建时常见位置为：

```text
build/faultpolytrace.exe
```

GeoEast 数据库读写执行程序为：

```text
geoeast_plugin/bo_runner/faultpolytrace_geoeast_runner.exe
```

该程序依赖 GeoEast SDK 和运行环境，不建议脱离 GeoEast 环境单独分发。

## 3. 仓库根目录结构

| 路径 | 内容 | 主要使用者 |
|---|---|---|
| `src/` | 跨平台核心算法和共享代码，包括网格、二值掩膜、骨架拓扑、断层追踪、多边形生成、UI 本地化模块等 | 开发者 |
| `standalone_app/qt_desktop/` | 独立桌面软件 Qt Widgets 源码，负责外部文件处理、GeoEast 数据库模式、真实图层查看、历史记录和参数模板 | 用户、开发者 |
| `geoeast_plugin/qt_launcher/` | GeoEast 集成启动器源码，负责 BOMapGrid 选择、参数设置、结果写入、结果查看和 GeoEast 工区底图/平面成图入口 | GeoEast 用户、开发者 |
| `geoeast_plugin/bo_runner/` | GeoEast BO 数据库读写执行程序源码，负责读取指定网格、调用核心算法、写入 BOFaultPolygon 和删除结果 | GeoEast 集成开发者 |
| `geoeast_plugin/mainframe_plugin/` | GeoEast 主控菜单插件相关文件，用于在 GeoEast 主界面增加 FaultPolyTrace 菜单入口 | GeoEast 集成开发者 |
| `scripts/` | 构建、部署、打包、质量评估、验收、图件生成和审计脚本 | 开发者、交付人员 |
| `docs/` | 中文文档、操作手册、设计说明、算法说明、验收报告和 GeoEast 帮助摘录 | 用户、评审、开发者 |
| `examples/` | 示例数据、官方数据输出、质量对比图、验收结果和可回溯实验目录 | 用户、评审、开发者 |
| `assets/` | 产品图标和界面资源 | 开发者、发布人员 |
| `release/` | 已生成的发布包、截图、答辩评审材料包和历史版本 | 用户、评审、交付人员 |
| `build/` | 本地构建输出目录，通常不作为正式交付依据 | 开发者 |

## 4. 核心源码目录

`src/` 是算法核心和共享模块所在目录。主要文件职责如下：

| 文件或目录 | 作用 |
|---|---|
| `BinaryMask.*` | 基于阈值和形态学操作生成断层响应掩膜 |
| `Grid2D.*` | 网格数据结构、坐标和数值访问 |
| `SkeletonGraph.*` | 骨架提取、拓扑节点和分支关系表达 |
| `FaultTracer.*` | 断层多边形自动追踪主流程 |
| `Polygon.*` | 多边形环、面积、周长、闭合和 WKT 输出 |
| `Segmentation.*` | 连通域、断层带分割和区域统计 |
| `Topology.*` | 拓扑检查、交切关系和结果合法性判断 |
| `ui/UiLocalization.*` | 独立软件和 GeoEast 启动器共用的界面语言切换与稳定键管理 |

核心算法应保持与界面解耦。界面只能通过执行程序或清晰 API 调用算法，不应把 GUI 控件逻辑写入核心算法文件。

## 5. 独立软件目录

```text
standalone_app/qt_desktop/
```

该目录是独立桌面软件源码目录，不应与 GeoEast 启动器混在一起。

| 文件 | 作用 |
|---|---|
| `FaultPolyTraceWindow.cpp/.h` | 独立软件主窗口、菜单、工具栏、参数面板、结果查看、历史记录、模板保存、GeoEast 数据库模式 |
| `main.cpp` | 应用入口，设置窗口图标并启动 Qt 主循环 |
| `FaultPolyTraceDesktop.pro` | Qt 工程文件，包含源码、图标和共享 UI 本地化模块 |

独立软件面向无 GeoEast 环境用户时，主要处理外部网格文件。面向已有 GeoEast 环境用户时，可通过配置连接 GeoEast 数据库并调用 GeoEast BO Runner。

## 6. GeoEast 集成目录

```text
geoeast_plugin/
```

该目录分为三个层次：

| 子目录 | 作用 |
|---|---|
| `qt_launcher/` | GeoEast 菜单按钮打开的可视化启动器 |
| `bo_runner/` | 负责 GeoEast 数据库读取和写入的执行程序 |
| `mainframe_plugin/` | GeoEast 主控菜单插件文件 |

GeoEast 集成的核心原则是：菜单插件只负责入口，Qt 启动器负责交互，BO Runner 负责数据库读写，核心算法负责追踪。这样可降低耦合，也便于排查问题。

## 7. 脚本目录

`scripts/` 存放自动化脚本。常用脚本如下：

| 脚本 | 作用 |
|---|---|
| `build.ps1` | 构建核心命令行算法 |
| `build_desktop_app.ps1` | 构建独立桌面软件并部署 Qt 依赖 |
| `build_qt_launcher.ps1` | 构建 GeoEast Qt 启动器并部署 Qt 依赖 |
| `build_geoeast_bo_runner.ps1` | 构建 GeoEast BO Runner |
| `部署到GeoEast.ps1` | 将菜单插件、启动器、执行程序、图标和文档同步到 GeoEast |
| `打包发布包.ps1` | 生成可分发发布包 |
| `验收独立软件发布包.ps1` | 验证发布包是否包含入口、依赖、文档和示例 |
| `检查独立软件界面功能.ps1` | 检查独立软件菜单、按钮、文档入口和运行状态联动 |
| `检查GeoEast插件界面功能.ps1` | 检查 GeoEast 启动器、结果管理、文档入口和部署链路 |
| `一键总验收.ps1` | 对官方数据、质量图件、性能和发布链路进行综合验收 |
| `赛题满分交付审计.ps1` | 汇总满分交付所需证据和待确认项 |

脚本生成的结果通常保存在 `examples/outputs/`，目录名包含时间戳，便于回溯。

`docs/` 是中文交付文档目录。关键文档如下：

| 文档 | 作用 |

| `项目目录结构与文件说明.md` | 本文档，说明目录结构和文件职责 |
| `用户操作手册.md` | 面向最终用户的操作流程 |
| `企业级用户操作手册与产品说明书.md` | 面向产品交付的完整说明书 |
| `软件设计说明.md` | 软件架构、模块划分和数据流 |
| `代码编制说明.md` | 源码组织、编码规范、构建与调试 |
| `算法原理说明.md` | 算法流程、理论依据、参数含义和结果解释 |
| `GeoEast使用指南.md` | GeoEast 环境下的导入、运行、查看和复核 |
| `发布说明与验收清单.md` | 发布包组成、验收项和评分项对应关系 |

发布包和 GeoEast 便携启动器均应包含 `docs/` 目录。软件内部文档入口会优先查找当前程序附近的 `docs`，再查找发布包和源码仓库位置。

## 9. 示例与结果目录

`examples/` 用于保存示例数据和实验结果。

| 路径 | 作用 |
|---|---|
| `examples/synthetic/` | 合成网格示例，适合快速验证独立软件是否能运行 |
| `examples/outputs/official/` | 官方数据相关输出和图件 |
| `examples/outputs/quality_compare_*` | 多方案质量对比结果 |
| `examples/outputs/acceptance_*` | 一键验收输出 |
| `examples/outputs/desktop_ui_function_*` | 独立软件界面功能检查报告 |
| `examples/outputs/geoeast_plugin_ui_function_*` | GeoEast 插件界面功能检查报告 |

测试过程生成的目录应保留时间戳，不应覆盖旧结果。这样可以追溯算法参数、输出图件和质量指标的变化。

## 10. 发布包目录

发布包位于：

```text
release/FaultPolyTrace_v*/
```

典型发布包包含：

| 路径 | 作用 |
|---|---|
| `FaultPolyTrace.exe` | 独立软件图形入口 |
| `01_打开图形界面.cmd` | 兼容启动入口 |
| `bin/faultpolytrace.exe` | 核心算法命令行执行程序 |
| `docs/` | 中文交付文档 |
| `examples/` | 示例数据和验收输出 |
| `qt_launcher/` | GeoEast Qt 启动器相关文件 |
| `geoeast_plugin/` | GeoEast 插件源码和配置 |
| `platforms/`、`imageformats/`、`styles/`、`translations/` | Qt 运行依赖 |
| `README_先打开我.md` | 发布包快速入口说明 |
| `发布包清单.md` | 发布包文件清单和使用顺序 |

发布包根目录的 `FaultPolyTrace.exe` 是推荐图形入口。不要让用户进入源码目录查找程序。

## 11. 配置与用户数据

软件运行过程中会在用户系统目录保存配置和历史记录，而不是写死到开发者电脑路径。

| 数据 | 位置策略 |
|---|---|
| 独立软件配置 | Qt 标准 `AppConfigLocation` 下的 `desktop.ini` |
| 独立软件历史记录 | Qt 标准 `AppConfigLocation/history/records.tsv` |
| 默认输出目录 | 当前用户“文档”目录下的 `FaultPolyTraceOutputs` |
| 参数模板 | 用户主动选择保存位置 |
| GeoEast 配置 | 用户在【数据库配置】中填写，保存后下次自动恢复 |

这种设计便于异机运行，也避免把开发者机器上的绝对路径带入正式交付。

## 12. 维护原则

1. 独立软件和 GeoEast 启动器应共享可复用模块，例如 `src/ui/UiLocalization.*`，避免同一功能维护两套实现。
2. 核心算法参数新增后，必须同步更新独立软件、GeoEast 启动器、CLI、文档和检查脚本。
3. 所有新增按钮必须有真实功能，不允许保留空控件或占位按钮。
4. 所有需要前置条件的操作必须在执行前检查，并通过弹窗、状态栏或日志引导用户补齐。
5. 发布包和 GeoEast 部署必须携带文档，软件内部文档入口不得依赖开发者电脑固定路径。
6. 重要测试输出必须保留时间戳，便于复查和答辩。
