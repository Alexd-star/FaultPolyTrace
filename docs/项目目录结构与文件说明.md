# 项目目录结构与文件说明

本文件是软件“帮助”菜单可打开的便携目录说明。完整源码索引位于根目录 `PROJECT_INDEX.md`，新 AI 上下文位于 `AI_PROJECT_CONTEXT.md`。

## 1. 用户入口

### 1.1 独立软件入口

| 场景 | 入口 |
|---|---|
| 独立软件 | 发布目录根部 `FaultPolyTrace.exe` |
| CLI | 发布目录 `bin/faultpolytrace.exe` |
| GeoEast | 主框架菜单打开 `faultpolytrace_launcher.exe` |
| GeoEast 数据库执行程序 | `geoeast_plugin/bo_runner/faultpolytrace_geoeast_runner.exe` |

独立软件可处理外部文件，也可在客户已安装 GeoEast 时配置数据库。GeoEast Launcher 面向当前工区。两者界面代码分离，但共享 C++ 核心和 `TraceParameterModel`。

## 2. 源码目录

| 目录 | 内容 |
|---|---|
| `src/` | 算法、网格、多边形、拓扑、文件读写、诊断和共享 UI 模型 |
| `standalone_app/qt_desktop/` | 独立桌面软件 |
| `geoeast_plugin/qt_launcher/` | GeoEast Qt 界面 |
| `geoeast_plugin/bo_runner/` | GeoEast BO 读写 |
| `geoeast_plugin/mainframe_plugin/` | GeoEast 菜单入口 |
| `scripts/` | 构建、测试、部署、打包和验收 |
| `tests/`、`tests_cpp/` | Python 与 C++ 测试 |
| `packaging/windows/` | Windows 安装器 |
| `docs/` | 当前中文文档 |

## 3. 本地生成目录

`build/`、`release/`、`outputs/` 和 `examples/outputs/` 都是可重建产物，不进入 Git。`archive/` 保存本机历史材料，也不属于当前源代码。

## 4. 用户配置

- 软件配置与历史记录写入 Qt 标准用户配置目录。
- 默认输出位于当前用户文档目录下的 `FaultPolyTraceOutputs`。
- 数据库密码不写入 QSettings。
- 仓库只保留不含凭据的配置示例。

## 5. 维护规则

1. 新参数必须通过共享参数模型进入桌面端和 Launcher。
2. 新按钮必须有真实动作、前置检查和失败提示。
3. 核心算法不得依赖 GUI 或固定客户路径。
4. GeoEast 数据库代码不得假设内环语义；写入后必须重读校验。
5. 发布必须使用完整目录或安装器，不能分发裸 EXE。
