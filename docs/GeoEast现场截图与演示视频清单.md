# GeoEast 现场截图与演示视频清单

文档版本：V1.0
适用阶段：赛题提交前 GeoEast 集成证明补证
目标：让评审能够确认 FaultPolyTrace 不是离线演示程序，而是可以从 GeoEast 入口启动、读取 GeoEast 数据库、写入 GeoEast 结果对象，并在 GeoEast 平面成图或工区底图中叠加查看。

## 1. 使用方式

先运行：

```powershell
.\scripts\检查GeoEast现场证据.ps1 -Initialize
```

脚本会生成如下目录：

```text
release\figure\geoeast_acceptance_<时间戳>
```

请将本清单要求的截图和视频放入该目录，并使用固定文件名。完成后运行：

```powershell
.\scripts\检查GeoEast现场证据.ps1 -EvidenceDir .\release\figure\geoeast_acceptance_<时间戳>
```

如果准备做最终提交前强检查，运行：

```powershell
.\scripts\检查GeoEast现场证据.ps1 -EvidenceDir .\release\figure\geoeast_acceptance_<时间戳> -Strict
.\scripts\赛题满分交付审计.ps1 -StrictManual
```

## 2. 截图前准备

1. 确认 GeoEast license 可用，平面成图或工区底图功能可以打开。
2. 确认 FaultPolyTrace 已部署到 GeoEast。
3. 确认当前工区中存在官方输入网格，例如 `test7_fault_attribute_bo` 或等价 BOMapGrid。
4. 确认输出名称使用清晰名称，例如 `FaultPolyTrace_Result_Check` 或 `FaultPolyTrace_Result_Final`。
5. 结果颜色建议使用青色、黄色或白色等与原始属性背景有明显区分的颜色，避免红色结果线与红色属性背景混在一起。

## 3. 必需截图

| 文件名 | 截图内容 | 合格标准 |
|---|---|---|
| `01_GeoEast菜单入口.png` | GeoEast 主界面中的“断层多边形追踪”菜单、按钮或 Ribbon 入口 | 能看出入口属于 GeoEast 主控界面，不是单独打开的 exe |
| `02_启动器自动配置.png` | 从 GeoEast 入口打开的 FaultPolyTrace 启动器 | 能看到数据库、项目、用户、执行程序或根目录等配置已自动识别 |
| `03_输入网格列表.png` | 启动器中刷新后的输入网格列表 | 能看到官方输入 BOMapGrid 名称 |
| `04_原始网格显示.png` | GeoEast 平面成图、工区底图或启动器真实视图区显示原始断层属性 | 能看到属性色标和断层响应范围 |
| `05_结果多边形图层.png` | GeoEast 中单独显示输出 BOFaultPolygon 结果 | 能看到追踪出的闭合断层多边形 |
| `06_原始与结果叠加.png` | 原始网格与结果多边形叠加显示 | 能看出结果边界贴合主要断层响应，颜色清晰 |
| `07_数据库对象管理.png` | GeoEast 图层树、对象管理器或数据管理窗口中的结果对象 | 能看到输出 BOFaultPolygon 已写入数据库 |
| `08_运行日志与耗时.png` | 启动器运行日志和耗时信息 | 能看到运行成功、写库成功和本次实际耗时，例如 `630 ms (0.630 s)` |

## 4. 建议录屏

建议录制：

```text
09_演示视频.mp4
```

建议时长 1 到 2 分钟。视频只需要证明完整流程，不需要长篇讲解。

推荐视频顺序：

1. 显示 GeoEast 主界面和“断层多边形追踪”入口。
2. 点击入口打开 FaultPolyTrace 启动器。
3. 点击刷新网格，选择官方输入网格。
4. 点击开始追踪，等待运行完成。
5. 展示日志中的核心耗时和写库成功提示。
6. 打开 GeoEast 平面成图或工区底图。
7. 分别显示原始网格、结果多边形和叠加图。
8. 打开对象管理或图层树，显示结果对象存在。

## 5. 常见不合格情况

以下截图不能作为满分证据：

1. 只截到独立软件，没有截到 GeoEast 主界面入口。
2. 只截到结果图片，没有截到数据库对象或图层树。
3. 截图没有显示输入网格名称或输出对象名称。
4. 结果线颜色与背景接近，评审看不清多边形边界。
5. 只有离线命令行运行结果，没有 GeoEast 读写数据库证据。
6. 使用占位文本文件冒充截图。
7. 只截到启动器窗口，没有平面成图或工区底图中的叠加效果。

## 6. 补证后的检查口径

补齐截图后，`检查GeoEast现场证据.ps1` 应至少满足：

```text
失败: 0
```

如果视频尚未录制，`待补充: 1` 可以作为内部开发状态，但正式答辩前建议补齐视频。若启用 `-Strict`，视频也必须补齐。

最终 `赛题满分交付审计.ps1` 中 GeoEast 现场相关项目应从“待人工确认”变为“通过”。如果仍为“待人工确认”，说明截图或视频文件名、大小、目录位置或检查脚本识别条件还没有满足。
