# 第16章 历史文件说明

## 16.1 说明原则

本章用于记录项目中的旧版本、备份文件、临时文件、重复文件和可归档内容。本轮整理不删除任何文件，也不移动文件，只给出判断依据和后续建议。

## 16.2 历史发布包

`release/` 下可能存在多个历史版本目录。它们记录了界面、算法、打包和文档演进；当前推荐版本是 `FaultPolyTrace_v1.0.0-rc2-unified`。旧版本只在本地归档中保留，不提交到主分支。归档建议结构：

```text
archive/release/
```

并把非最新、非关键里程碑版本移入该目录。

## 16.3 历史输出目录

`examples/outputs/` 中有大量带时间戳的实验、验收、质量图和审计目录。这些目录是算法迭代的重要证据，尤其是从高召回、误合并修复、根系防黏连到当前推荐方案的过程。建议保留最新官方验收、满分审计、独立软件验收和关键历史基线，其余可按日期归档。

## 16.4 文档渲染产物

`docs/FaultPolyTrace中文操作文档_V1.0_pages/`、`docs/FaultPolyTrace中文操作文档_V1.0_render/` 和 `docs/render_ascii/` 属于文档渲染或格式检查产物。它们对确认 Word/PDF 生成质量有帮助，但不一定需要进入最终提交包。若 DOCX/PDF 已确认，可归档。

## 16.5 构建产物

`build/` 以及源码目录中出现的 `.obj`、`.moc`、`.exe`、`.dll`、`.pdb`、`.qmake.stash`、Makefile 等通常是构建产物。它们可以重新生成，但在当前工程尚未完全清理前，不建议直接删除。后续可通过 `.gitignore` 和独立构建目录规范化。

## 16.6 本地配置和敏感文件

`geoeast_plugin/qt_launcher/faultpolytrace_launcher.ini` 可能是本地实际配置文件；`docs/GeoEast2024-V4.3-dev-20271227.lic` 根据文件名推断为 license 文件。此类文件可能包含个人路径、授权或环境信息，应人工确认是否需要保留、脱敏或移出公开仓库。

## 16.7 临时参考文件

`examples/gemini-code-1780242218899.html` 根据文件名推断为界面视觉稿或外部参考文件。若仍用于 UI 对比，可保留；若已完成界面迁移，可归档到 `archive/design_reference/`。
