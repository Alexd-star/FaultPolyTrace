# 企业级开发路线图

本项目的目标是做出比赛可交付、可演示、可解释、可复现的 GeoEast 断层多边形追踪工具，而不是只跑通一次的算法脚本。

## 1. 不可妥协的产品目标

1. 正确读取官方平面断层属性数据。
2. 自动生成闭合断层多边形。
3. 将结果写回 GeoEast 可识别的 `BOFaultPolygon`。
4. 支持面积统计和面积阈值过滤。
5. 合理处理断层交切关系，至少提供检测和诊断。
6. 核心算法耗时满足 1 分钟内要求。
7. 内存使用合理，无明显泄漏风险。
8. 提供清晰 UI、可复现日志、测试证据和专业中文文档。

## 2. 架构决策

| 模块 | 决策 | 原因 |
|---|---|---|
| 核心语言 | C++17 | 性能好，和 GeoEast SDK/Qt 生态匹配 |
| 界面 | Qt/C++ | 符合 GeoEast 培训材料和工业桌面软件习惯 |
| 算法核心 | 与 SDK 解耦 | 可脱离 GeoEast 快速测试，降低集成风险 |
| GeoEast IO | 适配器层 | 把 `BOMapGrid`/`BOFaultPolygon` 代码隔离 |
| 测试 | 合成数据 + 官方数据 + 几何回归 | 保护算法质量和演示可靠性 |
| 文档 | 中文为主，技术名词保留英文标识 | 方便答辩、队友协作和提交材料整理 |

## 3. 当前核心基线

当前软件已经可以：

- 读取外部二维网格或官方 DAT 转换结果。
- 通过阈值提取高值断层候选区。
- 对候选区域做形态学清理。
- 执行连通域分组。
- 追踪真实闭合外边界。
- 保留凹形边界，而不是退化为凸包。
- 执行 `ridge-belt` 骨架转断层带追踪。
- 计算面积、周长和属性统计。
- 按面积阈值过滤。
- 导出 CSV/诊断 JSON。
- 通过 GeoEast runner 读 `BOMapGrid`、写 `BOFaultPolygon`。
- 通过 Qt 启动器配置连接和算法参数。

## 4. 下一批关键升级

### 4.1 几何质量

- 支持一个连通域中的多个环。
- 支持孔洞表达。
- 增加自相交检测和修复。
- 增加 Douglas-Peucker 边界简化。
- 增加可选 marching squares 平滑边界模式。

### 4.2 分割鲁棒性

- 增加局部自适应阈值。
- 增加双阈值滞后分割。
- 增加线状结构增强。
- 将所有算法参数统一沉淀到稳定配置结构。

### 4.3 交切关系处理

- 检测多边形相交和线段相交。
- 按面积、长度、平均属性强度、置信度判断主次断层。
- 实现保守的吸附、截断或裁剪策略。
- 输出交切处理统计，作为报告亮点。

### 4.4 GeoEast 集成

- 继续保证 `BOMapGrid` 读取稳定。
- 继续保证 `BOFaultPolygon` 写入可在 GeoEast 中查看。
- 完善 Qt 启动器的默认配置和错误提示。
- 解决或绕过主控 Ribbon 插件的旧 Qt 兼容编译问题。
- 准备比赛用一键运行脚本。

### 4.5 交付质量

- 完善结构化日志。
- 增加异常数据和参数错误提示。
- 形成官方数据性能报告。
- 形成内存使用说明。
- 准备中文用户手册、软件设计书、算法报告和演示视频脚本。

## 5. 开发顺序

1. 固化核心算法和默认参数。
2. 补齐官方数据运行和截图证据。
3. 完善 GeoEast 数据查看和写回验证流程。
4. 增强交切诊断与保守修复。
5. 做大规模性能和内存测试。
6. 打磨 Qt 启动器和错误提示。
7. 处理 GeoEast 主控入口。
8. 整理最终中文文档、PPT 和演示视频。

这个顺序的原则是：先保证赛题硬性得分项稳定，再冲击高分亮点。
