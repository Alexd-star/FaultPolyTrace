# 顶尖质量差距分析与推进计划

文档版本：V1.0  
日期：2026-05-22  
适用对象：FaultPolyTrace 赛题 7 正式交付与后续冲顶开发

## 1. 当前做到什么程度

当前项目已经达到“强比赛交付基线”，但还不能诚实地称为“顶尖企业级最终版”。

当前正式主线具备以下能力：

- 可以独立运行，也可以通过 GeoEast runner 读取 `BOMapGrid` 并写入 `BOFaultPolygon`。
- Qt 启动器已经支持输入选择、输出命名、参数配置、运行日志和结果颜色设置。
- 官方 `test.dat` 当前主线保留 204 个闭合断层多边形。
- 强响应覆盖率约 99.62%，弱响应覆盖率约 96.94%。
- 开放环、自相交、多边形异常相交均为 0。
- 核心追踪耗时约 0.42 至 0.45 秒，总耗时约 1.3 至 1.4 秒，远低于赛题 1 分钟要求。
- 文档已按中文交付口径整理，算法原理、用户手册、GeoEast 指南、需求矩阵和性能报告齐全。

一句话判断：

```text
比赛提交：可以作为正式主线
国家级奖项竞争：具备较强基础，但还要继续打磨证据链和局部质量
企业级产品：已有核心原型，仍缺自动参数推荐、误合并诊断闭环和更多真实数据回归
```

## 2. 为什么还不能叫顶尖

顶尖作品不是某一张结果图看起来最好，而是满足以下标准：

1. 默认参数在不同数据上都稳定。
2. 主要断层响应高召回，但不把噪声和邻近断层乱合并。
3. 输出闭合、平滑、拓扑干净。
4. 每个异常结果都能定位到原因。
5. 用户不懂算法也能完成操作。
6. 评审能复现所有关键指标。
7. 面对新数据时不依赖人工反复试参。

当前项目在前四项里已经有较强基础，但第 4、6、7 项仍需要继续增强。

## 3. 当前发现的主要问题

### 3.1 正式主线和历史实验曾经混在一起

问题表现：

- 一些文档还残留 `2191/4823` 个多边形、`333` 条交切诊断、`2.17 秒` 核心耗时等历史高召回实验指标。
- 这些数字来自残余二次追踪和分支拆分探索，不是当前正式主线。

已修复：

- 已将正式主线统一为 204 个多边形、拓扑诊断 0、核心约 0.5 秒。
- 已把残余二次追踪重新定位为高级复核功能，默认关闭。
- 已更新性能报告、质量报告、需求追踪矩阵和算法成熟度评估。
- 已新增面积保持型平滑，修复普通平滑造成的边界轻微内缩问题，在不改变多边形数量和拓扑的情况下提升覆盖率。

剩余要求：

- 后续所有报告必须明确区分“正式主线”和“高召回实验”。
- 高召回实验可以作为研发证据，但不能替代正式提交结果。

### 3.2 仍存在少量漏检复核项

当前顶尖质量诊断结果：

```text
强响应需复核连通域：3 个
弱响应线性需复核连通域：11 个
```

解释：

- 强响应复核项较少，说明主要断层召回已较高。
- 弱响应复核项代表仍有少量细弱线性响应没有被正式多边形覆盖。
- 这些区域不一定都应该输出成正式多边形，但必须能被定位、解释和复核。

后续方向：

- 先逐项查看这 3 个强响应复核区域。
- 目前已确认它们主要集中在端点、数据边界和交切附近，不是主断层整体漏追踪。
- 若确认为真实连续断层，应优先通过局部补追踪或残余复核层解决。
- 若是边缘噪声、短孤立端点或非断层响应，应在报告中说明过滤原因。

### 3.3 疑似误合并需要局部诊断，而不能无验收地全局乱切

当前顶尖质量诊断结果：

```text
高风险疑似误合并多边形：13 个
中风险疑似误合并多边形：30 个
```

解释：

- 这不是说 43 个多边形一定错误。
- 诊断规则只是提示：这些多边形内部可能存在多个高值段、低属性背景比例较高、形态不够细长，值得复核。
- 长断层沿走向强弱变化也会产生多个高值段，不能简单按高值段数量拆分。

后续方向：

- 对高风险 13 个多边形做局部图件复核。
- 只对明确跨越低值背景、两侧走向不同、切开后不会碎片化的对象做局部拆分。
- 禁止重新开启全局 `separate-branch-belts`，也不能无验收地全局切开根系争议点。
- 当前已有 `防黏连增强` 高级模式：先生成候选切分，再做切后主体规模验收和自动回退，可作为默认结果的对照复核方案，但不替代 `贴合融合推荐` 主线。

### 3.4 参数自动推荐还没有产品化

当前参数是经过官方数据、合成数据和多轮实验后确定的推荐默认值，但面对新工区仍需要用户理解参数含义。

风险：

- 新数据噪声更强时，可能需要提高分位数或收紧残余复核。
- 新数据断层更宽时，可能需要增大 `belt-radius`。
- 新数据采样间隔不同，面积阈值和补连距离需要随网格尺度变化。

后续方向：

- 增加自动参数推荐模块。
- 根据属性直方图、非零像元比例、线性连通域尺度、网格间距自动给出“保守、均衡、高召回”三档。
- UI 中显示推荐原因，而不是只给数字。

### 3.5 真实数据回归不足

当前泛化验证主要来自合成数据和官方样例，已经能证明算法不是硬编码官方图案，但还不足以支撑真正企业级结论。

后续方向：

- 至少建立 5 至 10 组不同形态的回归数据：
  - 近邻平行断层。
  - 交切复杂断层。
  - 强弱变化断层。
  - 噪声背景断层。
  - 宽断层带。
  - 小断层密集区。
- 每组保留输入、输出、诊断 JSON、质量图、漏检表、参数文件和人工判断说明。

## 4. 如何探究到问题核心

后续不能只凭肉眼看整张图，而要按以下顺序定位问题。

### 4.1 先看覆盖率

目标：

- 强响应覆盖率保持 99% 以上。
- 弱响应覆盖率保持 95.5% 以上。

判断：

- 强响应漏检多，说明核心追踪不足。
- 弱响应漏检多但强响应覆盖好，说明可以用复核层处理，不一定要改默认主线。

工具：

```powershell
.\scripts\运行顶尖质量诊断.ps1
```

输出：

```text
强响应未覆盖复核连通域.csv
弱响应未覆盖线性连通域.csv
```

### 4.2 再看误合并候选

目标：

- 不把邻近但中间隔着背景 0 属性的断层合成大圈。
- 不把正常长断层沿走向强弱变化误拆成碎片。

判断：

- 如果一个闭合多边形内部有多段强响应，并且中间低属性背景比例高，才进入复核。
- 如果多边形整体很细长，且沿同一方向延伸，即使强响应断续，也可能是合理断层带。

工具输出：

```text
疑似误合并多边形.csv
逐多边形质量诊断.csv
```

### 4.3 然后看拓扑

硬门槛：

```text
开放环 = 0
自相交 = 0
多边形异常相交 = 0
```

任何算法改动只要破坏这三项，都不能进入正式主线。

### 4.4 最后看图件

图件只用于最终确认，不作为唯一判断依据。必须配合：

- 质量评估汇总表。
- 漏检质控表。
- 疑似误合并表。
- 拓扑 CSV。
- 诊断 JSON。

### 4.5 对几何后处理做因果对照

本轮发现少量强响应漏检并非来自主干追踪失败，而是来自平滑后边界轻微内缩。定位过程是：

1. 固定阈值、骨架、缓冲、面积阈值等主算法参数。
2. 只改变简化和平滑开关。
3. 对比强弱覆盖率和拓扑。
4. 若关闭平滑覆盖率上升但拓扑变差，说明根因在几何后处理，而不是断层响应识别。
5. 使用面积保持型平滑替代普通平滑，并再次验证覆盖率、拓扑和多边形数量。

该方法避免了盲目降低阈值或开启高召回残余层，属于低风险工程修复。

## 5. 精准修复方案

### 第一阶段：可信交付收口

状态：已基本完成。

目标：

- 统一正式主线指标。
- 清理旧实验指标残留。
- 补齐中文文档。
- 增加顶尖质量诊断工具。

验收门槛：

```text
保留多边形：204±15
强响应覆盖率：>= 99.0%
弱响应覆盖率：>= 95.5%
开放环：0
自相交：0
多边形异常相交：0
核心追踪耗时：< 60 秒
总耗时门禁：< 5 秒
```

### 第二阶段：漏检复核闭环

目标：

- 把强响应未覆盖连通域从“表格提示”升级为“可解释处理”。
- 每个强响应漏检项给出：补追踪、忽略、噪声过滤三种原因之一。

开发任务：

1. 在漏检质控表中增加最近多边形距离、最大属性、线性程度、是否接触边界。
2. 对强响应漏检区域生成局部裁剪图。
3. 对端点、边界、交切附近漏检做分类说明。
4. 增加“残余复核层”输出，不默认写入正式结果。
5. UI 增加复核层开关。

### 第三阶段：局部误合并拆分

目标：

- 解决少量本不该合并的近邻断层。
- 保持当前 200 个量级整体粒度，不退回几千个碎片。

开发任务：

1. 对疑似误合并多边形内部提取强响应子连通域。
2. 寻找子连通域之间的低属性窄桥。
3. 只在局部桥接处尝试切分。
4. 切分后重新计算拓扑和覆盖率。
5. 若切分导致强响应覆盖下降或碎片数量暴涨，则自动回退。

进入正式主线的条件：

```text
强响应覆盖率不下降超过 0.1%
弱响应覆盖率不下降超过 0.5%
多边形数量仍保持 200±30
拓扑异常仍为 0
人工复核图确认误合并减少
```

### 第四阶段：参数自动推荐

目标：

- 用户导入新数据后，不需要理解所有算法参数，也能得到合理默认结果。

开发任务：

1. 统计属性直方图、非零比例、高值比例。
2. 识别线性连通域尺度和典型宽度。
3. 根据网格间距自动换算面积阈值和补连距离。
4. 输出三档参数：
   - 保守：少误合并，适合噪声强数据。
   - 均衡：正式默认，适合提交和演示。
   - 高召回：适合解释人员复核弱响应。
5. UI 中显示推荐原因和风险提示。

### 第五阶段：真实数据回归库

目标：

- 证明软件不是官方样例专用。

开发任务：

1. 收集或构造多类测试数据。
2. 每类数据保存固定期望指标。
3. 一键回归输出总报告。
4. 每次算法改动必须跑回归。

## 6. 当前优先级

优先级从高到低：

1. 固定正式主线和文档口径。
2. 生成 GeoEast 内部原始图与叠合图截图。
3. 用顶尖质量诊断复核 3 个强响应漏检区域和 13 个高风险误合并候选。
4. 增加局部裁剪图，降低人工复核成本。
5. 开发参数自动推荐。
6. 扩展真实/合成回归数据集。

## 7. 当前不能做的事

为了保护当前主线，不应做以下操作：

- 不应为了追求“看起来全覆盖”默认开启残余二次追踪。
- 不应默认开启分支分开输出，避免回到几千个碎片。
- 不应无验收地全局切开根系争议点，避免把连续断层切碎。
- 不应把 `防黏连增强` 当作所有数据的默认替代方案；它必须和默认结果对照，并用差异诊断确认没有损失强弱响应。
- 不应只看单张图决定参数。
- 不应把官方样例的某些位置写成硬编码规则。
