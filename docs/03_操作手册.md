# 第3章 操作手册

## 3.1 手册目的

本文说明 FaultPolyTrace 的安装、启动、部署、运行和验收操作。它面向需要把项目跑起来的用户、评审人员和维护人员。与 `docs/02_用户手册.md` 相比，本文更关注“软件从哪里启动、脚本怎么执行、结果如何验证、部署后如何检查”。

## 3.2 发布包启动

推荐从最新发布包启动：

```text
release/FaultPolyTrace_v1.0.0-rc2-unified
```

常用入口如下：

| 入口 | 作用 |
|---|---|
| `FaultPolyTrace.exe` | 独立软件图形入口。 |
| `01_打开图形界面.cmd` | 兼容入口，适合不熟悉 exe 路径的用户。 |
| `02_运行离线演示.cmd` | 使用发布包自带示例数据进行快速演示。 |
| `03_查看命令行帮助.cmd` | 查看 CLI 参数说明。 |

如果双击命令行程序一闪而过，通常是因为 CLI 需要参数。评审场景应优先双击 `FaultPolyTrace.exe` 或 `01_打开图形界面.cmd`。

## 3.3 源码构建

源码构建常用命令：

```powershell
.\scripts\build.ps1
.\scripts\build_desktop_app.ps1
.\scripts\build_qt_launcher.ps1
.\scripts\build_geoeast_bo_runner.ps1
```

构建前应确认 Visual Studio C++ 工具链、Qt、GeoEast SDK 和相关环境变量可用。GeoEast BO runner 依赖 GeoEast 自带库，若脱离 GeoEast 环境运行，可能出现 DLL 缺失、license 不可用或数据库连接失败。

## 3.4 GeoEast 部署

部署到 GeoEast 可使用：

```powershell
.\scripts\部署到GeoEast.ps1
```

部署后应检查：

1. GeoEast 主界面是否出现 FaultPolyTrace 菜单或按钮。
2. 按钮是否能打开 Qt 启动器。
3. 启动器是否能自动识别 GeoEast 根目录和用户信息。
4. 是否能刷新 `BOMapGrid` 列表。
5. 是否能运行并写入 `BOFaultPolygon`。
6. GeoEast 工区底图或平面成图是否能叠加查看原始网格和结果多边形。

这些现场证据当前仍需要人工截图或录屏补齐，详见 `docs/GeoEast现场截图与演示视频清单.md`。

## 3.5 官方数据验收

官方数据质量验收应以 `test.dat` 为准。当前最新报告位于：

```text
docs/官方数据最新验收报告.md
```

推荐执行：

```powershell
.\scripts\一键总验收.ps1
.\scripts\赛题满分交付审计.ps1
```

如果当前机器 GeoEast 环境不可用，可先跳过 GeoEast 构建和打包：

```powershell
.\scripts\一键总验收.ps1 -SkipGeoEastBuild -SkipPackage
```

## 3.6 操作风险提示

不要在未备份的情况下手工覆盖 GeoEast 配置文件。不要把个人 license、个人数据库密码或本机路径写入通用发布包。不要只凭合成数据判断算法质量，正式质量结论必须以官方 `test.dat` 和 GeoEast 现场结果为准。
