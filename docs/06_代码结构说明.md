# 第6章 代码结构说明

## 6.1 根目录代码组织

项目根目录采用工程化分区：`src/` 存放核心代码，`standalone_app/` 存放独立软件，`geoeast_plugin/` 存放 GeoEast 集成，`scripts/` 存放自动化脚本，`docs/` 存放中文文档，`examples/` 存放示例和输出，`release/` 存放发布包。

这种结构的好处是：算法、界面、平台集成和交付材料互不混淆。后续维护时可以针对某一层修改并运行对应验收脚本。

## 6.2 `src/core`

`src/core` 是算法核心目录。`FaultTracer` 是主流程；`BinaryMask` 负责掩膜和形态学；`SkeletonGraph` 负责骨架拓扑；`Segmentation` 负责连通域和区域分割；`Polygon` 负责面积、周长、闭合和边界处理；`Topology` 负责结果合法性诊断。

输入是统一的 `Grid2D` 网格对象和追踪参数，输出是多边形集合、统计信息和诊断结果。该目录不应包含 Qt 控件代码，也不应写入用户界面文本。

## 6.3 `src/io`

`src/io` 负责输入输出。`AsciiGridIO` 用于读取外部 DAT、ASCII 和矩阵文本，并输出 CSV；`DiagnosticsIO` 用于输出 JSON 和诊断信息；`GeoEastAdapters.h` 定义 GeoEast 适配抽象，使核心算法可以在不直接依赖 GeoEast SDK 的情况下使用。

## 6.4 `standalone_app/qt_desktop`

该目录是独立软件。`FaultPolyTraceWindow` 是主要窗口类，负责数据源选择、输入输出、参数模板、历史记录、图层显示、日志提示、语言切换和文档入口。它应以普通用户使用逻辑为中心，不应出现“仅开发者能理解”的实现术语。

## 6.5 `geoeast_plugin`

GeoEast 集成分为三部分。`qt_launcher` 提供界面，`bo_runner` 提供数据库读写执行程序，`mainframe_plugin` 提供主控菜单入口。三者不能互相替代。若 GeoEast 菜单不可见，应先检查主控插件；若界面可打开但网格刷新失败，应检查启动器配置和 BO runner；若写入失败，应检查 GeoEast 数据库、权限和对象名。

## 6.6 `scripts`

脚本目录既是开发效率工具，也是交付质量门禁。脚本命名大多为中文，便于用户理解。建议后续新增脚本时继续使用明确动词，例如“检查”“生成”“打包”“部署”“验收”，并在脚本顶部写清楚输入、输出和运行前提。
