# FaultPolyTrace 可靠性与性能增量加固方案

> 实施状态：原子文件写入、输出限流、资源校验、即时停止和GeoEast事务式暂存/回读/回滚均已完成；最终验证结果见`官方数据最新验收报告.md`。

## 1. 目标与边界

本轮加固面向独立软件、命令行执行程序和 GeoEast 插件的生产使用场景，目标是在输入异常、磁盘写入中断、子进程异常输出、资源不足和用户强制停止等情况下保持界面可响应、已有结果不被半写文件破坏，并给出可理解的失败信息。

加固遵循三个约束：不改变正式追踪算法、默认参数和官方数据结果；正常路径只允许常数级低开销；无法确认 GeoEast SDK 事务语义的数据库写入流程不做推测性重构。

## 2. 风险分级与措施

| 风险 | 现状 | 本轮措施 | 正常路径代价 |
|---|---|---|---|
| 输出过程中断或磁盘写入失败 | 直接覆盖 CSV/JSON，可能留下半截文件 | 同目录临时文件完整写出并校验流状态，再原子替换目标文件 | 每个文件增加一次同卷重命名 |
| 恶意或异常执行程序持续刷屏 | 界面日志有 3000 行限制，但内存中的完整进程输出无上限 | 进程输出缓冲限制为 4 MiB，保留最新内容并标记前段已省略 | 仅在追加文本时做一次长度比较 |
| 非法网格维度或乘法溢出 | 正维度已校验，极端维度依赖分配失败兜底 | 在分配前检查维度乘法和容器最大容量 | 每次读入只执行一次 |
| 非有限网格元数据 | 间距只校验正数，NaN/Inf 可能绕过比较 | 明确要求原点和间距为有限值 | 每次读入只执行数次浮点判断 |
| GeoJSON 导出中断 | 直接截断目标文件 | 改用 Qt 原子保存并核对提交结果 | 一次原子提交 |
| 子进程停止 | 已使用 QProcess::kill 强制停止 | 保留现有即时停止；增加输出限流，避免停止前刷屏拖垮界面 | 无额外计算开销 |
| GeoEast 对象替换失败 | 直接覆盖存在旧对象丢失风险 | 先写暂存对象并逐点回读，替换目标后再次回读；失败时恢复旧几何与样式并清理暂存对象 | 两次数据库写入与回读，仅发生在结果提交阶段 |

## 3. 验收门槛

1. 官方 `test.dat` 的保留多边形数量、拓扑结果和正式 CSV SHA256 不变。
2. 核心处理总耗时继续满足 5 秒回归门槛，且相对本轮基线无显著退化。
3. 原子写入失败时，旧目标文件保持完整，临时文件被清理。
4. 非法维度、非有限元数据和不可写目标均以非零退出码结束，不崩溃、不产生伪成功结果。
5. 独立软件与插件的进程输出缓冲均有上限，日志控件继续保持 3000 行上限。
6. 既有 Python、C++、界面契约、参数一致性和发布验收全部通过。

## 4. 不采用的重型方案

本轮不引入常驻服务、任务队列、重复计算、网络重试风暴或算法内部高频检查。GeoEast 数据库操作也不加入未经 SDK 文档确认的“伪事务”。这些方案会增加复杂度、延迟或数据风险，不符合提交阶段的增量优化原则。
