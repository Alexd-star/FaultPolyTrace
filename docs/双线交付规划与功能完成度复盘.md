# FaultPolyTrace 双线交付规划与功能完成度复盘

文档版本：v1.0
更新日期：2026-06-02
适用范围：赛题 7 提交物、独立桌面软件、GeoEast 集成控件、核心算法程序、发布包与验收材料。

## 1. 文档目的

本文件用于把 FaultPolyTrace 当前项目状态、赛题要求完成度、独立软件与 GeoEast 集成控件的边界、后续开发优先级整理清楚。项目后续必须坚持“双线交付”原则：独立软件面向没有 GeoEast 或只需要外部文件处理的用户；GeoEast 集成控件面向已经在 GeoEast 工区、数据库和底图环境中工作的解释人员。两者可以复用同一套核心算法，但界面、配置、数据入口、运行提示、发布方式和验收场景必须分开设计、分开验证。

## 2. 产品交付形态

### 2.1 核心算法程序

核心算法程序是 `faultpolytrace.exe`，定位为可命令行独立运行的计算内核。它负责读取外部网格文件或由 GeoEast Runner 提供的数据，完成断层属性阈值化、线性连通追踪、根系防黏连、闭合多边形生成、面积统计、拓扑诊断和结果输出。

核心算法程序不承担界面交互，不直接依赖桌面 UI。这样做的目的有三个：第一，评审专家可以用命令行直接复现实验；第二，独立软件和 GeoEast 控件可以稳定调用同一个计算内核；第三，算法性能、结果质量和内存表现可以单独验收，避免被界面问题干扰。

### 2.2 独立桌面软件

独立桌面软件是面向普通用户和评审专家的完整应用，入口为发布包根目录的 `FaultPolyTrace.exe`。它应当具备独立打开外部数据、显示原始网格、运行追踪、查看结果多边形、查看叠加图、导出 CSV/GeoJSON/PNG/诊断文件、保存参数模板、读取历史记录和记住上次配置的能力。

独立软件不应强依赖 GeoEast 数据库、GeoEast 许可证或用户本机固定路径。发布包中必须包含示例数据、核心算法程序、Qt 运行库、必要运行依赖、中文帮助文档和默认参数模板。新用户首次打开时，即使没有任何 GeoEast 环境，也应能完成一次完整处理流程。

### 2.3 GeoEast 集成控件

GeoEast 集成控件用于在 GeoEast 平台内调用本算法。其入口可以是 GeoEast 菜单、工具栏按钮或主控插件按钮，打开后显示 GeoEast 风格的参数界面。它应自动识别或辅助填写 GeoEast 根目录、当前用户、当前项目、数据库名、数据目录、Runner 路径等环境信息，并提供刷新 BOMapGrid、选择输入网格、填写输出多边形名、设置颜色线宽和运行参数的能力。

GeoEast 集成控件不应被改造成独立软件的“大杂烩界面”。它的职责是减少 GeoEast 场景下的输入步骤，把结果写回 GeoEast 数据库，并提示用户在 GeoBasemap、GeoMapping 或工区底图中查看输出断层多边形。

### 2.4 GeoEast BO Runner

GeoEast BO Runner 是 `faultpolytrace_geoeast_runner.exe`，负责连接 GeoEast 数据库、读取 BOMapGrid、调用核心算法、写入 BOFaultPolygon 或指定结果对象。它是 GeoEast 集成控件和核心算法之间的桥梁。Runner 必须保持命令行可运行，以便出现数据库、权限、路径或许可证问题时可以单独排查。

## 4. 本次“无法读取 CSV”问题复盘

### 4.1 现象

用户在发布包 `FaultPolyTrace_v0.9.14-full-standalone-ui` 中运行独立软件后，日志显示已经拼出了完整命令行，但随后提示：

```text
无法读取 CSV：C:/Users/26312/Documents/FaultPolyTraceOutputs/FaultPolyTrace_Result.csv
```

这说明界面期望读取算法输出文件，但目标 CSV 并没有生成。

### 4.2 根因

发布包根目录存在独立 GUI：`FaultPolyTrace.exe`；核心算法程序位于 `bin\faultpolytrace.exe`。旧逻辑优先查找应用目录下的 `faultpolytrace.exe`。在 Windows 中，文件名大小写不敏感，因此 `faultpolytrace.exe` 会误命中根目录的 `FaultPolyTrace.exe`。最终独立 GUI 把自身当作核心算法程序启动，导致没有真正运行算法，也没有生成 CSV。

### 4.3 修复原则

修复必须解决根因，而不是简单修改参数或忽略错误。新的查找逻辑应当：

1. 优先查找发布包内的 `bin\faultpolytrace.exe`。
2. 在开发环境中允许回退到 `build\faultpolytrace.exe` 或 `bin\faultpolytrace.exe`。
3. 显式排除当前 GUI 自身路径。
4. 如果仍然定位到自身，应弹出明确错误提示，避免悄悄失败。
5. 如果历史配置中的示例输入文件不存在，应自动回退到当前发布包自带示例。
6. 如果用户给根目录 `FaultPolyTrace.exe` 传入 `--input` 等命令行参数，根目录程序应自动转发到 `bin\faultpolytrace.exe`，避免评审或新用户因为入口混淆而误判软件不可用。

## 5. 双线开发边界

### 5.1 独立软件边界

独立软件只负责外部文件处理和本地结果管理，不直接暴露 GeoEast 数据库连接字段。它应围绕“打开数据、预览数据、设置参数、开始追踪、查看结果、导出结果、保存模板、查看历史”组织界面。独立软件应使用自己的配置目录和历史记录目录，不保存开发机绝对路径作为默认值。

### 5.2 GeoEast 控件边界

GeoEast 控件只负责 GeoEast 环境下的数据选择、数据库配置、Runner 调用和结果写回。它可以显示 GeoEast 环境信息、当前项目、当前用户、BOMapGrid 列表和输出对象名。GeoEast 控件不需要承担外部文件结果管理的完整产品功能，但可以提供 DAT 导入覆盖 BOMapGrid 的辅助选项。

### 5.3 共享部分

两条线可以共享核心算法、参数定义、默认预设、结果诊断口径、颜色线宽含义、文档术语和质量验收脚本。共享部分应尽量以核心 CLI 和脚本为准，界面只是调用和展示，不应复制一套独立算法。

## 6. 当前风险与缺口

1. 独立软件发布包必须重新验证，确认 GUI 调用的是 `bin\faultpolytrace.exe`，而不是根目录 `FaultPolyTrace.exe`。
2. 独立软件需要继续检查所有按钮、菜单、状态栏和历史记录是否都有实际功能，不能存在空控件。
3. GeoEast 集成控件需要保留原有完整参数，不应因为独立软件改版而被误删或耦合。
4. GeoEast 集成控件需要在真实 GeoEast 环境中截图验收：选择输入网格、运行、写入结果、在底图中叠加查看。
5. 算法质量仍需持续使用官方数据、合成数据、弱响应数据、近邻断层数据、交切断层数据做回归。
6. 发布包需要形成稳定命名，例如 `FaultPolyTrace_v0.9.15-runner-path-fix`，并保留旧版本用于对比。

## 8. 验收标准

独立软件验收通过应满足：

1. 双击 `FaultPolyTrace.exe` 可以打开界面。
2. 默认示例数据可以加载。
3. 点击【开始追踪】后能生成 CSV、GeoJSON、PNG 和诊断文件。
4. 界面日志中的算法程序路径指向 `bin\faultpolytrace.exe`。
5. 关闭后再次打开能恢复上次配置。
6. 打开模板、保存模板、恢复默认、导出 PNG、打开输出目录、加载历史均有实际功能。
7. 在命令行中对根目录 `FaultPolyTrace.exe` 传入算法参数时，应自动转发到 `bin\faultpolytrace.exe`，并生成同样的结果文件。

GeoEast 集成验收通过应满足：

1. 从 GeoEast 菜单或按钮可以打开断层多边形追踪控件。
2. 控件能识别或辅助填写 GeoEast 环境。
3. 能刷新并选择 BOMapGrid。
4. 能运行 GeoEast Runner。
5. 能将结果写入 GeoEast 数据库。
6. 能在 GeoEast 底图或平面成图中叠加查看输入属性和输出多边形。

核心算法验收通过应满足：

1. 命令行可独立运行。
2. 官方数据核心耗时稳定低于 1 分钟。
3. 输出多边形闭合，拓扑诊断无严重异常。
4. 面积过滤生效。
5. 近邻断层不被错误粘连。
6. 弱响应和断续响应有合理追踪或残余复核提示。

## 9. 当前结论

项目已经具备赛题要求的主要功能骨架：核心算法可运行，面积过滤、闭合多边形、拓扑诊断、独立运行和 GeoEast 集成链路均已形成。但本次发布包暴露出独立 GUI 与核心 CLI 的路径定位缺陷，说明“产品级发布包验收”还必须继续加强。后续开发必须坚持：核心算法独立、独立软件独立、GeoEast 控件独立，三者通过明确接口协作，而不是混成一个界面。
