# FaultPolyTrace 总体蓝图

本文用于固定项目方向和总体技术路线。目标是完成一个企业级、可交付、可答辩的 GeoEast 解释工具，全面满足赛题 7，而不是松散的离线演示。

## 1. 赛题要求

选定赛题：

**基于平面断层属性的断层多边形自动追踪**

官方要求可归纳为：

1. 输入平面断层属性数据。
2. 设计并实现断层多边形自动追踪算法。
3. 支持追踪结果面积统计。
4. 支持用户设定面积阈值并过滤小多边形。
5. 合理处理断层之间的交切关系。
6. 每个追踪得到的多边形必须是闭合区域。
7. 支持独立运行和 GeoEast 集成。
8. 提供友好的用户交互界面。
9. 支持输入数据选择、输出数据命名和必要参数设置。
10. 可读写外部文件，也可读写 GeoEast 数据库。
11. 提交软件设计文档和代码文档。

评分压力点：

| 分值 | 含义 | 工程目标 |
|---:|---|---|
| 10 | 读取 GeoEast 指定断层属性数据，写入数据库并集成 | `BOMapGrid` 读取 + `BOFaultPolygon` 写入 + 尽量提供 GeoEast 入口 |
| 40 | 正确实现自动追踪功能 | 鲁棒分割、闭合边界追踪、Ridge-Belt 追踪、拓扑诊断 |
| 10 | 面积阈值过滤 | 面积统计、参数配置、过滤状态输出 |
| 10 | 结果展示直观、文档完整 | Qt UI、GeoEast 截图、中文文档、测试报告 |
| 20 | 核心算法 1 分钟内完成 | C++ 高效实现、官方数据性能证据 |
| 10 | 内存合理、无溢出或泄漏 | RAII、压力测试、内存说明 |

## 2. 核心数据模型

赛题是平面属性到多边形的转换，核心模型是二维网格到闭合多边形。

### 2.1 输入：断层属性网格

内部模型：

```text
Grid2D {
  nx, ny
  sx, sy
  dx, dy
  angle
  values[nx * ny]
  invalidValue
}
```

GeoEast 映射：

- 业务对象：`BOMapGrid`
- 父对象：`BOProject`
- 头信息：`BAMapGridHead`
- 数据值：二维网格属性值
- 关键字段：`sx/sy/dx/dy/nx/ny/angle`
- 无效值：`FLT_MAX`
- 相关接口：`readDataHead`、`readData`、`saveDataHead`、`saveData`

### 2.2 输出：断层多边形

内部模型：

```text
FaultPolygon {
  id
  outerRing
  innerRings
  area
  perimeter
  meanAttribute
  maxAttribute
  confidence
  status
}
```

GeoEast 映射：

- 业务对象：`BOFaultPolygon`
- 父对象：`BOProject`
- 点结构：`BAFaultPolygonPoint`
- 段结构：`BAFaultPolygonSegment`
- 数据结构：`BAFaultPolygonData`
- 头结构：`BAFaultPolygonHead`
- 关键写入接口：`saveData(head, data)`

## 4. 核心算法路线

最终算法必须确定、可解释、高效、鲁棒。这个赛题更适合工程化几何算法，而不是难以解释和部署的黑盒大模型。

赛题图示给出的重要信息是：目标不是普通填充斑块，而是围绕线状断层属性脊线形成细长闭合断层多边形。因此算法保留两条互补路线：

1. **区域边界路线**：对高值断层属性区域分割并追踪闭合边界。适合宽断层带或块状异常。
2. **脊线转断层带路线**：从属性图提取断层脊线或骨架，清理和补连后缓冲成狭长闭合多边形。更符合官方图示和地质解释习惯。

考虑地质勘探场景，算法不能只适配官方示例形状。实际平面断层属性可能表现为：

- 连续长脊线。
- 断续短段。
- 分支或马尾状结构。
- 雁列式断层。
- 交叉断层系统。
- 弯曲、弧形或 S 形断层。
- 平行或编织状断裂带。
- 厚的高属性带。
- 噪声孤立斑块。
- 低信噪比区域的弱响应。

所以最终产品必须支持模式切换、参数配置和拓扑诊断，不能写成只适配一张图的固定流程。

### 阶段 A：预处理

目标：将带噪声的属性值转化为稳定候选结构。

模块：

1. 无效值掩码。
2. 鲁棒归一化。
3. 可选中值滤波。
4. 可选高斯平滑。
5. 可选线状结构增强。

要求：每个预处理选项都要参数化，并记录到日志和诊断文件中。

### 阶段 B：分割

目标：提取候选断层区域。

当前基线：

- 固定阈值。
- 分位数阈值。
- 形态学开闭运算。
- 连通域分析。

生产目标：

- 自适应阈值。
- 双阈值滞后分割。
- 最小像元数过滤。
- 置信度评价。

### 阶段 C：边界和环追踪

当前确定方案：

- 使用活动网格边界边提取。
- 拼接有向边形成闭合环。
- 保留凹形边界。
- 输出前检查闭合性。

后续目标：

- 支持多个环。
- 识别外环和孔洞。
- 可选 marching squares 插值以改善平滑性。
- 在保证闭合的前提下进行 Douglas-Peucker 简化。

这是项目的视觉和功能核心。

### 阶段 C2：Ridge-Belt 多边形化

目标：把细长断层属性趋势转化为闭合断层带。

流程：

1. 增强线状响应。
2. 提取二值候选掩码。
3. 骨架化为中心线。
4. 剪除短毛刺和孤立噪声。
5. 按方向和距离补连小断裂。
6. 根据属性厚度或用户参数估计宽度。
7. 将中心线缓冲为闭合断层带。
8. 平滑并简化边界。

关键参数：

- 脊线阈值。
- 最小分支长度。
- 最大补连距离。
- 最大补连角度。
- 默认断层带半宽。
- 宽度估计模式。
- 简化容差。

### 阶段 D：统计和过滤

每个多边形输出：

- 面积。
- 周长。
- 点数。
- 来源像元数。
- 平均断层属性。
- 最大断层属性。
- 置信度。
- 保留或过滤状态。

面积阈值必须在 UI 中可见、可修改，并体现在输出报告中。

### 阶段 E：交切关系处理

官方明确要求合理处理断层交切关系，因此它必须是独立模块。

计划算法：

1. 建立线段索引。
2. 检测线段相交。
3. 按置信度、面积、长度和平均属性排序断层主次。
4. 提供修复模式：
   - 仅检测报告。
   - 近点吸附。
   - 交叉处分割。
   - 主断层附近裁剪低优先级断层。
5. 输出修正统计。

比赛交付至少要有可靠检测、报告和保守修复选项。

## 5. GeoEast 集成框架

### 5.1 环境要求

官方环境包：

```text
D:\BaiduNetdiskDownload\BGPCup2025\GeoEast-RC
```

已安装和使用的关键环境：

- Visual Studio 2019。
- GeoEast 自带 Qt 5.15.2 / Qt VS Add-in；编译版本与运行库版本必须一致。
- GeoEast-RC Develop。
- GeoEast 数据包。
- GeoEast 许可证。

注意：用户电脑常开 VPN。遇到下载、证书、代理或命令行网络问题时，应优先考虑 VPN 路由和代理继承问题。

### 5.2 GeoEast 数据流

```text
GeoEast 项目树
  -> 选择 BOProject
  -> 选择 BOMapGrid 断层属性
  -> 读取 BAMapGridHead + 网格值
  -> 转换为 Grid2D
  -> 运行 FaultPolyTrace 核心
  -> 转换为 BAFaultPolygonData
  -> 创建或获取 BOFaultPolygon 输出对象
  -> saveData(head, data)
  -> 在 Combined Fault Polygons / Basemap 中验证
```

### 5.3 插件和 UI 路线

推荐路线：

1. 优先保证 Qt 启动器稳定。
2. 通过 GeoEast runner 完成数据库读写。
3. 增加 GeoEast 主控或属性模块入口。
4. Ribbon action 尽量复用同一套参数对话框或启动器。

官方 `Training/Code/05_attriDemos/myPluginsSo` 示例说明了插件 DLL 加 `manifest.xml` 注册入口的模式。

## 7. 风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| GeoEast SDK 环境复杂 | 影响主控插件 | 保证 runner 和 Qt 启动器先稳定，主控入口作为增强项 |
| 手工 ASCII 导入格式错误 | 结果异常 | 使用程序导入生成 `test7_fault_attribute_bo`，并验证网格尺寸 |
| 边界追踪产生无效拓扑 | 输出错误 | 增加闭合性、自相交和多边形相交诊断 |
| 交切修复过度 | 破坏地质解释 | 默认检测报告，修复作为可选参数 |
| 重依赖与 GeoEast 冲突 | 部署风险 | 保持核心 C++ 轻依赖 |
| VPN 引起下载或代理问题 | 环境搭建延迟 | 先检查代理、证书和命令行环境变量 |

## 8. 立即执行原则

1. 保持 C++17 核心和 SDK 解耦架构。
2. 把 `BOMapGrid` 输入和 `BOFaultPolygon` 输出作为官方集成目标。
3. 默认使用 `ridge-belt`，保留 `region` 作为备用和质检模式。
4. 所有参数、耗时和拓扑指标都要可记录。
5. 下一步优先补齐最终报告所需的截图、性能证据和交切处理说明。
