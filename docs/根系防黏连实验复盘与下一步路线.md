# 根系防黏连实验复盘与下一步路线

文档版本：V2.0
日期：2026-05-22
适用对象：FaultPolyTrace 赛题 7 正式交付、算法答辩和后续冲顶开发

## 1. 背景

断层多边形追踪不能只按距离近进行合并。合理的产品级算法应判断相邻线状响应是否能沿同一条连续响应追溯到同一套断层主干；如果两条线之间隔着背景零值，或没有连续弱响应支撑，则不应合成一个大多边形。

这一思路对应工程算法中的“骨架拓扑追踪、主干归属、防误合并约束”。它是正确方向，但不能粗暴地把每条局部分支单独输出为多边形，也不能把所有根系之间的边界都切开。旧版全局像素级切割曾经出现过切问题，会把连续断层打碎成小片段。

## 2. 本轮解决的问题

旧 `rootAntiMerge` 的主要问题不是思想错误，而是缺少切后验收：

- 候选桥接点很多，其中一部分是真正的低属性背景桥。
- 另一部分位于连续断层内部的根系边界，不应该切开。
- 如果不判断切开后的主体规模，会把长连续断层切成“大主体加小碎片”。

因此本轮新增“候选切分 + 切后验收 + 自动回退”机制：

1. 先生成候选背景桥切分点。
2. 对每个原始连通断层带单独模拟切开。
3. 检查切开后是否形成至少两个足够大的主体。
4. 如果只得到一个大主体加少量小碎片，则回退该连通体的切分。
5. 只接受通过验收的切分，再重新追踪闭合边界、面积过滤和拓扑诊断。

新增参数：

```text
--root-anti-merge-min-part-cells
--root-anti-merge-min-part-ratio
```

默认 `min-part-cells=0` 表示按网格和带宽自动估计，`min-part-ratio=0.12` 表示切后主体应占原连通体的最低比例。

## 4. 产品策略

正式默认策略仍为 `贴合融合推荐`：

- 脊线骨架提取。
- 弱响应延拓。
- 端点短距连接。
- 属性约束断层带缓冲。
- 多外环闭合追踪。
- 面积阈值与自适应小目标保留。
- 拓扑检查与诊断输出。
- `rootAntiMerge=false`。
- `residualTrace=false`。

该策略在官方数据上保持 204 个量级、强响应覆盖率约 99.52%、弱响应覆盖率约 96.63%、拓扑诊断为 0，适合作为默认主交付线。

`防黏连增强` 作为受控高级模式：

```text
rootAntiMerge = true
rootAntiMergeSupportRatio = 0.25
rootAntiMergeMinPartCells = 0
rootAntiMergeMinPartRatio = 0.12
```

适用场景：

- 叠合图中明确看到近邻不同脉络被连成一个大圈。
- 默认结果覆盖率已经足够高，但局部误合并影响解释。
- 需要生成一份对照结果供解释人员复核。

不适用场景：

- 想通过全局切碎来追求更多多边形数量。
- 输入数据噪声很强且断层主干不清楚。
- 用户尚未检查默认结果和原始属性叠合图。

## 5. 可回溯诊断工具

新增脚本：

```text
scripts\防黏连差异诊断.py
```

用途：

- 对比稳定基线和防黏连候选。
- 统计每个基线多边形被拆成哪些候选多边形。
- 判断是否损失强响应或弱响应像元。
- 生成局部白底复核图。
- 输出 CSV、JSON 和 Markdown 报告。

推荐用法：

```powershell
python .\scripts\防黏连差异诊断.py `
  --dat "D:\BaiduNetdiskDownload\BGPCup2025\test.dat" `
  --baseline-csv "<稳定基线.csv>" `
  --candidate-csv "<防黏连候选.csv>" `
  --out-dir "<带时间戳的诊断目录>" `
  --max-figures 30
```

判断标准：

- 如果切掉强响应或弱响应像元，候选策略不能进入正式结果。
- 如果新增大量无基线来源的小多边形，候选策略过激。
- 如果只切掉低值背景桥，且覆盖率、拓扑和数量稳定，则可作为高级增强结果。

## 6. 下一步路线

优先级从高到低：

1. 保持 `贴合融合推荐` 作为默认主线，并继续跑性能回归和一键验收。
2. 在 Qt 启动器中提供 `防黏连增强` 预设，但不默认启用。
3. 将差异诊断脚本纳入冲顶质量流程，所有候选增强都必须可复查。
4. 对强响应漏检和高风险误合并候选生成局部图件，逐项判断是真问题还是诊断提示。
5. 继续开发参数自动推荐，让系统根据属性直方图、连通域尺度和网格间距给出推荐参数。
6. 扩展真实数据回归集，避免只围绕官方 `test.dat` 优化。

## 7. 当前结论

根系防黏连思想是正确的；旧问题出在无验收地全局切开。当前“切后验收 + 自动回退”版本已经把它推进为可控的产品能力：既能减少部分近邻误合并，又不牺牲强弱响应覆盖率，也不会把主线结果碎片化。

因此，最终交付策略应采用“双层结果”：

- 默认结果：`贴合融合推荐`，用于正式提交和常规解释。
- 对照结果：`防黏连增强`，用于近邻误合并明显时的复核和展示。
