# 根系防黏连实验复盘与下一步路线

## 1. 背景

断层多边形追踪不能只按距离近进行合并。合理的产品级算法应判断相邻线状响应是否能沿同一条连续响应追溯到同一套断层主干；如果两条线之间隔着背景零值，或没有连续弱响应支撑，则不应合成一个大多边形。

这一思路对应工程算法中的“骨架拓扑追踪、主干归属、防误合并约束”。它是正确方向，但不能直接把每条局部分支单独输出为多边形，也不能把所有根系之间的边界都切开。

## 2. 已完成实验

本轮以 `review_20260505_013300_multiring_fix` 和恢复后的 `balanced_recovery_20260506_043013` 为质量基准，进行了“根系防黏连 + 全局聚合”的实验。

基准主交付线：

- 输出目录：`examples/outputs/balanced_recovery_20260506_043013`
- 推荐结果：`E_恢复基准_belt3_属性约束.csv`
- 保留多边形：204 个
- 核心追踪耗时：约 0.5 秒
- 总耗时：约 1.6 秒
- 拓扑质量：无开环、无自相交、无多边形相交诊断

新增实验能力：

- `--root-anti-merge`
- `--root-anti-merge-radius`
- `--root-anti-merge-support-ratio`
- `--root-anti-merge-max-bridge-value`

该能力会先根据骨架方向连续性划分根系，再检测不同根系之间的争议桥接点。实验结果说明：如果在像素级全局切除这些争议点，虽然能减少部分黏连风险，但会把很多本来连续的断层带切碎。

## 3. 实验结论

根系思想是正确的，但当前不能作为默认像素切割策略。

原因如下：

- 官方数据中的断层响应存在大量交切、分叉和近邻并行结构，根系边界分布很广。
- 大断层带内部也会出现不同根系的边界，这些边界不一定代表错误黏连。
- 若把根系争议点全部切开，多边形数量会从 204 个上升到数百个，覆盖连续性下降。
- 这会偏离赛题对“边界平滑自然、结果直观、合理处理交切关系”的要求。

因此，`rootAntiMerge` 已保留为高级实验开关，不作为默认推荐方案。

## 4. 正确的下一步

下一步不应继续扩大像素级切割，而应做“局部候选拆分”：

1. 先使用当前 204 个量级的全局聚合主线，保证覆盖率、连贯性和视觉质量。
2. 对每个大多边形做局部质控，识别是否存在疑似误合并桥接。
3. 只对满足条件的局部桥接区域进行拆分，普通连续断层带保持不动。
4. 拆分后必须重新执行拓扑检查、面积过滤和覆盖率评估。

局部误合并候选应同时满足：

- 桥接位置原始属性值接近背景零值；
- 桥接宽度较窄，且两侧存在明显不同方向或不同主干的线状响应；
- 切开后不会导致主要断层带断裂成大量小碎片；
- 切开前后强响应覆盖率基本不下降；
- 输出多边形数量仍保持在合理量级。

## 5. 当前产品默认策略

当前推荐默认策略仍为：

- 脊线骨架提取；
- 弱响应延拓；
- 端点短距连接；
- 属性约束断层带缓冲；
- 多外环闭合追踪；
- 面积阈值与自适应小目标保留；
- 拓扑检查与诊断输出。

这条路线在官方数据上保持了较好的覆盖率、连贯性、拓扑稳定性和性能，适合作为主交付版本。

`rootAntiMerge` 暂作为高级质控工具保留，用于后续定位疑似黏连区域，不建议在正式交付默认开启。
