# 可靠性验证说明

## 1. 验证范围

本目录保存正式提交构建的内存安全与连续运行摘要。验证对象为同一Git提交生成的FaultPolyTrace命令行核心，输入采用赛题官方平面断层属性数据，参数与正式推荐预设一致。

## 2. AddressSanitizer

`AddressSanitizer验证摘要.json`记录内存安全检查结果。验证构建启用AddressSanitizer，对官方数据完整处理路径和损坏输入拒绝路径进行运行检查，覆盖路径未报告越界访问、释放后访问等内存安全错误。最终结果数量、拓扑和哈希以本目录的一键复现脚本与正式官方结果为准。

复现时在源码目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run_msvc_asan_validation.ps1 -OfficialDat <官方test.dat>
```

AddressSanitizer用于发现已执行路径中的内存访问错误，不能替代所有输入组合的形式化证明。

## 3. 连续运行与趋势检查

`连续运行稳定性摘要.json`和`连续运行明细.csv`记录多次独立进程运行结果。每轮均检查退出码、结果哈希、完整耗时、核心追踪耗时、峰值工作集、句柄数量和保留多边形数量；结束后比较首尾窗口趋势，并注入不存在的输入路径检查失败处理。

同目录还提供Application Verifier日志、16类异常输入与容错验证、GeoEast事务式写入和规范化几何回读、完整几何GEOS交叉验证及离散分位平台内扰动核验。这些文件分别覆盖Windows运行时、输入边界、数据库往返、几何有效性和参数稳定性；赛题交付审计结论见上一级`自动化验证结果.md`。

复现时执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\连续运行稳定性检查.ps1 `
  -OfficialDat <官方test.dat> -Runs 100 -SkipBuild
```

通过标准为：全部循环结果哈希完全一致并等于正式基线，拓扑和对象数量不漂移，耗时不超过门限，工作集与句柄无超限趋势，异常输入不能生成成功结果；分位数在同一离散属性阈值平台内扰动时，输出哈希也必须保持一致。
